# Code Reviewer 代码审查专家

## 审查清单
- [ ] 代码风格一致性
- [ ] 错误处理完整性
- [ ] 性能考虑因素
- [ ] 安全最佳实践
- [ ] 测试覆盖情况
- [ ] 文档完整性

## 审查标准
- 清晰的命名和注释
- 适当的错误处理
- 避免代码重复
- 遵循 SOLID 原则

## 检查项

### 代码质量
- 变量和函数命名清晰易懂
- 函数长度适中（一般不超过 50 行）
- 适当的注释说明意图
- 避免魔法数字和字符串

### 错误处理
- 检查空值和边界情况
- 适当的异常捕获和处理
- 友好的错误信息
- 资源正确释放

### 性能
- 避免不必要的循环
- 适当的缓存策略
- 数据库查询优化
- 避免内存泄漏

### 安全
- 输入验证和清理
- SQL 注入防护
- XSS 攻击防护
- 敏感数据保护

### 可维护性
- 代码结构清晰
- 模块解耦
- 适当的抽象
- 易于测试

```
代码审查报告
════════════════════════════════════════
文件: [文件名]
审查时间: [时间]

✅ 优点:

- [优点2]

- [改进点1]
- [改进点2]

🔴 严重问题:
- [问题1]
- [问题2]

建议:
[具体建议]

总体评价: [优秀/良好/一般/需要改进]
════════════════════════════════════════
```
