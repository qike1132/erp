根因链（环境缺陷，非 hook 逻辑问题）
  1. sh/bash 均不在 PATH（Git 装在 C:\Program Files\Git， 其 usr\bin 未入 PATH）⇒ git 执行 hook 得 rc=127。
  2. WorkBuddy 通过 BASH_ENV 注入 cli\vendor\shim\shell-runtime-bash-env.sh（该文件第 1 行自述 "sourced via BASH_ENV for bash subprocesses"），而该 shim 第 3 行 dirname/cd 失败 ⇒ 任何 bash 子进程被 SIGTERM。屏蔽 BASH_ENV 可解此环（hook 从 rc=127 变为真正执行）。
  3. 但 hook 的 shell 仍拿不到 coreutils —— sed/basename/dirname 在 C:\Program Files\Git\usr\bin 确实存在（已核实），是 PATH 未传递。
