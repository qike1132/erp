- **修**：`pip install pydantic-settings==2.14.2`；以 `pip freeze` 重建 `base.txt`，清理幻觉依赖；CI 加 `pip-audit` 门禁。
- **来源**：架构师 S1 ＋ 工程师 A-M4（**独立得出同一结论**）

### S2 · NSSM `AppEnvironmentExtra` 单元素 → 5 个环境变量全失效
- **证据（主理人实测）**：`HKLM\SYSTEM\CurrentControlSet\Services\erp-prod\Parameters\AppEnvironmentExtra`，`type=REG_MULTI_SZ`，**`decoded_items=1`**：
  `'APP_ENV=production FASTAPI_DEBUG=false PYTHONPATH=D:\erp_system PYTHONUTF8=1 PYTHONUNBUFFERED=1 UVICORN_WORKERS=8'`
- **机制**：NSSM 按 `REG_MULTI_SZ` 的**每个元素**设一个 `NAME=VALUE` 环境变量。整串为单元素 → 只产生变量 `APP_ENV`，其值为 `"production FASTAPI_DEBUG=false PYTHONPATH=..."` 整串。`config.py:42` 的"取首 token"容错把 `APP_ENV` 救回 `production`（**侥幸**，非设计），其余 5 个变量**从未生效**。
- **旁证链**：`PYTHONUNBUFFERED` 未生效 → 解释了 QA 的 S-2（`prod_runner` stdout 块缓冲）与 `erp-prod.log` 行序错乱；`PYTHONUTF8` 未生效 → 解释了 `erp-arq.log` 中文乱码。
- **修**：重装/改写服务环境为**每个变量一个 `REG_MULTI_SZ` 元素**（`APP_ENV=production`、`FASTAPI_DEBUG=false`、`PYTHONPATH=D:\erp_system`、`PYTHONUTF8=1`、`PYTHONUNBUFFERED=1`、`UVICORN_WORKERS=8`），并去掉 `config.py:42` 的取首 token 容错（让配置错误显式失败）。
- **验证**：重启后 `Get-CimInstance Win32_Process` 读不到 cmdline 时，改看子进程环境（或直接验证日志无乱码、行序正常）。
- ⚠️ **这是已知历史坑的复现**，修复脚本务必带 BOM、含 `-DryRun/-Verify`，且**不可重复 exe 路径**。

### S3 · `switch_env.py production` 会覆盖真实 `.env` 并导致全站宕机
- **证据**：`scripts/switch_env.py:44-45` 用 `env_backup` 中过时占位的 `.env.production` 覆盖真实 `.env`；该占位文件缺 `ALLOWED_HOSTS` / `APP_ENV`；叠加 NSSM 强设 `APP_ENV=production` → `config.py:150` 抛 `RuntimeError` → **应用启动即崩**。
- **修**：删除该脚本的"生产切换"分支，或改为**只读提示 + 显式 `--force` + 先备份真实 `.env`**。

### S4 · `restart_prod.ps1` 绕过 NSSM 另起 uvicorn（抢端口）
- **证据**：`restart_prod.ps1:103-119` 直接在 `:5002` 拉起新 uvicorn，与 `prod_runner` 的自动重启**抢端口**；`:39-40` 使用 PS7 专有 `??`（PS 5.1 下必然解析失败）。
- **修**：删除该脚本或改为 `nssm restart erp-prod`；`??` 改 `if ($null -eq $x) { ... }`。

### S-1 · 生产无错误聚合，6 天 65 个 5xx 无告警
- **证据**：全仓仅 `main.ts:56` 动态 `import('@sentry/vue')` 调 `captureException`（上限 10 次），**无 `Sentry.init` / 无 DSN / 无 captureMessage**。线上 6 天 nginx 日志 500×34、502×23、503×8 **全部无聚合无告警**；唯一定位手段是 `audit_middleware.py:96` 的 request_id 人工串联。
- **修**：接入 Sentry（前后端）+ 5xx 率告警；或至少加一条"5xx 计数超阈值即告警"的 ARQ 定时任务。
