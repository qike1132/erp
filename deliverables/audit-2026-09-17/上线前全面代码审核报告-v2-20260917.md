### H2 · `_check_last_backup()` 键名错配（HEAD 存量，从未被修）—— 「最近备份时间 1970-01-01」假告警

**位置**：`fastapi_app/api/v1/endpoints/backup/validation.py:155-156`
```python
latest_backup = max(backup_files, key=lambda x: x.get('mtime', 0))
latest_time = datetime.fromtimestamp(latest_backup.get('mtime', 0))
```
**机理**：真实生产者 `fastapi_app/services/backup/records.py:166` 返回 `{'filename': f.name, 'size': f.stat().st_size}`——**dict 里根本没有 `mtime` 键** → `.get('mtime', 0)` 恒为 0 → `datetime.fromtimestamp(0)` = **1970-01-01 08:00** → 恒报「最近备份时间超过24小时（49 万小时前）」。生产实测复现。
**对比**：`services/backup/verify/health_check_service.py:210-211` 有 Path-based 正确实现，但端点走的是 validation.py 内联版——**正确实现是死代码，缺陷实现在服役**。
**影响**：备份健康页核心指标恒假，真告警（如备份真停了）会被假告警淹没而漏判。
**修复建议**：
```python
latest_path = max(
    (backup_service.BACKUP_DIR / f['filename'] for f in backup_files),
    key=lambda p: p.stat().st_mtime,
)
latest_time = datetime.fromtimestamp(latest_path.stat().st_mtime)
```
**必须同时**加一条不 mock `list_backup_files()` 的契约测试（真实临时目录端到端），呼应本仓已两次踩中的「替身字段形状不镜像真实生产者」陷阱。
