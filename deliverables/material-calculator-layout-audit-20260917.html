物料计算器页面布局走查

路由 /material-calculator · 前端 frontend-vite/src/views/material-calculator/

取证时间 2026-09-17 运行环境 http://192.168.0.95:3000（生产） 视口 1920×1080 / 1600×900 样本 3 个产品 × 100 件 → 3 个作用域 方式 只读，未改动任何线上数据

一句话结论：页面之所以"挤"，不是元素太多，而是三件事叠加 ——

① 竖向预算被次要的「跨角色对比矩阵」常驻切走 37%；② 每个元素（搜索框 50px、过滤按钮 43px、产品行 72px、表格行 45px）都被放大了一档，密度靠滚动补偿；③ 三列之间的分组信号全部失效——列标题样式是死 CSS、列间距为 0、三列内容基线不齐。

三者相乘的可见后果：产品列表 26 条里同屏只看得到 5–6 条，结果区内容 1919px 挤进 586px，纵向溢出 3.27 倍。

1 · 取证方法

全部结论都走双证据，不接受单一来源：

证据来源能证明什么
声明值源码逐文件读取（含 .vue 的 template 与 scoped style）设计意图：作者写了什么
渲染像素Playwright + 系统 Edge 打开生产页，getBoundingClientRect() / getComputedStyle() 实测浏览器实际用了什么（可揭穿"写了但没生效"）

本文所有 px 数字均为浏览器实测值，非估算；涉及"没生效"的判断，均给出元素上的 data-v-* 属性作为佐证。

3 · 严重问题详述

S1 · 对比矩阵常驻，切走 37% 竖向预算 severe

现象：只要计算出 ≥2 个作用域，页面底部就固定出现「跨角色对比矩阵」区块，三列工作区被压扁到 610px。

成因：.page-card-body 是 flex:1 的三列网格，而矩阵区块写成 flex-shrink: 0——即永不收缩、优先占位。

// MaterialCalculatorView.vue:225-229
.mc-matrix-section {
  flex-shrink: 0;   // 永远优先占位，把压力全推给三列
  overflow: auto;
  border-top: 1px solid var(--color-border-light, #f1f5f9);
}

实测：卡片正文 1004px = padding 40px + 三列 610px + 矩阵 354px。矩阵独占 37%，而三列是完成「选品→录数→看结果」主任务的唯一区域。

改法：矩阵降级为按需展开——默认渲染一条 44px 的摘要条（跨角色对比 · 3 个作用域 · 8 行物料　[展开]），点击后以抽屉或浮层展示完整矩阵。主工作区拿回 +354px。

S2 · 三列标题样式整体失效（死 CSS） severe

现象：三个区块标题「产品选择 / 订单数量录入 / 物料用量计算结果」渲染成与正文同级的灰色小字，没有内边距、没有分隔线，且左边缘比下方内容外突 16px。

成因：.mc-col-title 的样式写在父组件 MaterialCalculatorView.vue 的 scoped 块里，但元素实际位于子组件内部。Vue 只会把父级 scope 属性加到子组件的根元素上，因此这条规则从未匹配到任何元素。

证据（渲染像素）：
列根元素 class="mc-col" → 属性 ["data-v-19904fd3", "data-v-b3a5c610", "class"]（含父级 b3a5c610，所以 .mc-col + .mc-col 的竖线生效了）
列标题 class="mc-col-title" → 属性 ["data-v-19904fd3", "class"]（无父级 scope，规则永不匹配）
实测计算值：padding: 0px · font-weight: 400 · font-size: 15px（继承）· border-bottom-width: 0px · height: 24px
声明值本应是：padding: 12px 20px · font-weight: 700 · font-size: 14px · border-bottom: 1px

影响：三列之间失去了唯一的分组信号。页面退化成一整片上下贯通的白色区域，用户扫读时找不到"这一栏在干什么"。这是"拥挤感"的主要来源之一，且修复成本极低。

改法：把 .mc-col-title 样式下沉到各子组件（或提到全局 app.css，与 .page-card-* 同级），并统一左内边距为 16px（与列内其它内容对齐）。

/* 三个子组件内各自声明，或提到 app.css 全局 */
.mc-col-title {
  display: flex; align-items: center; gap: 8px;
  height: 44px; padding: 0 16px;            /* 与内容同左边界 */
  font-size: 13px; font-weight: 600; color: var(--color-text);
  border-bottom: 1px solid var(--color-border-light);
  flex-shrink: 0;
}

S3 · 三列之间间距为 0 severe

现象：三列各 535px 宽，彼此紧贴，只靠一条 1px 的浅灰竖线分隔；而卡片左右两侧却留了 24px 内边距。

证据：display: grid · grid-template-columns: 535.328px 535.328px 535.328px · gap: normal（=0px）· padding: 20px 24px
列实测坐标：x=279 → x=814 → x=1350，前两列 279+535=814，严格零间隙 
// MaterialCalculatorView.vue:188-194
.page-card-body {
  display: grid;
  grid-template-columns: 1fr 1fr 1fr;  // 缺 gap
  flex: 1; min-height: 0; overflow: hidden;
}

改法：补 gap: 20px 16px，并把 .mc-col 加 border-radius: 10px —— 让三列成为三个可辨识的"面板"，而不是一整块被划了两刀的白色。

S4 · 控件与行高全面放大，单屏容量减半 severe

现象：每一个可交互元素都比同类大厂规范大一档，且放大是"系统性"的、没有主次。

S5 · 结果区纵向堆叠所有作用域 severe

现象：3 个产品 = 3 张作用域卡纵向堆叠，每张卡又强制渲染 3 个分类块。结果区内容高达 1919px，用户要滚 3 屏才能看完一次计算。

证据：三张卡实测高度 688px / 458px / 688px，共 1834px + 卡片间距 36px + padding 32px ≈ 1919px
分类头文本实测：填充类(1项) / 面料类(7项) / 辅料类(0项)、填充类(0项) / 面料类(4项) / 辅料类(0项)、填充类(1项) / 面料类(7项) / 辅料类(0项)

改法：改用作用域切换器（Segmented / Tabs，横向一行）替代纵向堆叠——同一时刻只渲染一个作用域的明细，卡片外层高度从 1834px 降到约 400px。配合矩阵折叠，整页可做到"零纵向滚动"。

4 · 其余问题与改法

M1 · 图标尺寸规则失效（i vs svg）

四处图标尺寸规则使用了 i 选择器，而 FontAwesomeIcon 渲染出来的是 <svg>，规则全部落空：

位置声明实测
.mc-col-title i14px15px（继承）
.mc-action-btn i11px12px（继承）
.mc-empty-state i28px≈15px（继承）→ 空态图标孱弱
.mc-loading-state i20px继承

改法：改为作用于 svg，或直接给 <FontAwesomeIcon class="…"> 指定尺寸。

M2 · 表头字号小于表体（层级倒挂）

结果表 thead th 实测 12px / 600，tbody td 实测 14px / 400。数据比列名更"响亮"，扫读时找不到列锚点。建议表头 12px/600 + 浅灰底，表体 13px/400，让"表头 > 表体"的视觉重量关系成立。

M3 · 无页面标题，工具栏左对齐悬空

.page-card-header 用 justify-content: space-between，但只有一个子元素 .mc-header-actions——于是"已选 3 个 / 批量录入 / 清空 / 8 种物料"四个元素左对齐挤在一起，页面没有任何标题锚点。建议改为左「物料用量计算」标题（含一句用途说明）+ 右操作区，或直接复用 .page-card-toolbar 的 .page-toolbar-left / .page-toolbar-right 结构。

M4 · 尺寸令牌失控

圆角取值7 档7 / 8 / 9 / 10 / 11 / 12 / 20 px
边框宽度2px 主导39 个元素用 2px，仅 3 个用 1px
字重取值4 档400 / 600 / 650 / 700（650 非标准）
字号取值7 档11 / 12 / 13 / 14 / 15 / 18 / 32 px

根因在样式系统本身：app.css 的令牌块里只有颜色、圆角、阴影、层级、渐变，没有间距令牌，也没有字号令牌。各组件只能自由发挥，于是同一页出现 7 档圆角、7 档字号。

/* app.css:124-132 —— 现状：只有圆角，且最小档已达 10px */
--radius-sm: 10px;  --radius-md: 14px;  --radius-lg: 24px;
--radius-card: 24px; --radius-button: 14px; --radius-input: 12px;
/* 缺失：--space-*（间距）与 --text-*（字号） */

/* 建议补齐 */
--space-1: 4px; --space-2: 8px; --space-3: 12px; --space-4: 16px; --space-5: 20px; --space-6: 24px;
--text-caption: 11px; --text-xs: 12px; --text-sm: 13px; --text-base: 14px;
--text-lg: 16px; --text-title: 18px; --text-metric: 22px;
--radius-xs: 4px; --radius-sm: 6px; --radius-md: 8px; --radius-lg: 12px;
--border-w: 1px;   /* 全局默认 1px，取代泛用的 2px */

M5 · (0 项) 分类仍渲染完整头部

9 个分类头中有 4 个显示 (0 项)，每个占 46px，合计白占 184px；且折叠箭头照常渲染，点击没有任何反馈（假可交互，误导用户）。建议计数为 0 时不渲染该分类块，或降级为一行 24px 的灰色注记且不可点。

M6 · 作用域卡头部语义重复

头部为 [默认] 默认BOM 招财猫盲盒毛绒挂件(混4款)　数量 100——徽章「默认」与名称「默认BOM」表达同一件事。建议徽章只承担"默认/角色"的分类色块，名称位直接显示产品名，把作用域名并到数量一侧：[默认] 招财猫盲盒毛绒挂件(混4款)　100 件。

M7 · 矩阵列头无法区分产品

3 个作用域（三个不同产品的默认 BOM）在三列表头全部显示「默认BOM」，用户无法判断哪一列属于哪个产品。建议列头改为两行：作用域名 + 产品名，或至少在 title 中补全。

L1–L4 · 细节

  • L1 渐变：实测 11 处渐变表面（1 个 count-badge + 1 个 mc-summary-panel + 9 个 mc-category-header，均为 linear-gradient(135deg, …)）。建议全部改纯色浅底 + 1px 边框，与扁平克制的整体方向对齐。
  • L2 徽章高度：「已选 N 个」高 29px / 圆角 20px，「N 种物料」高 37px / 圆角 16px。同一行内两个徽章高度差 8px，建议统一为 24px 高 / 圆角 12px。
  • L3 基线不齐：三列第一行内容实测 y = 248 / 127 / 131。第一列因前置控件被推低 121px。建议三列共用同一套列头（44px），让首行内容落在同一水平线上。
  • L4 hover 位移：.mc-product-item:hover { transform: translateX(4px) }——128 条列表逐行扫读时，鼠标划过的行会横向抖动。建议改为纯 border-color / background 变化。
