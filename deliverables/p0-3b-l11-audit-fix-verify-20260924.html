一、判据设计（按约定先给设计，再改）

病根

L11 的判据假设仓库根存在 alembic.ini / Dockerfile / deploy-*.ps1。 本仓库实际：迁移在 migrations/（script_location = %(here)s）；部署靠 NSSM 服务（erp-prod / erp-arq / …）+ runbook；没有也不应有容器编排文件。 于是同一个错误假设产生了两个方向相反的缺陷：

子检查缺陷类型机理
_check_migrations 假阴性（更危险） 只找 PROJECT_ROOT/alembic.ini / alembic/ / fastapi_app/alembic/， 三者皆无 ⇒ 直接 return "Alembic 未配置,跳过迁移检查" ⇒ 整个迁移检查永不执行，真实 schema 漂移被无声放过
_check_container_config 假阳性 只认 Dockerfile / docker-compose.* / deploy-*.ps1 （后两者已于 commit 15e13a79 删除）⇒ 稳定输出 L11-CONTAINER-001

新判据（原则：判据描述「本项目应有的状态」，而非「通用模板」）

  • 迁移：路径候选本仓库优先（migrations/alembic.ini → alembic.ini）； versions 目录按 ini 的 script_location 解析（本项目为 %(here)s，即 ini 同目录）， 再回落 ini 同级 / alembic 目录。找不到配置时发 LOW 提示——让「跳过」可见，而不是假装通过。
  • 部署就绪：容器化 或 Windows 原生 NSSM，二者有其一即视为已具备部署路径。 容器路径走原「非 root 用户」校验；原生证据 = runbook 或任一 *.ps1/scripts/*.ps1 含 nssm 关键字。只有两者都缺失才报问题。
  • 幽灵文件名清理：_DEPLOY_SCRIPTS 里的 deploy-windows.ps1 / deploy_nginx.ps1 / build_and_release.py 换成真实存在的运维脚本，并在注释里写明「不得再把它们当作判据」。

四、复核中发现的三个问题

已恢复 quality_gate.py 曾因我 P0-② 的 RUF100 步骤 FAIL —— 现已 PASS

我的 P0-② 用 RUF100 把 6 处 # noqa: BLE001 - <理由> 降级为 # <理由>， 而 scripts/check_bare_except.py 恰恰要求 noqa: XXX - <理由> 或 # defensive: <理由> 作为审计豁免凭证 ⇒ 凭证失效 ⇒ 该门禁 9 → 11 处 → FAIL。

现已恢复：那 6 处（core/database.py:111,116、order/beile.py:232、 outsource/_shipments.py:228,401、purchase_order_sku.py:86）已改为门禁认可的 # defensive: <理由> 形式。实测 quality_gate.py EXIT=0 [PASS]。 （该修复非本轮所为；本轮仅复核并确认。）

教训：RUF100 的「unused」判定只看 ruff 自己的规则集， 看不见其它工具（如本项目自研 AST 门禁）对同一注释的依赖。凡把 noqa 当跨工具凭证的地方， 一律改用工具中立的 # defensive: 形式。
