四、过程中踩到 / 发现的既有问题

已修 alembic.ini 必须保持纯 ASCII

Alembic 用 encoding="locale" 读 ini（alembic/util/compat.py:144），zh-CN Windows = GBK。 我第一次写入中文注释后，所有 alembic 命令立即崩在 UnicodeDecodeError: 'gbk' codec can't decode byte 0xa8 in position 68。已改为 ASCII 英文注释。

既有 upgrade head --sql（离线 dry-run）在本仓必失败 —— 非本次引入

失败于 _delete_version 的 KeyError。对照实验：用旧语义（cd migrations）跑同一条命令， 同样 EXIT=1、同类 KeyError、生成的 SQL 行数完全相同（4149） ⇒ 与本次改动无关。

根因：迁移图为 4 个 base / 9 个 fork / 5 个 merge（收敛为单 head，linear_graph = False）， 离线模式无法线性化。CI 实际执行的在线 upgrade head 逐条走图，不受影响。 ⇒ 需要 dry-run 请走「克隆库 + 真实 upgrade head」，不要依赖 --sql。

证据：_qa_tmp/alembic_graph_ctrl.txt

未修 · 建议单独处理 生产审计的迁移检查是假阴性

scripts/prod_audit/layers/l11_deployment.py:401-412 查找的是 PROJECT_ROOT/alembic.ini 与 PROJECT_ROOT/alembic/ —— 两者都不存在 （真实路径是 migrations/alembic.ini 与 migrations/versions/）。

后果：该审计层会直接输出「Alembic 未配置,跳过迁移检查」并 静默跳过，属假阴性。 建议改指向真实路径 —— 但这会把「静默跳过」变成「真实检查」，可能浮出新的审计问题，故未擅自改动。
