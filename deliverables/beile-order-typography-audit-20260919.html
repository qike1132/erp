1 · 一句话结论

页面字体颜色不统一，不是随机着色，而是三条可复现的结构性根因：

  1. success 语义在页面内分叉 —— 三个共用同一浅绿底 #e8f9ef 的徽章，文字色却取了两档：--color-success-600（青绿 #1e9e55）与 --color-success-700（黄绿 #2e7d32）。二者色相不同，同屏可直接对比。
  2. 「订单数量」列额外着色品牌蓝 —— .bo-qty--ordered 在加粗之外又声明了 color: primary-700，造成相邻两列异色、同列上下行异色；而源码注释只写了「加粗」。
  3. 次要信息灰阶分档过密 —— text-secondary #475569 与 text-muted #64748b 在同类数据单元格上无层级依据地混用，字重亦不统一（400 / 500 / 600 三档）。

4 · 严重问题详述

C1 · 同一浅绿底上并存两种绿 severe

现象：表格「订单类型」列的「订单」徽章是青绿，「小义开单」的「已开单」、「确认状态」的「已确认」是黄绿，而三者底色完全相同。

改动后 · 统一 #2e7d32
订单 已开单 已确认
文字色唯一，底色不变

成因

  • frontend-vite/src/views/beile-order/components/BeileOrderRow.vue:277 — .bo-type-badge--order 取 var(--color-success-600)
  • BeileOrderRow.vue:295 — .bo-open-badge--done 取 var(--color-success-700)
  • BeileOrderRow.vue:321 — .bo-confirm-badge--done 取 var(--color-success-700)
  • 详情弹窗重复定义同款样式：BeileOrderDetailDialog.vue:319 / 337 / 363（取值与列表一致，故问题同源）

证据（实测 vs 声明）

元素声明（源码）实测 color实测 background节点数
.bo-type-badge--order--color-success-600 → #1e9e55rgb(30,158,85)rgb(232,249,239)18
.bo-open-badge--done--color-success-700 → #2e7d32rgb(46,125,50)rgb(232,249,239)2
.bo-confirm-badge--done--color-success-700 → #2e7d32rgb(46,125,50)rgb(232,249,239)18

影响（量化）：已确认 TAB 下 38 个绿徽章中，18 个（47%）与其余 20 个色相不同。
另：#1e9e55 在 #e8f9ef 上的对比度为 3.20:1，低于 WCAG AA 小字要求的 4.5:1；#2e7d32 为 4.75:1，达标。

改法：两处组件统一取 --color-success-700（既有底色不变，同时修复对比度）。

C2 · 「订单数量」列的品牌蓝 severe

现象：表格中「订单数量」是蓝色数字，「生产数量」是黑色数字 —— 相邻两列、同为数量，颜色不同。

成因：BeileOrderRow.vue:233 —— .bo-qty--ordered { font-weight: 700; color: var(--color-primary-700, #2d5ab8); }。
而模板注释 BeileOrderRow.vue:37 只说明「来自采购单实际下单量时加粗」——实现超出了注释意图，额外引入了颜色。

证据：首行实测 —— .bo-qty--ordered rgb(45,90,184) / fw700；.bo-prod rgb(26,26,46) / fw600。且同一「订单数量」列内，已下单行为蓝、未下单行为黑（同列两色）。

影响：一列两色 + 相邻列异色，破坏列语义一致性。而「是否已下单」在同一行已由「已开单」徽章（.bo-open-badge--done）独立表达，颜色属冗余信息。

改法：移除该 color 声明，仅保留 font-weight: 700，使数字列统一取正文色。

9 · 第二轮修复：SKU 列与数量列形态对齐

第二轮反馈：「SKU、订单数量 —— 内容显示不一致，字体大小和图标」。经实测，两列同处一行数字区，却在字号与形态上分属两套。

即：SKU 列是一个带内边距与圆角的「胶囊」，数量列是纯文本；且 SKU 列自身在单 / 多 SKU 之间又有「灰字无底」与「蓝字带底」两种形态。

9.2 关于「图标」——实测澄清

探针对两列做了图标元素计数：tableIcons = 0，即两列内不存在任何 svg / i / img 图标元素（整个表格区亦为 0）。
因此用户感知到的「图标」应为 SKU 列的胶囊形态 —— padding: 1px 8px + border-radius: 6px，多 SKU 时再叠加 #eff5ff 浅蓝底，视觉上像一个独立的标签标记，与相邻的纯文本数字列形成割裂。

9.3 改法

  • 字号 12px → 13px，与「订单数量 / 生产数量」列对齐。
  • 移除胶囊形态：padding: 1px 8px → 0、border-radius: 6px → 0、多 SKU 的 background 移除。
  • 保留多 SKU 的语义强调：仍以 --color-primary-600 + font-weight: 600 区分（与 .bo-prod 的 600 字重体系一致），不再依赖背景色块。［第三轮已修订：颜色 + 字重强调被判定为行间不一致，已移除，见 §9A］

9A · 第三轮修复：列内行间不一致清零

第三轮反馈（附截图，未确认 TAB 前两行）：「这两行还是不一致」。上一轮解决了「列与列之间」的形态差，本轮实测发现残留的是「同一列之内、行与行之间」的呈现差 —— 用户圈选的第 1、2 行恰好同时踩中两处。

9A.1 实测定位（改动前，逐行 computed style）

9A.2 根因与改法

  • C9：第二轮保留的「多 SKU 蓝 600 强调」使同一单元格因数据不同呈现两套样式。SKU 数文本本身（「4 项」vs「1 项」）已经表达数量差异，无需再加视觉强调 → 移除 .bo-sku-count--multi 的颜色与字重声明，全列统一为 13px / 400 / --color-text-muted（元数据弱于数量列正文，层级合理）。
  • C10：.bo-qty--ordered 的 font-weight: 700 与行内「小义开单」徽章表达同一信息（第二轮已据此移除其颜色，本轮把字重一并收口）→ 移除 700 声明，订单数量全列统一 600。
  • 语义钩子保留：bo-sku-count--multi / bo-qty--ordered 类绑定仍挂在 DOM 上（4 个测试文件以此断言「多 SKU / 已开单」行为契约），仅 CSS 层不再产生视觉差异 —— 语义层与视觉层解耦。
