样例用生产库真实数据：PO-20260930-0013 · MINISO国际 · 3 个 SKU · 合计 30000（每 SKU 各 10000）
问题：一行只显示第一个 SKU 的产品名+订单总数量。PO-20260930-0013 的另外两个 SKU（「鲨鱼」「《蛋仔派对》团子木鱼毛绒挂件盲盒-黄蛋 陈列样」） 在列表里完全看不到，只能靠 SKU 数量那个绿徽章「3」知道还有别的。现在唯一能看到全部 SKU 的入口是点眼睛 → 详情弹窗里的「订单明细」表。
另：合并后「备货行」的查看按钮是坏的（我这次改动引入，必须先定）
旧的备货页签里表格根本没有「操作」列（actions 只在订单模式 push），所以备货行点不到详情。合并后我给每行都加了「查看」， 但 openDetail() 不区分记录类型，一律调 GET /orders/{id}。备货行的 id 是 StockIn.id， 与订单 id 是两套独立序列：生产库里那笔备货 id=39268，而订单 id 范围是 68819~68915， 查 id=39268 的订单 → 0 行 → 必然 404 → 弹「获取订单详情失败」，且后端不存在备货详情端点（只有 /stock/in/list）。
处置二选一：(a) 备货行先撤掉「查看」按钮（回到旧的"备货行无操作列"行为，止血，最小改动）； (b) 给备货做详情弹窗（要新增 GET /stock/in/{id} 端点 + 前端弹窗，是独立一块活）。

方案 B · 产品列堆叠显示全部 SKU 备选

不加交互，把 SKU 名直接堆在产品格里，名字后面跟各自数量。缺点很明显：SKU 多的行会把整行撑得很高， 3 个 SKU 已经是 3 行文字，10 个 SKU 的行会占掉大半屏，而且与"数量"列的总数分离、容易读错。
