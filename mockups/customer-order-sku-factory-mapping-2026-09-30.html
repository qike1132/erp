哪个 SKU 在哪个厂 · 对比稿

页面：/customer-order → 记录查询  ·  2026-09-30  ·  未改代码  ·  用生产库真实数据（PO-20260930-0013 的 3 个 SKU） ·  已按你选的选项 A（产品名称列居中 + 块缩排）
你指出的问题成立，而且比"看不出来"更严重：现有数据里这条信息是被聚合掉的。
工厂列显示的是订单级聚合值 factories: ['东莞','湖北']。这笔订单的三个 SKU 实际是： 盲盒→东莞、鲨鱼→湖北、团子木鱼→东莞。合成"东莞, 湖北"之后， 「鲨鱼是湖北的」这条信息就没了 —— 不是没显示，是已经不在下发的数据里。
所以下面三个方案都需要先加一小段后端改动：items[] 目前只有 id / product_id / product_name / product_barcode / product_image / quantity / deduct_quantity / note， 没有 factory，前端拿不到"这个 SKU 是哪个厂"。
改法：fastapi_app/services/order/unified.py 的 _build_order_record() 与 _build_stockin_record() 各给 item 加一个 'factory': item.product.factory。
不会引入新查询：_fetch_orders() 已经用 selectinload(Order.items).joinedload(OrderItem.product) 把 items→product 预加载了，item.product.factory 是白拿的，没有 N+1 风险。

我倾向 A：它直接回答你的问题且不牺牲扫读 —— 厂名在一列里，一眼能圈出全部湖北的 SKU。 C 的序号在"名字被截断"时有真实价值，但你们的产品名现在最长也就到"…黄蛋 陈列样"这种，截断还不常见，可以先不上。

三个方案共同的改动面：
· 后端 unified.py：_build_order_record / _build_stockin_record 的 item 各加 factory（约 2 行）
· 前端类型 api/order.ts 的 UnifiedRecord.items 加 factory?: string | null
· OrderRecordTable.vue：工厂列渲染（A/C 逐行堆叠、B 并入产品行）
· 顺带：factories 聚合字段在多 SKU 行下就不再需要了（单 SKU 行仍可用），可以先留着不动

测试：后端加"items 里每个 SKU 带上自己的 factory"用例（真实 SQLite）；前端加"多 SKU 行的工厂列渲染 3 条且与 SKU 顺序一致"用例。
