# 01 · 增量 PRD：BOM 全局角色字典 + 计算器按角色展示 + 跨角色共有物料矩阵

## 0. 文档头

| 项 | 内容 |
|---|---|
| 需求名称 | BOM 多角色支持：全局角色字典、计算器按角色分块、跨角色共有物料矩阵 |
| 版本 | v1.0（增量 PRD，非从零重做） |
| 日期 | 2026-09-17 |
| 关联页面 | `http://192.168.0.95:3000/product`（BOM 编辑）、`http://192.168.0.95:3000/material-calculator`（物料用量计算） |
| 一句话目标 | 把「角色」从产品私有升级为全局字典，并让物料计算器**按角色分别展示用量**、额外给出**跨角色的共有物料对比矩阵**，使两页口径一致、可跨角色统计。 |
| 现状基线 | 产品内私有角色 + BOM 多角色编辑**已实现并已进生产产物**（dist 命中 `bom-role-tab` 指纹）；计算器**无角色维度**，是把默认 BOM + 全部角色合并成一个口径——本次主要缺口。 |

> 口径前提（用户已确认，实施中不得推翻）：
> 1. 角色 = **全局字典，跨产品复用**（最重方案）。
> 2. 共有物料判定键 = **物料名称 + 规格型号 + 供应商**。
> 3. 展示形态 = 独立「**角色对比**」区，**矩阵**（物料为行 / 角色为列 / 末列合计）。
> 4. 沿用 9-11 已定语义：**一个产品只录一个订单总数量，每个作用域都用这个总数量展开计算（不分摊）**；结果按作用域分块；默认 BOM 恒在首块。

## 1. 问题定义

| # | 问题 | 现象 | 影响 | 现有证据 |
|---|---|---|---|---|
| P-1 | 角色为**产品私有**，跨产品无法复用 | 产品 A 建了「角色-爸爸」，产品 B 想用同一角色必须再建一遍同名记录，且两处名称可能漂移（「爸爸」/「爸爸 」/「Dad」） | 主数据重复、口径不统一；跨产品统计「同一角色」时无法撮合；角色改名要逐产品改 | `ProductRole` 表字段 = `product_id + role_name`，无全局唯一约束；`bom_service.save_bom` 按 `product.roles` 逐产品全量替换 |
| P-2 | 计算器口径与录入页**不一致** | 录入页在「角色」作用域下只显示该角色的 1 条物料；计算器却合并默认 BOM + 全部角色显示 10 条，用户以为丢数据/串数据 | 计划员按计算器下的采购量无法对应到具体角色 BOM；无法按角色排产/备料 | 9-11 三路交叉验证结论：**口径差异非 BUG**。`purchase_product_service.aggregate_materials()` 现版把 `product.get_all_materials()` 合成一个扁平 `{filling/fabric/accessory/packaging}`；`calculate_material()` **未加载 `Product.roles`** |
| P-3 | 无**跨角色对比**能力 | 想知道「哪些物料被多个角色共用、各角色用量差多少」，只能人工逐角色两两比对 | 无法识别共用物料（可合并采购/议价）、无法发现某角色漏配或超配 | 现有结果表只有单一口径清单；`CalcResultColumn.vue` 结果表 `row-key="material_name"`，同分类同名不同规格/供应商还会 key 冲突丢行（缺陷②，见 REQ-P0-11） |

## 2. 目标与非目标

### 2.1 目标（3 个，正交）
- G1 **角色主数据全局化**：角色升级为跨产品复用的全局字典，存量数据无损归并，BOM 编辑照常可用。
- G2 **计算口径角色化**：计算器按 BOM 作用域（默认 BOM + 各角色）分块展示，与录入页/订单生成口径三者一致。
- G3 **跨角色可比**：提供共有物料矩阵，一眼看清哪些物料被多角色共用、各角色用量差异与合计。

### 2.2 非目标（本次明确不做，附理由）

| 不做 | 理由 |
|---|---|
| 不改订单生成链路（`purchase_order_generate._scope_order/_bom_rows_by_scope/_scope_label`）的**作用域化逻辑** | 该链路已作用域化并保留至今，与本次目标方向一致；仅需保证**角色来源改为全局字典后取角色名仍然正确**（属回归，不属新设计） |
| 不做角色级**权限 / RBAC** | 用户诉求是「不同角色可维护各自的 BOM 配置」，指的是 BOM 内容维度而非账号权限；无权限需求输入，避免范围蔓延 |
| 不做**按角色分别录入订单数量** | 与 9-11 已确认语义冲突（一个产品只录一个总数量、各作用域按同一总数量展开、不分摊）；若要改动须单独立项 |
| 不做**自动单位换算引擎** | 本次只处理「单位不一致时不得错误相加」的展示规则（见 REQ-P0-08），不做跨单位数值自动转换 |
| 不做角色**多变体 BOM**（同产品同一角色多份） | 无需求输入，且会破坏 `product_id + role_id` 唯一语义；列为待确认（Q-01） |
| 不重做 BOM 编辑器的角色标签页交互骨架 | 已实现并已进生产；本次只做「默认停靠作用域」修正与全局角色入口（REQ-P0-09 / 交互设计） |

## 3. 用户故事

| # | 角色 | 故事 |
|---|---|---|
| US-1 | 主数据维护者 | As a 主数据维护者，I want 维护一份全局角色字典并让多个产品复用同一角色，so that 角色命名统一、不用逐产品重复建、改名只改一处 |
| US-2 | 产品/BOM 维护者 | As a BOM 维护者，I want 给同一产品的多个角色分别配置 BOM，且清楚知道「我此刻改的是哪个作用域」，so that 我不会把物料误挂到角色而非默认 BOM |
| US-3 | 采购/计划员 | As a 采购/计划员，I want 按角色查看各自物料用量，并看到跨角色共有物料的对比矩阵，so that 我能识别可合并采购的共用物料、发现用量异常 |
| US-4 | 数据迁移视角 | As a 运维/迁移执行者，I want 存量产品私有角色能自动上卷归并为全局角色且迁移后可回滚，so that 迁移后旧页面/旧客户端照常工作、无数据丢失 |
| US-5 | 移动端用户 | As a 移动端用户，I want 在手机上也能看到按角色分块的结果（矩阵可折叠/横滑），so that 现场也能按角色核对 |

## 4. 需求池（P0 / P1 / P2）

> 优先级：P0 = Must have（本次交付必须）；P1 = Should have；P2 = Nice to have。
> 验收要点均为**可观测、可断言**。

### 4.1 P0

| 编号 | 需求描述 | 验收要点（可断言） |
|---|---|---|
| **REQ-P0-01** | **全局角色字典**：角色主数据跨产品复用，提供最小维护能力（列表 / 新建 / 改名 / 删除），入口可内嵌于 BOM 编辑器，不强制独立页面 | ① 在任一产品新建一个此前不存在的角色后，另一产品的角色选择器**无需重建**即可选到同名角色；② 两端引用的是**同一条**角色记录（同一 id）；③ 字典内角色名唯一性校验生效（见 §5） |
| **REQ-P0-02** | **产品 × 角色关联**：产品可关联 / 解绑一个或多个全局角色；同一产品同一全局角色**只允许一份 BOM** | ① 产品 A 关联「爸爸」「妈妈」后，BOM 编辑器出现两个角色作用域；② 重复关联同一角色被拒（幂等或校验报错）；③ 解绑某角色后该产品不再出现该作用域，但**全局字典内该角色仍存在**（不被连带删除） |
| **REQ-P0-03** | **物料归属全局角色**：物料行的角色归属引用全局角色；默认 BOM（`role_id IS NULL`）语义**保持不变** | ① 角色改名后，其下物料归属不变（按 id 关联，不按名称）；② 默认 BOM 物料在计算器中仍归入「默认 BOM」块，不被误算入任一角色 |
| **REQ-P0-04** | **存量数据迁移与归并**：把现有 `product_role` 去重上卷为全局角色，重建「产品×角色关联」与「物料归属」；迁移**幂等 + 可回滚 + 零丢失** | ① 迁移前后物料行总数守恒（按分类计数一致）；② 迁移脚本重复执行结果不变（幂等）；③ 有回滚脚本且演练通过；④ 迁移后随机抽样 3 个存量产品的 BOM 与迁移前逐行一致（含 role 归属） |
| **REQ-P0-05** | **计算器按角色分块（`groups` 契约）**：`POST /purchase-center/calculate` 返回 `groups`，沿用 9-11 契约字段：`product_id / product_name / role_id / role_name / quantity + filling/fabric/accessory/packaging`；**默认 BOM（`role_id=None`）恒在首块**；单产品单总数量、每作用域用同一总数量展开（**不分摊**） | ① 一个含 1 个默认 BOM + 2 个角色的产品，总数量 N，返回 3 个 group（空作用域不产出块）；② 每块的物料量 = 该作用域单 SKU 用量 × N，三块之和不参与相互分摊；③ group 顺序：默认 BOM 在前、其余按稳定序（角色名升序，见 §5）；④ `role_name` 缺失时退化为「角色#<id>」而非静默丢弃 |
| **REQ-P0-06** | **旧接口 / 旧客户端兼容**：响应在新增 `groups` 的同时**保留原扁平字段**（`filling/fabric/accessory/packaging`，按全作用域合并口径）；schema 以「追加」而非「替换」实现 | ① 只读旧字段的旧客户端不报错、不白屏；② 旧扁平字段的数值 = 原口径（全作用域合并），可用于回归比对；③ 前端在 `groups` 缺失时回退旧扁平渲染，不抛异常 |
| **REQ-P0-07** | **角色对比矩阵**：独立区，物料为**行**（判定键 = 名称 + 规格型号 + 供应商）、角色为**列**、**末列合计**；数据源取自 `groups` | ① 同一「名称+规格+供应商」在多个角色出现时，落在同一行；同名但规格或供应商不同 → **不同行**（不得合计）；② 末列合计 = 该行各角色列数值之和（受 REQ-P0-08 约束）；③ 只有 1 个角色时矩阵隐藏（见 REQ-P1-02） |
| **REQ-P0-08** | **矩阵单位一致性合计规则**：判定键**不含单位**，但合计列做单位一致性校验。仅当该行在所有出现角色中的**单位完全相同**才给出数值合计；**否则不得相加** | ① 单位一致 → 末列给出数值合计；② 单位不一致 → 末列显示「单位不一致 · 不合计」，且该行**按单位拆分为多行**（每行仅同单位角色的列有值，其余列显示「—」，合计只对同单位子集求和）；③ 任何情况下不会出现「码 + 个」被相加的数值 |
| **REQ-P0-09** | **BOM 编辑器默认停靠作用域修正**（缺陷①）：打开 BOM 弹窗时默认停靠在「**默认 BOM**」作用域，而非 `bomRoles[0]` | ① 有角色数据的产品，打开 BOM 弹窗后当前作用域 = 默认 BOM（标签高亮在「默认BOM」）；② 在角色作用域下点「添加物料」前，界面明确显示当前归属作用域（作用域徽标/面包屑），不会静默挂到角色 |
| **REQ-P0-10** | **两页口径一致性**：录入页作用域展示、计算器分块、矩阵三者的**归属 / 命名 / 顺序**一致：默认 BOM 恒为**首块 / 首列**，角色顺序为同一稳定序 | ① 同一产品在录入页看到的角色清单顺序 = 计算器 groups 顺序 = 矩阵列顺序（除矩阵可能隐藏单角色情形）；② 默认 BOM 自定义名（`default_bom_label`）在三处显示一致；③ 端到端脚本可断言三处集合相等 |
| **REQ-P0-11** | **结果表 key 冲突修复**（缺陷②）：`CalcResultColumn.vue` 的 `row-key` 由 `material_name` 改为**稳定复合键**（含规格 + 供应商 + 单位，与 REQ-P0-07 判定键一致） | ① 同分类、同名、不同规格/供应商/单位的多行**全部渲染**，无丢行；② 行 key 在同一分类内唯一 |

## 5. 字段与口径定义表

| 定义项 | 口径 | 备注 |
|---|---|---|
| 全局角色名称 | `trim` 去首尾空白；**比较不区分大小写**；存储保留用户输入原样；全局唯一 | 冲突时返回校验错误，不静默改名 |
| 角色改名影响面 | 物料按 **id** 关联 → 改名只改显示名，不影响归属；历史 `PurchaseOrderItem.remark` 存的是**角色名字符串快照**，改名**不级联改写历史** | 见 Q-02 / Q-04 |
| 产品 × 角色关联 | `(product_id, global_role_id)` 唯一；同产品同角色仅一份 BOM | 与现有 `uq_product_material_product_role` 语义对齐 |
| 物料归属 | 物料行 `role_id` 指向全局角色；`role_id IS NULL` = 产品级默认 BOM | 默认 BOM 语义不变（REQ-P0-03） |
| **共有物料判定键** | `(物料名称, 规格型号, 供应商)`，**不含单位** | 用户已确认最严口径；单位单独用于合计校验（REQ-P0-08） |
| 材料类别 | `fabric` 面料 / `filling` 填充 / `accessory` 辅料 / `packaging` 包装 | 计算器与矩阵**不展示包装类**，但接口保留返回 |
| 单位与精度 · 面料 fabric | 单位 **码**；展示保留 2 位小数 | 9-11 记录：单位是码/个，仅填充走 kg 换算 |
| 单位与精度 · 填充 filling | 单 SKU 用量单位 **克**；汇总时换算为 **kg（1 kg = 1000 克）**，展示保留 3 位小数 | 换算仅用于展示，不改底层存储（克） |
| 单位与精度 · 辅料 accessory | 单位 **个**；按原值展示，保留 0–2 位 | — |
| 包装 packaging | 不纳入计算器/矩阵展示 | 接口字段保留以兼容 |
| 作用域顺序 | 默认 BOM(`None`) 恒在**首位**，其余按**角色名升序**（名称相同再按 id 升序）稳定序 | 与 `purchase_order_generate._scope_order` 现「按 role_id 升序」需**统一**为同一序（见 Q-05） |
| 数量语义 | 每产品一个**订单总数量**；每个作用域都用该总数量展开；**不分摊** | 9-11 已确认语义（REQ-P0-05） |

## 6. 交互与展示设计要点

> 设计基调：扁平、克制、分层仪表台；参考 Ant Design / Arco / TDesign 语言；**拒绝表单式 grid，倾向分层卡片 / 矩阵**；无花哨渐变与动效。

### 6.1 BOM 编辑器（/product）

- **全局角色入口**：在角色标签页区提供「选择已有全局角色」下拉 + 「新建角色」；已有角色直接关联到当前产品，不复制角色记录。
- **默认 BOM 与角色并列**：默认 BOM 作为**首个固定作用域**与角色标签并列；默认 BOM 名称可自定义（沿用 `default_bom_label`）。
- **默认停靠修正**（REQ-P0-09）：打开弹窗默认高亮「默认 BOM」，不再默认落在 `bomRoles[0]`。
- **当前作用域提示**：顶部常驻作用域徽标 / 面包屑；在非默认作用域下点「添加物料」时，按钮文案或提示需显式声明「将挂到：<作用域名>」。
- **空态**：角色作用域无物料时展示空态文案（P1-04）。

### 6.2 物料计算器（/material-calculator）

- **录入**：沿用单一「订单总数量」录入（不分摊）。
- **结果分块**：按作用域分块**卡片**渲染，默认 BOM 恒在首块；每块内按 filling/fabric/accessory 分区，包装类不展示。
- **独立「角色对比」矩阵区**（位于分块结果之后）：
  - 列 = 默认 BOM + 各角色（默认 BOM 是否计入见 Q-06）；
  - 行 = 共有物料判定键（名称 + 规格 + 供应商）；
  - 末列 = 合计（受 REQ-P0-08 单位一致性约束）；
  - **共有物料高亮 / 分组**：被 ≥2 个角色共用的行做视觉分组或高亮，与仅单角色出现的行区分；
  - **排序**（P1-01）：共有角色数降序 → 合计用量降序 → 类别/名称稳定序；
  - **显隐与空态**（P1-02）：仅 1 个作用域列时隐藏矩阵并提示；无共有物料时空态。
- **单位不一致**（REQ-P0-08）：末列显示「单位不一致 · 不合计」，该行按单位拆行，禁止跨单位求和。
- **移动端**（P1-03）：`MMaterialCalculatorView` 同步分块；矩阵以折叠卡片 / 横滑呈现。

## 7. 待确认问题（每条给默认建议）

| 编号 | 问题 | 默认建议 | 风险 |
|---|---|---|---|
| **Q-01** | 全局角色是否允许「同产品同一角色多份 BOM」？ | **不允许**（保持 `product_id + role_id` 唯一）；多变体用角色命名区分 | 若现场确有多变体场景，需另立需求 |
| **Q-02** | 角色删除对存量物料的影响？ | **禁止删除已被任意产品物料引用的全局角色**；确需删除则先解绑，并对引用物料给出处理向导 | 直接硬删会丢物料归属 |
| **Q-03** | 角色删除/改名对**历史采购单**的影响？（`PurchaseOrderItem.remark` 存角色名字符串） | 历史 `remark` 是**快照**，改名/删除**不改写历史文本**，保证历史可读性不变；需要「当前名」时走 P2-03 实时回填 | 若期望历史同步改名，需迁移改写历史文本（有争议，建议不做） |
| **Q-04** | 存量归并规则：**不同产品下的同名角色是否合并为一个全局角色**？ | **合并**：`trim` 后名称完全一致才合并（大小写不敏感比较）；其余保留为独立全局角色，避免误并 | 误并会让两个本意不同的同名角色共用 BOM 归属；迁移前需出**归并报告**人工确认 |
| **Q-05** | 作用域稳定序用「角色名升序」还是现有「role_id 升序」？ | **统一为角色名升序**（更符合用户可读预期），并同步 `purchase_order_generate._scope_order` 的排序口径保持一致 | 改动排序会影响既有回归断言与历史顺序预期 |
| **Q-06** | 「默认 BOM」是否作为一列参与矩阵（是否计入共有判定与合计）？ | **计入**，作为首列（列名用 `default_bom_label`），与分块口径一致；如需只看角色间对比，可加开关 | 不计入会与「分块里默认 BOM 存在」产生新的口径分歧 |
| **Q-07** | 矩阵单位不一致时「按单位拆行」是否可接受？ | 接受（P0-08 结论）；如不接受，则退化为末列统一显示「不合计」不拆行 | 拆行会增加行数、需要前端排序配合 |
| **Q-08** | 存量迁移窗口与停机策略？（生产机、改后端需重启 `erp-prod`） | 迁移脚本优先**幂等 + 可在低峰执行 + 可回滚**；重启 `erp-prod` 前先备份 DB | 生产机即本机，迁移失败会阻塞业务 |

## 8. 验收场景清单

> 标注 【E2E】= 需**真实浏览器**端到端（用户要求浏览器专属能力必须真机 E2E，不能只靠单测）；【UT】= 可单文件单测；【MO】= 需移动端视口/真机。

| # | 场景 | 类型 | 断言 |
|---|---|---|---|
| A-1 | 全局角色新建与跨产品复用 | 【E2E】 | 产品 A 新建角色 R → 产品 B 选择器可选到 R，且为同一记录 |
| A-2 | 存量迁移数据守恒与幂等 | 【UT】 | 迁移前后物料行按分类计数一致；重复执行结果不变 |
| A-3 | BOM 编辑默认停靠默认 BOM | 【E2E】 | 打开弹窗后高亮「默认 BOM」；在角色作用域添加物料前有归属提示 |
| A-4 | 计算器按角色分块 | 【E2E】 | 1 默认 BOM + 2 角色 → 3 块，默认 BOM 首块，各块量 = 单 SKU 用量 × 总数量 |
| A-5 | 计算器旧接口兼容 | 【UT】+【E2E】 | 旧扁平字段仍在且数值等于原合并口径；`groups` 缺失时前端回退渲染不报错 |
| A-6 | 共有物料矩阵分组 | 【E2E】 | 同名+同规格+同供应商跨角色落同一行；同名不同规格/供应商分行 |
| A-7 | 矩阵单位不一致不合计 | 【E2E】 | 单位不一致行末列显示「不合计」且不出现相加数值；单位一致行正常合计 |
| A-8 | 矩阵排序 | 【UT】+【E2E】 | 行顺序 = 共有角色数降序 → 合计降序 → 类别/名称稳定序 |
| A-9 | 结果表 key 冲突修复 | 【E2E】 | 同名不同规格/供应商/单位的多行全部渲染，无丢行 |
| A-10 | 两页口径一致性 | 【E2E】 | 录入页角色清单顺序 = groups 顺序 = 矩阵列顺序；默认 BOM 名三处一致 |
| A-11 | 单角色无矩阵 | 【E2E】 | 仅 1 个作用域时矩阵隐藏并显示提示 |
| A-12 | 移动端分块 + 矩阵 | 【E2E】【MO】 | 移动视口下可见分块与矩阵，布局不溢出 |
| A-13 | 角色改名后物料归属不变 / 历史单不受影响 | 【E2E】 | 改名后物料归属不变；历史采购单 `remark` 原文不变 |
| A-14 | 角色删除保护 | 【E2E】 | 删除被引用角色被拒并给出提示 |
