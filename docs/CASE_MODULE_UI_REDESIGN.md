# 皮套管理模块 UI 彻底重设计方案 (Case Management UI Redesign Plan)

## 1. 当前界面视觉问题分析 (Current Visual & UX Issues)

在深入分析当前的 `case.html` (入库)、`case_out.html` (出库) 和 `case_inventory.html` (库存查询) 页面后，我们发现了以下影响用户体验和操作效率的痛点：

### 1.1 配色不协调 (Color Inconsistency)
- **缺乏视觉焦点**：当前界面的按钮（如保存、取消、提交）使用了生硬的高饱和度原色（Bootstrap 默认的 `#0d6efd` 蓝和 `#ffc107` 黄），没有形成具有品牌辨识度的统一风格，长时间盯着看容易造成视觉疲劳。
- **状态感知弱**：入库（Stock-in）和出库（Stock-out）页面的色调没有明显的场景区分。用户在快速切换时，很容易因为视觉缺乏提示而填错表单。

### 1.2 布局混乱与空间利用率低 (Messy Layout & Spacing)
- **表单与列表失衡**：在入库/出库页面中，左侧的“信息录入”表单与右侧的“暂存列表”之间的间距和高度比例不协调。列表区域在数据较少时显得过于空旷，而表单区域又显得拥挤。
- **数据表格展示**：库存查询和记录列表的表格直接横铺在页面中，列与列之间的留白不足，特别是在包含“皮套名称”、“69码”、“操作时间”等长文本时，信息显得杂乱无章。

### 1.3 字体层级不清 (Unclear Typography Hierarchy)
- **信息主次不分**：卡片标题、表单标签 (Label)、输入框文本和辅助说明（如必填项 `*`）的字号差异过小（大多在 14px-16px 之间徘徊），字重（Weight）没有拉开差距。
- **数据弱化**：像“入库数量”、“当前库存”这样核心的业务数据，没有在视觉上被加粗放大，用户需要耗费额外的精力去“寻找”这些数字。

### 1.4 交互反馈不足 (Lack of Interaction Feedback)
- **缺乏微交互**：鼠标悬停在暂存列表的卡片或操作按钮上时，缺少平滑的位移（Translate）和阴影（Shadow）变化，导致用户感知不到“此元素可点击”。
- **状态切换生硬**：在输入产品名称进行联想搜索，或点击提交入库时，没有优雅的 Loading 动画或过渡效果，界面显得干瘪。

## 2. 新设计目标 (New Design Goals)

基于 **Plush Cute (软萌现代风)** 的整体规范，针对“皮套管理”这一核心业务模块，我们确立以下三大设计目标：

1. **提升品牌一致性 (Brand Consistency)**
   - 全面引入 **Plush Blue (`#B0E0E6`)** 作为主视觉色，将原本生硬的直角和细小圆角全部替换为 `24px` 的大圆角卡片和 `14px` 的柔和按钮，打造无压力的工作环境。
2. **增强可用性 (Enhanced Usability)**
   - **场景化色彩区分**：入库操作偏向“增加”（使用柔和的薄荷绿或主品牌蓝），出库操作偏向“消耗”（使用柔和的浅橙或警告色），从视觉底层防止用户误操作。
   - 强化数字展示：对“库存数量”、“入库总数”等关键指标使用特定的 Typography 样式放大加粗。
3. **优化信息架构 (Optimized Info Architecture)**
   - 将录入流线型化：采用**左侧悬浮卡片录入，右侧堆叠卡片暂存**的布局，底部采用无缝衔接的宽幅数据表格，确保信息的流向符合人眼“从左到右，从上到下”的阅读习惯（F-Pattern）。

## 3. 高保真设计规范与组件说明 (High-Fidelity Specs & Components)

为皮套管理量身定制的设计规范如下：

### 3.1 核心色彩系统 (Color System)
- **主导色 (Primary)**: `Plush Blue (#B0E0E6)` —— 用于入库表单的高亮、主按钮。
- **辅助色 (Secondary/Hover)**: `Plush Blue Light (#D4F1F4)` —— 用于表格斑马线交替、输入框 Focus 光晕。
- **出库警示色 (Stock-Out Accent)**: 柔和橙色 `rgba(255, 193, 7, 0.15)` —— 作为出库界面的特定背景点缀。
- **文本层级**:
  - `Plush Text (#5A4A4A)`: 核心正文、标题。
  - `Plush Text Light (#8B7B7B)`: 表单 Label、备注说明、时间戳。

### 3.2 组件规范 (Component Rules)
- **卡片 (Cards)**:
  - 圆角：`border-radius: 24px`
  - 阴影：常态 `0 4px 20px rgba(176, 224, 230, 0.25)`；悬停时提升至 `0 8px 25px rgba(135, 206, 235, 0.35)` 并伴随 `transform: translateY(-2px)` 的 0.4s 平滑过渡。
- **输入框与下拉联想 (Inputs & Autocomplete)**:
  - 圆角：`12px`
  - 边框：常态 `1px solid #D4F1F4`，Focus 时边框变为 `#87CEEB`，无生硬的黑色或蓝色外轮廓。
  - 尺寸：高度提升至 `44px`，确保在触摸屏或鼠标点击时的易用性。
- **状态徽章 (Badges)**:
  - 采用更柔和的背景配合深色文字，圆角 `6px`，如暂存列表中的“数量：X”。

## 4. 响应式断点说明 (Responsive Breakpoints)

为适应车间扫码枪（小屏）、办公平板（中屏）和管理后台（大屏）的不同场景：

| 屏幕类型 | 断点 (Breakpoint) | 布局与展示策略 |
| :--- | :--- | :--- |
| **手机/扫码枪 (Mobile)** | `< 768px` | **单列流式布局**。左侧表单与右侧暂存列表变为上下堆叠。表格隐藏“备注”、“客户”等次要列，只保留“皮套名称”和“数量”。按钮占满 100% 宽度。 |
| **平板 (Tablet)** | `≥ 768px` | **双列布局**。入库表单占 5 栏 (`col-md-5`)，暂存列表占 7 栏 (`col-md-7`)。表格允许横向滚动（`table-responsive`）。 |
| **桌面 (Desktop)** | `≥ 992px` | **完整布局**。展示全部表格字段，卡片之间保持 `24px` (`g-4`) 的充足留白，信息呈现最为舒展。 |
| **超大屏 (Ultra Wide)**| `≥ 1400px` | 页面内容最大宽度限制在 `1320px`，居中对齐，防止视线左右移动过大导致疲劳。 |

## 5. 用户测试计划 (User Testing Plan)

为确保新版“皮套管理”UI 确实优于旧版，我们制定了以下严格的测试和验收流程：

### 5.1 5秒测试 (5-Second Test)
- **测试对象**：5名仓库录入员。
- **执行方式**：向他们展示新版“皮套入库”高保真原型 5 秒钟，然后关闭。
- **评估问题**：
  1. 页面最主要的功能是什么？
  2. 如果你要提交一批入库，你刚才看到按钮在哪里了吗？
- **成功标准**：100% 的用户能说出这是“入库”页面，且 >80% 的用户能准确回忆起“提交暂存”按钮的位置。

### 5.2 A/B 测试 (A/B Testing)
- **测试场景**：高频批量入库操作。
- **变量设置**：
  - A组 (旧版 UI)：使用原有的高密度表单和无动画列表。
  - B组 (新版 Plush Cute UI)：使用大圆角卡片、清晰字重区分和悬停反馈的新版。
- **任务指令**：“请连续录入 3 个不同的皮套产品（共 150 个），并确认提交到总库存。”
- **量化指标**：
  - **完成时间 (Time on Task)**：新版预期比旧版缩短 **15%**。
  - **操作错误率 (Error Rate)**：如填错数量、漏填客户，新版预期降低 **30%**。

### 5.3 系统可用性量表 (SUS - System Usability Scale)
- A/B 测试完成后，让所有受试者填写 SUS 问卷（10个问题，1-5分制）。
- **成功标准**：新版 UI 的 SUS 综合得分必须达到 **85分以上**（行业平均卓越线为 80.3 分），且显著高于旧版得分。

### 5.4 性能与可访问性验收 (Performance & Accessibility)
- **可访问性 (a11y)**：使用 Lighthouse 测试，确保色彩对比度符合 WCAG 2.1 AA 标准，输入框 `aria-label` 完整，得分 **≥ 90 分**。
- **性能 (Performance)**：确保引入的 CSS 阴影和过渡动画不影响渲染，LCP (最大内容渲染时间) **< 2.5 秒**，FID (首次输入延迟) **< 100 毫秒**。
