## 2. 核对结果：**0 处不一致**

对全部 50 个 SKU 逐项比对：

| 检查项 | 口径 | 结果 |
|---|---|---|
| `/stock` 订单数量 | `max(0, Σord − 直出 − 出货净)` | ✅ |
| `/stock` 备货数量 | `Σ_si(si.quantity − consumed)`（consumed 含退货冲减） | ✅ |
| `/stock` 出货数量 | `Σ(quantity−returned)`，stockin_id IS NULL | ✅ |
| `/stock` 总订单(total_stock) | 备货数量 + 订单数量 | ✅ |
| `/stock` 库存结余 | `Σ生产(packaging) − Σ出货流水净额`（含退货两型、不含抵扣三型） | ✅ |
| `/stock` 顶部聚合（订单数量/备货数量/总订单） | 客户维度求和 | ✅ |
| `/report` 订单 / 备货 / 抵扣流水 | 对应口径 | ✅ |
| `/report` 出货流水 | **毛量** `SUM(quantity)`（不扣退货） | ✅ |
| 每 SKU 不变量 `current_stock == Σ生产+Σ备货−Σ抵扣−Σ出货` | — | **50/50 成立** |

写侧无静默丢失：订单/明细/备货/生产 = 9000/9000/9000/9000。

## 3. 关键口径澄清（本次踩到）

- **`/report` 出货流水 = 毛量 `SUM(quantity)`**（不扣退货），而 **`/stock` 出货数量 = 净量 `SUM(quantity−returned)`**。
  二者在**有退货时不同源**，是**应用的刻意设计**（出货毛量、退货在「退货流水」tab 单列，2026-10-08 业务裁定）。
  首轮 verify 误用净量比对毛量报表 → 假 FAIL；修正后全绿。
- `/report` 备货抵扣流水 = **净量** `SUM(quantity−returned)`。
- 库存结余**不含抵扣三型**（订单抵扣/取消抵扣/抵扣回滚）；`生产入库`、`订单` 两类 inventory_log 也不计入结余。

### ⚠️ 测试盲区（测试永远测不出、只有读代码能发现）

**抵扣行退货虚增「库存结余」**：`stock_return_service.py:113` 对抵扣行退货写 `退货` +qty 库存流水，
而结余公式（`get_inventory_balance` / CTE）**含 `退货`、不含 `订单抵扣`** → 抵扣从没从结余扣过，
退货却往结余加 → **结余虚增 = 退货量**。

本测试的期望值公式与应用的结余公式**逐字同构（镜像口径）** → **永远测不出**这个偏差。
这是**应用侧口径问题**，需 owner 裁定：
- UI 只允许退「独立出货」（`search_returnable_stockouts` 明确 `stockin_id IS NULL`）；
- 但 **API（`POST /stock-returns/create`）不拦抵扣行退货**，两者不一致。
