# 采购中心：去掉「待审核」，改为自动生成采购订单

- 日期：2026-10-10
- 状态：待用户复核
- 相关页面：`/purchase`（PC + 移动端）

## 背景

采购中心 `/purchase` 现有三个 tab：

1. **待审核订单** —— 客户订单（`Order.status='待备货'`）与备货记录（`StockIn`）中**尚未被采购单关联**的单。
2. **待生产订单** —— `PurchaseOrder.status='pending'`。
3. **记录查询** —— `PurchaseOrder.status='completed'`。

当前流转：客户订单/备货创建 → 进「待审核订单」→ 人工勾选点「一键审核订单」→ 端点
`POST /orders/one-click-generate` → 服务 `generate_purchase_orders_from_customer_orders`
按 BOM 生成采购单，并把客户订单状态由「待备货」改为「已备货」→ 生成的采购单进「待生产订单」。

## 目标

去掉「人工审核」这一步。订单/备货创建后**自动**生成采购单，直接进入「待生产订单」。
**生成算法与其它业务规则一律不变。**

## 行为（改前 → 改后）

| 项 | 改前 | 改后 |
|---|---|---|
| 客户订单/备货创建 | 进「待审核订单」，等人工审核 | 后台自动生成采购单，进「待生产订单」 |
| 人工动作 | 勾选 → 点「一键审核订单」 | 无 |
| 生成逻辑 | BOM → 物料 → 按客户分组落单 | **同一函数，一行不改** |
| 缺 BOM（任一 SKU 未配 BOM） | 审核时提示「未配置BOM表」，无法通过 | 不生成，采购页标「未配置BOM，无法下单」；BOM 配好后自动补生成 |
| 去重 / 幂等（`uq_po_pending_dedup` + savepoint） | 不变 | 不变 |
| 订单状态流转（待备货 → 已备货） | 审核时写入 | 自动生成时写入（同一处） |

## 机制

与改造前「一键审核」同形态 —— **在请求内同步生成，不引入后台队列**：

1. **提交后就地生成**：订单/备货创建、**BOM 保存**的事务提交成功后，由
   `db_transaction` / `get_async_db` 的 post-commit 回调**当场**跑一次自动生成
   （开独立会话，复用同一生成函数）。下单/保存响应不被生成失败连累（失败只记日志）。
2. **BOM 保存钩子**：覆盖「先缺 BOM、配好后生成」——保存 BOM 提交后同样触发一次扫描。
3. 生成核心 `generate_purchase_orders_from_customer_orders`（`fastapi_app/services/purchase_order_generate.py`）
   **不修改**。

### 为什么不用 ARQ

曾试过「创建后投递 ARQ 扫描任务 + 5 分钟 cron 兜底」。缺陷：ARQ worker 在本机**常年不跑**
（GUI 开发栈托管 `:5002/:3000`，不管 ARQ），任务投出去无人消费，页面永远停在「生成中…」。
而改造前的「一键审核」本就是请求内同步生成、零后台依赖。故回到同形态：
**没有 worker 也不影响功能**。

## 前端

- `/purchase`（PC + 移动端）：删除「待审核订单」tab、待审核面板、「一键审核订单」按钮；默认进入「待生产订单」。
- 「待生产订单」tab 内**同一张表**并列展示两类行（同列、**无颜色区分**）：
  - **待生成行**：尚未生成采购单的客户订单/备货记录（不可勾选）；操作列显示
    「未配置BOM，无法下单」（有 BOM 的短暂显示「生成中…」）。
  - **待生产行**：已生成的采购单（可勾选，支持汇总下单 / 批量确认）；操作列为「下单完成」。
  - BOM 配好后自动生成，对应行自然由「待生成」变为「待生产」。
- 移动端 `MPurchaseView.vue`：「待审核」tab 改名「待生成」并只读展示，去掉一键审核按钮。

## 非目标

- 不改生成算法、BOM 校验规则、订单状态机、去重/幂等。
- 不删现有 `POST /orders/one-click-generate` 端点与 `generate_purchase_orders_from_customer_orders`
  （保留兼容，避免破坏其它引用与测试）。

## 验证（验收标准）

1. 有 BOM 的客户订单创建后**自动**生成采购单，进「待生产订单」；步骤无人工审核。
2. 无 BOM 的订单：不生成，采购页标「未配置BOM，无法下单」；补上 BOM 后自动补生成。
3. 已被采购单关联的订单：不重复生成（幂等）。
4. 前端：无「待审核订单」tab 与「一键审核」按钮；默认 tab 为「待生产订单」。
5. 后端相关回归测试 + 新增测试通过；`python scripts/quality_gate.py` 通过。
