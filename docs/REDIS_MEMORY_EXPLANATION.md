```
❌ 错误理解: Redis启动就会占用2GB内存
✅ 正确理解: Redis最多可以使用2GB内存，实际使用取决于数据量
```

### 3. 内存限制的工作原理

#### 3.1 动态分配机制

```
Redis内存使用流程:

启动时
  ↓
占用少量内存 (约0.5-1MB)
  ↓
存储数据时
  ↓
按需分配内存
  ↓
达到maxmemory限制
  ↓
触发淘汰策略 (allkeys-lru)
```

#### 3.2 内存分配示例

```python
# 存储1个key-value
r.set('key1', 'value1')  # 约占用100字节

# 存储100万个key-value
for i in range(1000000):
    r.set(f'key_{i}', f'value_{i}')
# 约占用100MB内存

# 存储2000万个key-value
# 约占用2GB内存（达到限制）
# 触发LRU淘汰策略
```

### 4. 内存限制的作用

**maxmemory 2gb** 的实际作用:

```
✅ 防止Redis占用过多内存
✅ 保护系统不会因Redis而内存不足
✅ 当达到2GB时自动淘汰旧数据
✅ 确保Redis稳定运行
```

---

### 5. 淘汰策略详解

**当前配置**: `maxmemory-policy allkeys-lru`

```
LRU (Least Recently Used) 算法:

当内存使用达到2GB时:
  ↓
自动删除最久未使用的数据
  ↓
为新数据腾出空间
  ↓
保持内存使用在2GB以内
```

**示例场景**:
```
假设Redis已存储2GB数据:
- 产品信息: 500MB (最近1小时访问)
- 订单数据: 1GB (最近10分钟访问)
- 用户会话: 500MB (最近1天未访问)

当需要存储新数据时:
- LRU算法会删除"用户会话"数据
- 因为它们最久未被访问
```

### 8. 监控内存使用

#### 8.1 命令行监控

```powershell

# 关键指标:
# used_memory_human: 已用内存
# used_memory_peak_human: 内存峰值
```

#### 8.2 Python监控

```python

r = redis.Redis(
    host='localhost',

    password='ERP_Redis_2026_Secure_Password'

print(f"内存限制: {info.get('maxmemory', 'unlimited')}")
```
