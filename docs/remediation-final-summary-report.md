## 一、整改概述

### 1.1 整改背景

滨发协同系统（BinFa ERP）当前运行在 Flask + FastAPI 双框架架构下，存在以下核心问题：
- 无容器化部署，环境不一致
- asyncmy 驱动停止维护，存在安全漏洞
- Celery 任务队列与 FastAPI 异步生态不匹配
- MySQL 性能受限，JSON 操作效率低
- Jinja2 + 原生 JS 前端无构建系统，零组件化
- Flask 遗留代码冗余，维护成本高

### 1.2 整改范围

| 阶段 | 整改项 | 周期 |
|------|--------|------|
| 阶段一 | 容器化建设 | 第 1-2 周 |
| 阶段一 | 依赖升级 | 第 1-2 周 |
| 阶段一 | 高可用架构 | 第 1-4 周 |
| 阶段二 | PostgreSQL 迁移 | 第 5-8 周 |
| 阶段三 | 前端重写 | 第 9-16 周 |
| 阶段四 | Flask 下线 + 安全加固 | 第 17-18 周 |
