# ERP 系统 - 其他服务器安装部署说明

> 适用：在**任意一台新的 Windows 服务器**上从零安装并部署本 ERP 系统。
> 部署方式：Windows + Python + PostgreSQL + Redis + Vue + FastAPI + Nginx + NSSM。
> 本文档为一份自包含的安装手册，可按章节顺序逐步完成。

---

## 1. 系统架构与组件清单

| 组件 | 版本/说明 | 安装后所在位置 |
|------|-----------|----------------|
| 后端 | FastAPI + Uvicorn（多 worker） | `start.py` / `fastapi_app/` |
| 异步任务 | ARQ worker（内建 cron） | `fastapi_app/core/arq_app.py` |
| 前端 | Vue3 + Vite（`frontend-vite/`），构建产物 `dist/` | `frontend-vite/dist/` |
| 数据库 | PostgreSQL 18，主库 `erp_system`（端口 5432，用户 `erp_app`） | 系统服务 |
| 迁移工具 | Alembic（`migrations/`） | 项目内 |
| 缓存/队列 | Redis（6379 缓存 / broker / results） | 系统服务 |
| Web 服务 | Nginx for Windows，监听 3000 | `config/nginx-windows.conf` |
| 进程守护 | NSSM 服务：`erp-prod`、`erp-arq`、`erp-redis` | `C:\nssm\nssm.exe` |

---

## 2. 前置软件安装（新服务器）

1. **Python 3.11+**（建议 3.12），安装时勾选 **Add to PATH**。
2. **Node.js 20.19+ / 22.12+**（Vite 构建要求）。
3. **PostgreSQL 18 for Windows**，安装到默认路径，端口 **5432**。
4. **Redis for Windows**，端口 **6379**。
5. **NSSM**：解压 `nssm.exe` 到 `C:\nssm\nssm.exe`（`server_manager.py` 默认探测路径）。
6. **Nginx for Windows**：解压 `nginx.exe` 到 `C:\nginx\nginx.exe`（`prod_runner.py` 默认探测路径）。
7. **Git**（用于拉取代码）。

## 3. 获取代码

从 git 仓库克隆（把仓库地址替换为实际地址）：

```bash
git clone git@github.com:qike1132/erp.git
cd erp
```

> 若仓库已包含 `.env`、`config/jwt/private.pem` 等敏感文件，则直接使用；若为空，请按下面章节生成。

## 4. 数据库结构与插件

### 4.1 建库与用户（用 psql / pgAdmin 管理员执行）

```sql
CREATE ROLE erp_app LOGIN PASSWORD '新强密码';
CREATE DATABASE erp_system OWNER erp_app;
```

### 4.2 数据库插件（必须与现有环境一致）

- **pg_trgm**（必装）：GIN 模糊搜索索引。迁移脚本会自动执行 `CREATE EXTENSION IF NOT EXISTS pg_trgm`，**迁移成功即自动就位**。
- **流复制角色**（可选，单机可跳过）：`erp_replicator`（复制）、`erp_readonly`（只读）。

验证插件：

```sql
SELECT extname FROM pg_extension WHERE extname='pg_trgm';   -- 期望返回 pg_trgm
```

### 4.3 PostgreSQL 内置审计配置

在 `postgresql.auto.conf` 中追加（与旧库一致）：

```
log_statement = 'mod'
log_connections = on
log_disconnections = on
```

### 4.4 建表（二选一）

**路线 A（推荐，最保真）：旧库 schema 导出再恢复**

在旧服务器导出结构（不含数据）：

```bash
pg_dump -U postgres -h old_host -p 5432 -d erp_system --schema-only --no-owner --no-privileges -F p > erp_schema.sql
```

拷到新服务器后恢复：

```bash
psql -U postgres -h localhost -p 5432 -d erp_system -f erp_schema.sql
```

**路线 B（替代，纯迁移）：Alembic 跑迁移建表**

```bash
pip install -r requirements/base.txt
# 确保 .env 已配置 DB 连接（见第 5 章）
alembic heads          # 确认唯一 head
alembic upgrade head   # 自动建 pg_trgm 扩展 + 全部表结构
```

## 5. 后端依赖与环境配置

### 5.1 安装 Python 依赖

```bash
pip install -r requirements/base.txt
# 如需要 OCR 导入功能（约 500MB）：
pip install -r requirements/ocr.txt
# 开发/测试（可选）：
pip install -r requirements/dev.txt -r requirements/test.txt
```

### 5.2 创建 `.env`

复制 `.env.example` 为 `.env`，按新机填写：

| 变量 | 说明 |
|------|------|
| `DB_HOST/DB_PORT/DB_USER/DB_PASSWORD/DB_NAME` | 指向新库，`DB_PASSWORD` 用强密码 |
| `SECRET_KEY` | 生成：`python -c "import secrets; print(secrets.token_hex(32))"` |
| `REDIS_HOST/REDIS_PORT/REDIS_PASSWORD` | Redis 地址与密码 |
| `REDIS_URL/REDIS_CACHE_URL/REDIS_BROKER_URL/REDIS_RESULT_URL` | 对应缓存/队列实例 |
| `ASYNC_DATABASE_REPLICA_URL` | 单机不建副本时**置空**（读操作回退主库） |
| `JWT_ALGORITHM` | RS256 |
| `JWT_PRIVATE_KEY_PATH / JWT_PUBLIC_KEY_PATH` | 指向 RSA 密钥对 |
| `ALLOWED_HOSTS` | 新服务器 IP/域名（JSON 数组格式，**禁止 `*`**） |
| `CORS_ORIGINS` | 新服务器访问地址 |
| `APP_ENV` | `production` |
| `UVICORN_WORKERS` | 视内存（默认 4） |

### 5.3 JWT RSA 密钥对

> 若仓库已包含 `config/jwt/private.pem`、`public.pem` 则直接使用；否则重新生成：

```bash
openssl genpkey -algorithm RSA -out config/jwt/private.pem -pkeyopt rsa_keygen_bits:4096
openssl rsa -pubout -in config/jwt/private.pem -out config/jwt/public.pem
```

### 5.4 Redis 独立实例

推荐将缓存/队列拆分为独立逻辑库（与 `.env` 中 `REDIS_CACHE_URL/BROKER/RESULT` 对应，通常 6379/0、/1、/2）。设置 Redis 密码为 `ERP_Redis_2026_Secure_Password`（与 `.env` 一致）。

## 7. 初始化数据（管理员 / 权限 / 导航）

新库无业务数据，需建立初始账号与权限体系：

1. **创建管理员账号**（密码可改）：

   ```python
   # 在项目根执行
   import asyncio
   from fastapi_app.core.database import _init_async_engine, _AsyncSessionLocal
   from fastapi_app.core.security import hash_password
   from sqlalchemy import text

   async def main():
       _init_async_engine()
       pw = hash_password("admin123")
       async with _AsyncSessionLocal() as s:
           await s.execute(
               text('INSERT INTO "user" (username, password, is_super, status) VALUES (:u,:p,true,true) ON CONFLICT DO NOTHING'),
               {"u": "admin", "p": pw},
           )
           await s.commit()

   asyncio.run(main())
   ```

2. **初始化权限数据**：

   ```bash
   cd scripts && python init_permissions.py
   ```

3. **补充导航与授权脚本**（按需逐项运行，幂等）：`scripts/add_*.py`，例如 `add_pattern_room_nav.py`、`add_purchase_center_nav.py`、`add_batch_nav.py`、`add_backup_nav.py`、`add_supplier_nav.py`、`add_production_plan_nav.py`、`add_outsource_nav.py`、`rename_dev_section.py` 等。运行后会自动清 nav Redis 缓存。

4. 建议运行 `python reset_admin.py` 重置 `admin` 密码为已知值（`admin123`）。

## 8. NSSM 服务 + Nginx 启动

启动顺序遵循 `prod_runner`：**后端 → ARQ → 前端**，以 `/api/health` 为就绪门。

### 8.1 NSSM 安装（两步法，避免单参错误）

```bash
# <PY> 代表 python.exe 绝对路径，<项目根> 代表项目目录
nssm install erp-prod <PY>
nssm set erp-prod AppParameters "-m fastapi_app.core.prod_runner --no-arq"
nssm set erp-prod AppDirectory <项目根>
nssm set erp-prod AppEnvironmentExtra PYTHONIOENCODING=utf-8 PYTHONUTF8=1

nssm install erp-arq <PY>
nssm set erp-arq AppParameters "-m arq fastapi_app.core.arq_app.WorkerSettings"
nssm set erp-arq AppDirectory <项目根>
nssm set erp-arq AppEnvironmentExtra PYTHONIOENCODING=utf-8 PYTHONUTF8=1

nssm install erp-redis <redis-server.exe>
nssm set erp-redis AppParameters "redis.windows.conf"
nssm set erp-redis AppDirectory <redis目录>
```

### 8.2 启动服务

```bash
nssm start erp-redis
nssm start erp-prod
nssm start erp-arq
```

### 8.3 启动 Nginx

`prod_runner` 会自动探测并拉起 `config/nginx-windows.conf`（监听 3000，反代 5002）。若未自动启动：

```bash
nginx -p <项目根> -c config/nginx-windows.conf -e logs/nginx-error.log
```

### 8.4 验证监督器环境（可选）

```bash
python -m fastapi_app.core.prod_runner --check
```

## 9. 验证

- [ ] 后端健康：`curl http://127.0.0.1:5002/api/health` → 200
- [ ] 前端：浏览器访问 `http://<新服务器IP>:3000` 能打开登录页
- [ ] 数据库插件：`SELECT extname FROM pg_extension WHERE extname='pg_trgm';` → 有返回
- [ ] Alembic：`alembic current` 与 `alembic heads` 一致（路线 B）
- [ ] 登录：`admin / admin123` 可登录，权限/导航正常
- [ ] 备份模块可手动触发一次（验证 pg_dump 路径可用）
- [ ] 异步任务：触发一次导出/报表，确认 ARQ 正常消费

## 10. 风险与回滚

| 风险 | 应对 |
|------|------|
| Alembic 迁移图分叉（多 head） | 优先用路线 A（schema-only dump）；路线 B 需先 `alembic heads` 核实 |
| 前端 `vite build` 卡死 | 用 `vite preview` 对已有 dist，或排查 Vite/Rolldown+PWA 冲突 |
| 只迁结构导致缺初始账号/权限 | 必须执行第 7 章的 admin/权限/导航初始化 |
| 端口冲突（5002/3000/5432/6379） | 释放旧进程，或改 `.env`/Nginx 端口 |
| Redis 多实例不一致 | 核对 `.env` 中 `REDIS_URL/CACHE/BROKER/RESULT` 指向 |
| 回滚 | 建库前保留旧库；失败可 `DROP DATABASE erp_system` 重建重跑 |
