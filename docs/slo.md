# 性能 SLO 与延迟预算（erp_system）

**建立日期**：2026-11-03（源自全栈测试审查 S3 / M14）
**适用范围**：本仓后端 API 的**常规响应延迟**。压测（并发/吞吐）不在本文档定标范围内，
见文末「与压测的分工」。

## 一、为什么需要这份文档

审查发现两个问题：

1. **CI 没有任何性能断言**——`docs/performance-baseline.md`（2026-09-14 直连 PG 只读探针）与
   `docs/db-index-analysis-2026-10-31.md`（生产只读诊断）两轮高质量实测的结论**没有任何测试锁定**；
   2026-10-31~11-01 删 30+ 建 9 个索引的大规模 DDL，只有 EXPLAIN 静态证明，无性能复测佐证。
2. **阈值口径散落**：三份 2026-04 压测报告自设目标（P95<3s / <5s）来源不明且与业务规模无关；
   E2E 的 20s 超时与压测目标之间没有推导关系——20s 过宽会掩盖「从 200ms 退化到 15s 仍然绿」。

本文档是**唯一阈值来源**：CI 门禁（`tests/e2e_api/test_latency_budget.py`）直接引用这里的数值，
改阈值 = 改一处。

## 二、业务前提

内网单机 ERP：nginx :3000 → uvicorn 127.0.0.1:5002，PostgreSQL 18 同机。
真实并发量级为**个位数到低双位数**，用户对「点击后多久出结果」的容忍度远高于公网系统，
但**列表类页面**是高频入口（订单/产品/库存/客户），慢 1 秒即明显影响日常操作。
因此分两档，而不是一刀切。

## 三、SLO 定义

| 档位 | 覆盖端点（示例） | 中位数（p50） | 长尾（p95） | 错误率 |
|---|---|---|---|---|
| **常规档** | `/orders/list`、`/products/list`、`/stock/inventory`、`/customers/list` | ≤ **300 ms** | ≤ **1500 ms** | 5xx 必须为 0 |
| **容忍档** | `/dashboard/stats`、`/reports/order-logs` 等聚合/报表类 | ≤ **800 ms** | ≤ **3000 ms** | 5xx 必须为 0 |

**依据**：`docs/performance-baseline.md` 实测的 DB 层查询在 0.1–0.7 ms 量级
（如 audit_log 深分页 6.5 ms），应用层合理开销后 300 ms 有充足余量；
2026-04 压测暴露过数秒级尾部（P95 4.2 s），1.5 s / 3 s 是「明显劣化」的判定线，
不是「最优目标」。

**这是宽松初值，不是终值**：先跑 3 轮取实际分布，再按 `p95 + 3σ` 收紧。
收紧前必须先有基线，否则阈值本身会变成噪音源。

## 四、CI 如何执行

`tests/e2e_api/test_latency_budget.py`，在 CI test job 既有的**隔离真实栈**上运行
（uvicorn :5502 + 真实 PG18/Redis + `erp_test` 库，`e2e-identity` 自证目标）：

```
pytest --confcutdir=tests/e2e_api tests/e2e_api/test_latency_budget.py -v
```

- 每条链路**预热 3 次**后采样 **20 次**，取 p50 / p95
- 断言只拦「档位阈值」与 5xx，不设吞吐门槛（吞吐由压测看，不进 CI）

**CI runner 与生产主机不等价**：阈值按「CI 自身基线 + 余量」定，防跨环境误报；
跨环境绝对值以手动压测（第五节）为准。若 CI runner 抖动导致偶发红，
先加采样次数或放宽到实测 p95+3σ，**不要**直接删除门禁。

## 五、与压测的分工

| 关注点 | 归属 | 入口 |
|---|---|---|
| 单请求延迟回归（p50/p95） | CI 门禁，每次 push | `tests/e2e_api/test_latency_budget.py` |
| 并发吞吐 / 阶梯负载 / 错误率 | 手动执行，需显式授权 | `tests/stress/locustfile.py`（环境变量化 + 生产守卫） |
| DB 层慢查询诊断 | 人工周期（非门禁） | `docs/performance-baseline.md`、`docs/db-index-analysis-2026-10-31.md` |

压测**不**进 CI：单次 30 分钟级、且会与本机生产服务争 CPU（本机即生产主机）。

## 六、当前未实测声明

- 本文档的中位数/p95 阈值来自 DB 层实测 + 历史报告反推，**尚未在生产等价负载下校准**；
- `latency_budget` 用例需真实隔离后端，仅 CI 执行，本地非提权环境无法复现；
- 首次跑通后应把实测分布回填到本文档，并按 `p95 + 3σ` 复核阈值。
