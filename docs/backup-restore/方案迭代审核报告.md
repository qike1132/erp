## 1. 🔴 Severe（必修，直接影响"可备份/可恢复"）

### S1 Redis 双实例遗漏 —— 队列与进度数据会丢
- **发现**：方案 §3 只列 `redis/dump.rdb` 单实例。实际存在业务实例（6379）与 **broker 实例（6380，ARQ 队列 + 结果存储 + 进度键）**。
- **影响**：恢复后业务 DB 完整但任务队列/进度键回退，异步任务（含备份任务本身）状态错乱。
- **修订（已写入 v1.1）**：备份范围改为 `redis/6379-dump.rdb` + `redis/6380-dump-broker.rdb`；恢复时两实例都还原、都自检（`PING` + `DBSIZE`）。
- **工作量**：小。

### S2 RDB 定位方式错误 —— 相对路径导致备份抄错文件
- **发现**：`dir ./` 是相对路径，方案未定义如何定位 RDB 文件。
- **影响**：备份可能复制到错误的 RDB 或空目录；恢复时写回的 `dir` 同样漂移。
- **修订（已写入 v1.1）**：备份时通过 `redis-cli -p <port> CONFIG GET dir dbfilename` 实时解析**绝对路径**并写入 manifest；恢复时按 manifest 写回配置为绝对路径。Redis 可能为 Memurai（Windows 原生兼容）——命令兼容，仅服务发现需兼容。
- **工作量**：小。

### S3 备份锁缺失 —— 一致性点被并发破坏
- **发现**：方案说"停摆窗口趋近 0、无需停服务"，但未定义与**部署发布 / 配置保存 / 一键启停**的并发互斥。
- **影响**：备份进行中用户点"部署更新"，app 目录与 DB 处于不同代际，恢复出一个"混合态"环境。
- **修订（已写入 v1.1）**：复用 OneClickAction 的 **ActionLock 模式**——备份开始时占用全局操作锁（部署/配置/服务启停均被互斥或提示排队），结束/失败释放；界面进度卡明示"已加锁，部署/配置操作暂不可用"。
- **工作量**：中。

### S4 增量链完整性校验缺失 —— 增量包无法独立恢复
- **发现**：方案含增量备份（复用 incremental），但恢复流程未定义增量链校验。
- **影响**：缺上游全量/增量的"孤儿增量"会被静默恢复出残缺环境。
- **修订（已写入 v1.1）**：manifest 增加 `parent`（上游备份点引用）+ 链式校验（沿链累加 SHA-256）；恢复前**逐链验包**，缺上游 → 阻断并提示"需重建全量备份点"。恢复界面展示所选点至最新点的完整链路。
- **工作量**：中。

## 2. 🟠 Medium（应修，影响体验/健壮性）

| # | 发现 | 修订（已写入 v1.1） |
| --- | --- | --- |
| M1 | NSSM 服务清单写死 4 项，与源码常量（erp-prod/erp-arq）不符 | 服务清单改为**从源码常量 + 注册表动态枚举**（含可选 redis/web），manifest 记录实际项；依赖检测兼容 Memurai |
| M2 | 无演练模式（dry-run），迁移前无法低成本验证包可恢复性 | 新增**演练模式**：预检 + 解包 + 校验 + 计划生成，**不落盘、不重启**；界面「恢复」旁加「演练」按钮，审计记录"恢复演练" |
| M3 | 未区分"首次迁移"与"覆盖恢复"两种模式 | 预检检测目标目录/数据库是否已存在 ERP 实例：空 → 迁移模式；已存在 → 默认**阻断**，需显式切换"覆盖模式"并在影响面弹窗红字提示 |
| M4 | 主密码轮换策略缺失（改密码后旧包无法解密） | 增加**密钥版本**（`key_version` 进 manifest）：轮换后新备份用新密钥，旧包仍可用旧密码解密；引导期提供"口令提示"字段 |
| M5 | 恢复前快照的空间与生命周期未量化 | 空间估算显式化：**所需空间 = 备份包体积 ×3**（临时解包区 + 备份区 + 恢复前快照）；快照在下次恢复成功后可清理，失败保留 |
| M6 | NSSM 服务账户跨机缺失会导致恢复失败 | 预检增加**服务账户存在性检查**：目标机无该账户 → 回退 LocalSystem 并警告（记录于恢复报告） |
| M7 | 无版本兼容矩阵与格式前向保护 | manifest 记录 `manager_version` + `erp_version` + `format_version`；恢复器**拒绝高于自身能力的 format_version**，跨大版本给出升级路径提示 |
| M8 | VSS 快照内复制大目录（frontend dist 等）可能拖垮 IO | 大目录复制采用 `robocopy /J`（无缓冲大文件模式），逐项写入 manifest 的复制耗时供性能分析 |

## 3. 🟡 Mild（打磨项）

| # | 发现 | 修订（已写入 v1.1） |
| --- | --- | --- |
| L1 | 异地副本未定义增量是否推送（易碎文件碎片） | 策略：异地副本**只推全量** + 每日最后一份增量；增量仅本机保留 |
| L2 | SSL 私钥恢复后仅提"收紧 ACL"，缺证书有效性校验 | 恢复自检增加**证书有效期/链校验**；提供"排除私钥"选项（仅证书）已在方案 |
| L3 | 审计日志源机/目标机衔接未定义 | 源机审计副本随包存放（readonly）；恢复操作写入**目标机**审计，两者通过 `source_audit` 字段关联 |
| L4 | 备份进行中管理器重启，进度显示会丢失 | 进度键 TTL 已设（默认 1h），恢复显示逻辑写明"重启后按进度键续显" |
| L5 | 恢复自检无"期望状态"基准 | manifest 记录备份时各服务状态；自检对比"期望 vs 实际"，偏差输出到恢复报告 |
