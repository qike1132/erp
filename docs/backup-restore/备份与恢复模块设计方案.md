# ERP 服务器管理器 —「备份与恢复」模块设计方案（一键迁移 / 容灾恢复）

> 版本：**v1.1**（2026-08-29 迭代审核修订，审核报告见 `方案迭代审核报告.md`）｜ 目标 GUI：v7（pywebview 混合，原型 `docs/ui-redesign/ui_prototype_v3.html`）
> **核心场景（已澄清）**：在新服务器上一键恢复整套 ERP 运行环境 —— 备份包必须是**自包含、可移植**的环境快照，而非仅数据库。
> 硬性约束：既有功能逻辑不变；本模块与 ERP Web 端既有备份子系统**复用共享，不另起炉灶**。
> **v1.1 变更摘要**：S1 双 Redis 实例入包 / S2 RDB 绝对路径解析 / S3 备份锁（ActionLock 互斥）/ S4 增量链校验；M1-M8、L1-L5 见 §13。

---

## 1. 需求澄清与设计目标

| 项 | 结论 |
| --- | --- |
| 首要场景 | 迁移：旧机备份 → 新机（同 OS 系列 Windows Server 2019 / 同架构）一键还原 |
| 次要场景 | 容灾回滚：生产环境故障 → 恢复到最近备份点 / 上一备份点 |
| 备份粒度 | 整机运行环境：应用代码 + PostgreSQL + Redis + 配置 + 环境变量 + NSSM 服务 + 第三方配置（nginx/SSL） |
| 交付形态 | 单一加密备份文件 `.envbak`，含完整清单与校验值 |
| 恢复形态 | 新机管理器内选择备份文件 → 预检 → 二次确认 → 一键还原 → 自检 → 失败可回滚 |

### 1.1 设计原则
1. **自包含**：恢复不依赖源机任何在线资源（代码/证书/配置全部进包）。
2. **可校验**：每个备份点带 SHA-256 + 环境指纹，恢复前先验包。
3. **可回滚**：恢复前自动生成"恢复前状态快照"，失败一键回退（防误操作最后防线）。
4. **可移植**：同 OS 系列 + PostgreSQL 大版本一致即可恢复；路径支持重映射表。

## 2. 现状盘点与复用清单（关键）

| 已有资产（fastapi_app） | 能力 | 本模块处置 |
| --- | --- | --- |
| `services/backup/`（orchestrator/dump/restore/restore_plan/snapshot/incremental/chunks/verify/cleanup/metrics） | 全量/增量备份编排、恢复计划、校验、清理 | **直接复用**（DB 数据层） |
| `core/backup_encryption.py` | AES-GCM 加密 | 复用，抽为共享模块供管理器调用 |
| `core/backup_progress.py` | Redis 进度键 `erp:backup_progress:*` / `erp:restore_progress:*` + TTL + 任务密码 | 复用键体系（管理器页实时进度） |
| `services/backup/schedule_service.py` + `shared_models/backup_schedule.py` | 定时计划模型 | 复用，管理器页加 CRON 配置 |
| 告警/健康/指标/策略服务 + 告警中心 | 失败告警、保留策略 | 复用，接入管理器告警中心 |
| `backups/server/*.zip.meta`（format 2.0） | 元数据格式：checksum/encrypted/type | 扩展为 **format 3.0**，向后兼容 |
| 管理器侧：NSSM 服务（erp-api/arq）、`server_manager_config.json`、端口 5002/3000/6379、`SERVICE_DEPENDS_ON` | 服务生命周期与配置 | 环境层新增：服务清单导出/注册 |
| PostgreSQL（asyncpg/psycopg3）+ Alembic | 业务库 | 环境层新增：`pg_dump -Fc` 物理逻辑导出 |

**边界划分**：ERP Web 备份子系统 = 数据库业务数据（63 表 JSON/增量）；本模块 = **整机环境**（在其之上叠加 app/conf/env/services/redis/ssl 层）。两者共用存储目录 `backups/`、进度键与加密，互不覆盖。

## 3. 备份包格式（v3.0，单一 `.envbak` 文件）

```
erp_env_v6.0.1_20260829_094200.envbak      ← ZIP（Deflate，DB 块可 STORE）
├─ manifest.json      # 格式版本 3.0、创建时间、源机指纹、各项明细+各自校验值、总 SHA-256
├─ meta.json          # 兼容 2.0 字段 + encrypted/checksum/type/env_fingerprint
├─ db/
│  ├─ pg_dump.custom  # pg_dump -Fc --no-owner --no-acl --single-transaction（结构+数据+存储过程）
│  └─ tables.json     # 复用现有 JSON 全量导出（63 表），供 Web 端/轻量恢复兼容
├─ redis/
│  ├─ 6379-dump.rdb         # 业务实例（config/redis.production.conf，dir 为相对路径 → 备份时 CONFIG GET 解析绝对路径）
│  └─ 6380-dump-broker.rdb  # ARQ 队列 broker 实例（config/redis-broker.conf）——双实例都必须入包（v1.1 S1）
├─ app/
│  ├─ fastapi_app/    # 源码（排除 __pycache__/logs/tests/虚拟环境）
│  ├─ migrations/     # Alembic 迁移脚本
│  ├─ frontend-vite/dist/  # 前端构建产物（生产仅需 dist）
│  └─ requirements-lock.txt  # pip freeze 锁定（含间接依赖）
├─ conf/
│  ├─ server_manager_config.json
│  ├─ config/         # yml/conf/ini（告警规则、redis 双实例配置、prometheus…）
│  ├─ nginx/          # 站点与 SSL 配置
│  └─ ssl/*.pem       # 证书与私钥（加密存储，恢复后权限收紧）
├─ services/nssm_services.json  # 从源码常量+注册表动态枚举（erp-prod/erp-arq，可选 redis/web；依赖匹配兼容 Memurai）——不写死（v1.1 M1）
├─ env/env_vars.json  # 白名单环境变量（ERP_*、SERVICE_DEPENDS_ON…）
└─ runtime/runtime.json  # Python/Node 版本与路径、pg 版本、缺依赖清单（不含运行时本体）
```

**manifest.json 关键字段（v1.1 新增）**：`format_version=3.0`、`created_at`、`type`（full/incremental）、`parent`（增量链上游引用，S4）、`key_version`（密钥版本，M4）、`manager_version`/`erp_version`（兼容矩阵，M7）、`redis_instances`（双实例端口+绝对 RDB 路径，S1/S2）、`nssm_services`（动态枚举清单，M1）、`expected_states`（备份时各服务状态，L5）、逐项 SHA-256 + 源机指纹 + 总 SHA-256。

**设计决策（附理由）**：
| 决策 | 理由 |
| --- | --- |
| 运行时本体不进包（Python/Node/PostgreSQL 只存清单） | 体积/许可/病毒扫描风险；恢复时"探测→缺失引导安装→再还原"，管理器 exe 自含 Python 可作为兜底 |
| `pg_dump -Fc` 为主 + JSON 导出为辅 | -Fc 保留存储过程/约束/一致性最佳且支持并行恢复；JSON 兼容既有 Web 恢复链路 |
| 单文件 ZIP + 分块 STORE | 便于拷贝/校验/加密；DB 块已压缩则 STORE 免双重压缩损耗 |
| AES-256-GCM + 主密码派生密钥（Argon2id） | 复用现有 crypto；GCM 自带完整性认证，防止篡改 |

## 4. 一致性策略

| 数据 | 方法 | 一致性保证 |
| --- | --- | --- |
| PostgreSQL | `pg_dump --single-transaction -Fc` | MVCC 单一快照点，无需停机 |
| Redis 业务实例 (6379) | `BGSAVE` 完成事件后复制 RDB | 内存快照一致 |
| Redis broker 实例 (6380) | 同上（ARQ 队列/结果/进度键） | **双实例都须纳入**（v1.1 S1）；RDB 定位用 `redis-cli -p <port> CONFIG GET dir dbfilename` 解析**绝对路径**（`dir ./` 为相对路径，v1.1 S2），Redis 可能以 Memurai 形态存在（命令兼容） |
| 应用文件 | 备份/恢复时启用 **VSS shadow copy**（借用 UrBackup 范式），对 app/conf 做一致快照 | 打开中的文件也可一致备份，**替代硬停机窗口**；恢复端无需 VSS；大目录复制用 `robocopy /J`（v1.1 M8） |
| 全链路 | manifest 记录"一致性点时间戳"+ 各服务期望状态，恢复自检时比对 | 可审计、可追溯（v1.1 L5） |

> 一致性点统一收敛：先触发 VSS 快照 → 同一时间窗内完成 pg_dump 与双 Redis RDB 复制 → 记录一致性点。**停摆窗口趋近于 0**（无需停服务；恢复时的窗口 = DB 还原时长，维护窗口执行，界面明示）。
> **备份锁（v1.1 S3）**：备份开始时复用 OneClickAction 的 ActionLock 占用全局操作锁——部署发布 / 配置保存 / 服务启停均被互斥或提示排队，结束或失败即释放；界面进度卡明示加锁状态。

## 5. 恢复流程（新服务器一键恢复）

```
选择 .envbak → 解密+验包(SHA-256/指纹) → 增量链校验（沿 parent 逐链验包，缺上游→阻断，v1.1 S4）
  → 环境预检 → 风险评估弹窗 → 管理员二次确认(密码)
  → 自动生成"恢复前状态快照"(最小包：db+conf+services)
  → 停用冲突服务 → 还原文件(路径重映射) → 还原 DB(pg_restore -Fc -c / 或 JSON 导入)
  → 还原双 Redis 实例 RDB（按 manifest 绝对路径写回）→ 注册 NSSM 服务(路径重映射)
  → 启动全部服务 → 自检(health=200 / web=200 / redis=pong / 双实例 DBSIZE / 服务 Running / 证书有效期)
  → 成功：更新 meta 与审计；失败：一键回滚到"恢复前状态快照"
```

**预检清单**（失败即阻断，逐项给原因）：OS 系列与架构、磁盘空间 **≥ 备份体积 ×3**（临时解包区+备份区+恢复前快照，v1.1 M5）、目标端口占用、PostgreSQL 版本兼容（缺失 → 引导安装）、Python/Node 运行时探测、目标目录可写、同版本冲突检测、**NSSM 服务账户存在性（缺失 → 回退 LocalSystem 并警告，v1.1 M6）**、**format_version 前向保护（拒绝高于恢复器能力的包格式，v1.1 M7）**。

**恢复双模式（v1.1 M3）**：预检检测目标机是否已存在 ERP 实例——目标目录/数据库为空 → **迁移模式**（直接还原）；已存在 → **覆盖模式需显式勾选**（默认阻断），影响面弹窗红字列出将覆盖的路径/库/服务。

**演练模式（dry-run，v1.1 M2）**：预检 + 解包 + 校验 + 恢复计划生成，**不落盘、不重启**；界面「恢复」旁提供「演练」入口，审计记录"恢复演练"，用于迁移前低成本验证包可恢复性。

**路径重映射**：恢复时 `manifest` 中源路径 → 新机路径，支持界面可编辑映射表（默认同路径，可整体平移如 `D:\erp_system` → `E:\erp_system`）。

## 7. 安全与审计

1. **加密存储**：`.envbak` 全程 AES-256-GCM；密钥由管理器主密码派生（首次使用引导设置主密码），不落盘明文。
2. **主密码轮换（v1.1 M4）**：manifest 记录 `key_version`；轮换后新备份用新密钥，旧备份仍可用旧密码解密（按 key_version 选择密钥）；引导期提供"口令提示"字段，文档化密码重置流程。
3. **访问控制**：备份文件 ACL 收紧（仅管理员账户）；管理器单实例互斥沿用。
4. **恢复二次确认**：影响面弹窗（列出将覆盖路径/服务/数据库 + 预计停摆窗口）+ 主密码确认 + 危险操作红色按钮；覆盖模式需额外显式勾选。
5. **审计日志**：所有备份/恢复/演练/删除/回滚操作写审计（操作者/时间/动作/备份点/校验值/结果），界面"操作历史"页可查、可导出；**源机审计副本随包存放（readonly），目标机审计通过 `source_audit` 字段关联（v1.1 L3）**。
6. **失败留现场**：失败时保留中间产物与现场日志，供定位；回滚快照不被清理（直到下次成功恢复）。

## 10. 风险与对策（severity 分层）

| 级别 | 风险 | 对策 |
| --- | --- | --- |
| 🔴 severe | 恢复期间业务停摆（DB 还原窗口） | 维护窗口执行；界面明示预计窗口；恢复前快照保证可回退 |
| 🔴 severe | 跨环境不兼容导致恢复失败 | 预检阻断（OS/架构/PG 版本）；同构环境为支持基线；指纹写入 manifest |
| 🟠 medium | 大数据量备份性能（全量+增量） | 增量备份（复用 incremental）+ 分块 + 并行 pg_dump；备份不阻塞业务 |
| 🟠 medium | 备份文件单点存储（本机磁盘） | **异地副本通道**（网络盘 / rclone→S3·WebDAV，3-2-1 容灾）+ 保留策略 + 校验防损坏 |
| 🟠 medium | 主密码遗忘 → 无法解密 | 引导期提示备份恢复口令；支持"口令提示"；文档化密码重置流程 |
| 🟡 mild | SSL 私钥随包分发风险 | 加密包内已加密；恢复后收紧 ACL；提供"排除私钥"选项（仅证书） |
| 🟡 mild | 整机系统盘故障（超出应用层范围） | 文档化外部可选层：Veeam Agent / UrBackup 整机镜像备份（不并入管理器） |
