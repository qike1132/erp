# ERP系统 UI 重设计方案 (UI Redesign Plan)

## 1. 现状分析 (Current UI Analysis)

通过对现有界面的审查，我们发现了以下影响用户体验和品牌一致性的视觉与交互问题：

### 1.1 配色不协调 (Color Inconsistency)
- **问题描述**：当前界面大量使用 Bootstrap 默认的色板（如标准蓝 `#0d6efd`、危险红 `#dc3545`），缺乏统一的品牌基因，使得整个系统看起来像是一个未定制的通用后台模板。
- **影响**：视觉风格生硬、缺乏亲和力，容易引起视觉疲劳。

### 1.2 布局混乱与空间利用率低 (Messy Layout & Spacing)
- **问题描述**：表单和表格之间的留白（White space）不足或分配不均匀，部分卡片（Card）内部元素过于拥挤，且在多列布局时对齐方式存在偏差。
- **影响**：信息密度过高，用户在处理复杂表单（如批量入库、出库）时容易感到压抑，信息查找效率低。

### 1.3 字体层级不清 (Unclear Typography Hierarchy)
- **问题描述**：标题（h1-h6）、正文和辅助说明文字的字号、字重对比度不明显。标签（Label）与输入框（Input）之间的视觉关联性弱。
- **影响**：用户无法在第一眼识别出页面的核心操作区和主要信息。

### 1.4 交互反馈不足 (Lack of Interaction Feedback)
- **问题描述**：按钮、卡片、表格行在鼠标悬停（Hover）、点击（Active）和聚焦（Focus）时缺乏平滑的微交互动画。加载状态（Loading）提示较为生硬。
- **影响**：用户不确定系统是否接收到了操作指令，导致可能发生重复点击等误操作。

---

## 2. 新设计目标 (New Design Goals)

为了解决上述问题，我们将基于 **Plush Cute (软萌现代风)** 规范对系统进行全面升级，目标如下：

1. **提升品牌一致性**：引入专属的色板（如 Plush Blue `#B0E0E6`），建立柔和、现代、专业的视觉基调。
2. **增强可用性**：通过增加圆角（大圆角 24px）、优化留白与投影，减轻用户的认知负担，打造无压力的工作环境。
3. **优化信息架构**：采用清晰的卡片式布局（Card-based UI）和明确的字体排版体系，使用户操作流线型化。

---

## 3. 高保真设计规范与组件说明 (High-fidelity Specs & Components)

### 3.1 核心视觉基调 (Core Visuals)
- **主色调**：Plush Blue (`#B0E0E6`) / Plush Blue Deep (`#87CEEB`)
- **背景色**：Plush Cream (`#F8F9FA`) 作为页面底色，Plush White (`#FFFFFF`) 作为内容卡片底色。
- **圆角规范**：
  - 页面主卡片 (Card)：`24px`
  - 按钮 (Button)：`14px`
  - 输入框 (Input)：`12px`
- **阴影规范**：
  - 常规卡片：`0 4px 20px rgba(176, 224, 230, 0.25)`
  - 悬停浮浮：`0 8px 25px rgba(135, 206, 235, 0.35)`

### 3.2 组件库设计 (Component Design)

#### 按钮 (Buttons)
摒弃直角或小圆角，统一采用 `14px` 圆角，增加 `padding: 12px 24px` 确保可点击区域充足。
- **Primary**：背景色 `#B0E0E6`，悬浮时 `transform: translateY(-2px)`，带柔和投影。
- **Secondary**：使用轮廓线或浅灰色背景，用于次要操作（如重置、取消）。

#### 表单 (Forms)
- 输入框默认带有 `1px solid #D4F1F4` 边框。
- Focus 状态下边框变为 `#87CEEB`，并带有一个软蓝色光晕（`box-shadow: 0 0 0 0.2rem rgba(135,206,235,0.25)`）。
- 加入内部图标前缀（如 Font Awesome 图标）增强字段识别度。

#### 数据卡片与表格 (Cards & Tables)
- 使用无边框卡片设计，依赖软投影界定边界。
- 表格头部使用浅色背景，行之间增加 Hover 高亮效果。数据状态（如出库、入库）使用带圆角的柔和色彩 Badge (`border-radius: 6px`) 标记。

## 4. 响应式断点说明 (Responsive Breakpoints)

为确保在车间手持设备、平板和桌面显示器上的一致体验，采用以下断点策略（基于 Bootstrap 5 标准，并辅以弹性布局）：

| 断点 (Breakpoint) | 屏幕宽度 | 布局调整策略 (Layout Strategy) |
| :--- | :--- | :--- |
| **XS (Mobile)** | `< 576px` | 单列布局。卡片间距缩小至 `16px`。所有按钮宽度为 `100%`。隐藏表格次要列，提供展开视图。 |
| **SM (Large Mobile)** | `≥ 576px` | 维持单列，表单输入框适度加宽，允许部分内联按钮。 |
| **MD (Tablet)** | `≥ 768px` | 两列布局。左右两侧表单和列表（如入库页面的录入和暂存区）可并排显示（`col-md-6`）。 |
| **LG (Desktop)** | `≥ 992px` | 完整的多列布局。左侧导航栏固定，右侧内容区留白增加。表格展示完整列。 |
| **XL/XXL (Large Monitor)** | `≥ 1200px` | 增加最大容器宽度限制，防止文字行长过长影响阅读体验（Max-width: 1400px）。 |

## 5. 用户测试计划 (User Testing Plan)

为验证新 UI 的有效性，制定以下结构化的用户测试方案：

### 5.1 5秒测试 (5-Second Test)
- **目标**：测试页面的信息层级和第一印象。
- **方法**：向受试者（如仓库操作员）展示新版入库页面 5 秒钟，然后关闭页面。
- **提问**：
  1. 你刚才看到的页面主要是用来做什么的？
  2. 你印象中最显眼的按钮或区域是哪里？
- **通过标准**：>90% 的用户能准确说出页面核心功能，并指出首要行动号召按钮（如“新增入库”）。

### 5.2 A/B 测试 (A/B Testing)
- **目标**：对比新旧版本的实际操作效率。
- **方法**：将用户分为两组，A组使用原版UI，B组使用新版 Plush Cute UI。
- **测试任务**：
  - 任务1：完成 5 条皮套入库记录的批量录入并提交。
  - 任务2：在库存查询页面，找到特定条码的商品，并筛选出其上个月的“出库”流水。
- **量化指标**：任务完成时间 (Time on Task) 和 错误率 (Error Rate)。

### 5.3 可用性评分标准 (Usability Scoring)
在 A/B 测试结束后，要求用户填写 **系统可用性量表 (SUS - System Usability Scale)**，包含 10 个标准化问题（1-5分制）。

#### 量化成功指标 (Success Metrics)
新版 UI 必须在以下三个维度达到明确的量化标准才能全面上线：
1. **美观度与满意度 (Aesthetics & Satisfaction)**
   - SUS 评分目标：**≥ 85 分**（原版本基准线假设为 65 分）。
2. **可访问性 (Accessibility)**
   - 色彩对比度：通过 WCAG 2.1 AA 标准（文本与背景对比度至少 4.5:1）。
   - Lighthouse 可访问性评分：**≥ 90 分**（支持键盘导航和屏幕阅读器标签）。
3. **性能 (Performance)**
   - LCP (Largest Contentful Paint) < **2.5s**。
   - CLS (Cumulative Layout Shift) < **0.1**（避免加载时卡片跳动）。
   - FID (First Input Delay) < **100ms**。
