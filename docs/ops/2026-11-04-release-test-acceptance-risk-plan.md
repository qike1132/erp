## 0. 执行摘要

本方案把上线验收拆成六条主线：版本冻结、业务功能与数据一致性、权限与安全、非功能、备份恢复、上线运维与回滚。测试设计采用场景法、状态转换、边界值、错误推测和并发对抗组合，共给出 **51 条高价值用例**（正常 16、边界 15、异常/对抗 20）。

当前不能签字的原因不是“某条测试失败”，而是存在**已经发生且尚未关闭的发布阻断项**：

1. `readiness` 持续为 503：`backups/server/.restore_in_progress.json` 仍存在，记录目标库为 `erp_system_restore_test`、失败阶段为 `rebuild_db`。该标记按 fail-closed 设计阻止业务 readiness 通过；它不能证明生产库已损坏，但也不能直接删除标记“消红”。
2. 恢复能力未被证明：最近可查的两次灾备演练（2026-11-01）均为 `overall_success=false`。恢复动作本身返回成功，但约束校验因查询 `ccu.ordinal_position` 不存在而失败，`audit_log` 行数还存在 256824→260880 的未解释差异。当前源码 `drill_validator.py:65` 仍含该查询。
3. 最新备份未加密：`erp_auto_daily_20261104_084509196.zip.meta` 显示 `encrypted=false`，与生产配置基线“备份加密应启用”不一致。备份含业务数据和配置，属于高风险暴露面。
4. 告警没有实际投递通道：`logs/watchdog.log` 从 2026-11-04 上午至 13:22 持续记录 `backend_ready=fail`，同时多次显示“告警 0 项，通道 无”。故障可见但没有被送达值班人。
5. 发布基线未冻结：当前在 `main@4049ab1e19`，工作区仍有两个其他会话产生的未跟踪交付目录。后端生产运行直接加载工作区源码，此时重启/发布无法证明“上线的是哪个版本”。

此外，目标 SHA 对应的 CI 四 job、生产数据库实际迁移版本、RTO/RPO、业务 UAT 签字均未完成。历史基线“5411 passed / 58 skipped / 0 failed”只能作为参考，不能替代本次目标版本的当场证据。

**处置原则：先恢复、再验收、后发布。** 恢复链路未闭环前，不进行部署、不扩大开放、不用“重启一下”或“删状态文件”方式绕过。

## 4. 核心端到端链路

### 链路 A：订单→采购→来料→生产→库存→出货

1. 创建客户订单，确认订单号唯一、明细与数量一致，且下单不直接增加物理库存。
2. 基于 BOM 生成采购单，验证同一来源只产生一张采购单；自动生成与手工一键生成不得重复。
3. 完成采购单生成来料登记，分批收货状态按 `pending→partial→completed` 推进，任何阶段不可超收。
4. 包装部生产日报形成可出货库存；来料收货本身不得被误当作成品入库。
5. 出库受订单余量、包装结余和批次余量共同约束，FIFO 行必须绑定订单；失败请求不得留下出库行或库存变化。
6. 退货和取消退货必须对称回补库存、退货量、订单状态和出货计划进度。

### 链路 B：订单→审批→撤销/出货

1. 普通用户编辑/删除订单只生成 pending 审批并锁单，不直接修改业务数据。
2. 另一超管审批通过后才应用变更；自审批、非超管审批、终态重复审批必须拒绝。
3. 删除审批提交阶段不得提前发布 `ORDER_DELETED`，不得提前撤销关联 pending 采购单。
4. 实际删除完成后才发布删除事件并撤销关联采购单；事件处理失败必须进入死信/可追踪路径，不得静默。

### 链路 C：库存一致性

每次库存操作同时核对：

- `product.current_stock`
- 包装部库存结余
- `stock_out.quantity / returned_quantity / order_id / stockin_id`
- `stock_return`
- `inventory_log`
- 订单派生状态
- 出货计划 `shipped_qty / remaining / status`

任何失败路径都必须满足：无新单据、库存不变、流水不变、派生状态不变。

### 链路 D：湖北订单确认

未完成采购单时确认必须 409；采购单完成并生成来料登记后确认成功；重复确认幂等 200 且 `confirmed_at` 不被二次改写。确认动作不得错误覆盖业务派生状态。

### 链路 E：权限与灾备

- 功能权限、工厂隔离、部门隔离在列表、详情、写接口、导出上一致生效；跨厂资源按契约返回 404，不泄露存在性。
- 备份任务真实消费并产出可校验包；恢复必须在独立 scratch 库完成，验证探针数据、表/约束、旧会话撤销、临时资源清理，并记录实际耗时。

### 6.1 性能阈值唯一口径

- 上线验收统一使用 `docs/slo.md`：常规档 p50≤300ms / p95≤1500ms；聚合档 p50≤800ms / p95≤3000ms；5xx=0。
- `scripts/prod_audit/audit_config.yaml` 中另有 p95=300/500ms、500 RPS 等旧阈值，**不得作为本次放行判据**。后续应删除或明确标注为历史审核器专用。
- 500 RPS 不适用于当前“内网、单机、个位数到低双位数并发”的业务前提。需要吞吐目标时，应先测真实峰值再定，不应拿历史常量当承诺。
- 性能结论必须带环境、SHA、数据量、并发、预热、样本量、p50/p95/max、5xx 与业务 4xx；不得把 DB 查询中位数写成 API 延迟。

## 9. Go / No-Go 标准

### 9.1 Go 必须同时满足

- [ ] 恢复中断标记已按受控流程清除，`/api/health/ready=200`，`restore_pending=false`；不得以删除文件代替根因处置。
- [ ] 最新备份已加密、校验通过，并在独立 scratch 库完成真实恢复；`overall_success=true`，约束/数据/清理/会话撤销全部通过。
- [ ] 告警通道至少一条实际送达，readiness、ARQ、备份、磁盘、死信告警均能触达值班人。
- [ ] 目标 SHA 已冻结，工作区洁净；CI `test/lint/frontend/build` 四 job 全绿。
- [ ] 生产库迁移版本与发布计划一致；迁移已在隔离副本演练。
- [ ] P0 用例 100% 通过且 0 skip；P1 核心链路 100% 通过；Blocker/High 清零。
- [ ] 并发/幂等测试无超卖、负库存、重复采购、重复来料、重复审批副作用；无新增未解释库存差异与死信。
- [ ] 权限矩阵无越权；CSRF/CORS、恶意上传、恢复安全闸均通过。
- [ ] 性能达到 `docs/slo.md` 门槛或经业务/技术共同批准的实测校准值；不得使用旧审核器阈值混判。
- [ ] RTO/RPO 已由业务确认，回滚树已推演并具备可读回退制品。
- [ ] 业务 UAT 签字；发布经理、DBA、运维、QA 全部签字。

### 9.2 任一即 No-Go

- `/ready` 持续失败、恢复中断标记未查清、备份不可恢复或恢复演练失败。
- 任一 P0 用例失败/跳过，或存在未关闭 Blocker/High。
- 出现越权、负库存、超卖、重复采购、订单/库存/审批数据不一致。
- 目标 SHA 的 CI 非全绿、工作区不洁净、生产库迁移状态未知。
- 告警无人接收、备份未加密且未获书面风险接受、回滚路径不可执行。
- 只用历史“全绿”或“进程 RUNNING”代替本次证据。

### 9.3 条件放行（仅限 Medium/Low）

必须同时具备：不影响数据与安全、有可验证 workaround、业务 owner 书面接受、明确修复期限与责任人。Blocker/High 不得条件放行；备份加密若选择暂时不启用，必须有安全负责人书面风险接受、访问控制与离机副本补偿措施，否则仍按 No-Go 处理。

### P1：上线后 30 天内

1. **不可变发布包**：源码、dist、依赖锁、迁移、配置版本、CI URL、SHA 一体归档；生产只消费审批包。
2. **独立预发/演练环境**：按需 Windows VM + 独立 PG，避免“测试即生产操作”。
3. **数据保护**：离机副本、WAL 归档/PITR 评估、RPO/RTO 实测；恢复安全备份改为硬门禁。
4. **可观测性**：真实 443 入口探针、`/ready`、证书、连接池、锁、Redis 认证 PING、死信、备份加密/恢复状态。
5. **日志/审计**：按合规确认保留期，关键证据离机归档；统一 `config/log_policy.json` 与文档。
6. **秘密治理**：减少命令行/注册表可见秘密，制定 JWT/Redis/TLS/上传签名/备份密钥轮换步骤。

### P2：90 天内

1. 以真实样本校准 SLO，按 `p95+3σ` 收紧；删除旧审核器重复性能阈值。
2. 完善索引与 schema 漂移只读门禁；现有性能证据不支持盲目加缓存/读写分离/keyset。
3. 测试数据工厂与清理自动化，逐步把高频人工用例转为隔离 E2E。
4. 发布复盘并更新本方案、runbook 和风险登记册。

## 12. 决策与权衡

| 决策 | 采用 | 否决 | 理由 |
|---|---|---|---|
