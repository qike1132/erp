### F-02（跨任务 / medium，归 t22 P1-6 写域）

SQL 原子守卫对 `ALLOW_NEGATIVE_STOCK` 策略**无条件生效**：策略打开时，统一入口仍会拦下扣成负数的请求并抛 `ValueError`（库存不足！当前库存: 5，需要: 10），而不是按 t14 策略放行。真实库探针证据（`%TEMP%/p13_interact_besec.py`，10/10 PASS，exit 0）：

```
I1 持锁路径 apply_stock_delta_locked: ALLOW_NEGATIVE_STOCK=true, 5-10
   -> ValueError(库存不足！当前库存: 5，需要: 10)，库中不变 (5, 0)，未抛 StockConcurrentError
I3 未持锁路径 update_stock_with_optimistic_lock: 同上 ValueError，且日志无重试（不进入重试循环）
I2 同一路径不越界 -> 正常 (2, v1)      I4 策略关闭 -> 仍 ValueError 且库中不变
I5 过期 version -> 仍抛 StockConcurrentError（并发语义未被守卫改写）
```

t22 的 docstring 自称「即使策略被 ALLOW_NEGATIVE_STOCK 打开，扣成负数也会被这条 SQL 拦下」，即**有意覆盖**；但 t14 的策略用例（`test_stock_negative_policy.py:313-320`，ALLOW_NEGATIVE_STOCK=true 期望 `current_stock == -3`）走的是替身/直写路径，未覆盖真实 SQL 守卫 ⇒ 策略口径与实现出现分叉。请 captain 裁定策略是否仍应支配统一写入口，并在 t28 中核对。
