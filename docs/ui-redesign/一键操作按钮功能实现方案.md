# ERP 服务器管理器 — 一键启动 / 重启 / 关闭 功能实现方案

> 适配对象：`server_manager.py` **v6.0.0**（三段式 UI，API=5002 / WEB=3000 / Redis=6379）
> 设计目标：三个按钮（一键启动·开发/生产、一键重启、一键关闭）**一次点击、全程自动**，含互斥切换、优雅停止、等待确认、loading 反馈与错误恢复，无需人工干预。
> 本文所有改造点均给出当前代码的精确落点与可合并代码。

---

## 1. 功能定义（按钮 × 模式行为矩阵）

| 按钮 | 目标模式 | 功能定义 | 前置条件 | 一键完成的内容 | 结果状态 |
| --- | --- | --- | --- | --- | --- |
| **一键启动** | 开发 | 启动 后端+前端+Redis 全套开发环境 | 无运行中的过渡态；若生产在运行→自动互斥切换 | 停生产 → 清端口 → 启 Redis → 启后端(等 /api/health) → 启前端(等页面就绪) | `dev_running`，Toast「开发模式已启动 · 后端:5002 前端:3000」 |
| **一键启动** | 生产 | 启动 erp-prod + erp-arq 两个 NSSM 服务 | 同上 | 停开发 → 清端口 → `nssm start` ×2 → 等 RUNNING → 健康检查 | `prod_running`，Toast「生产服务已启动」 |
| **一键重启** | 开发 | 优雅停止当前开发环境后原样恢复 | 开发模式运行中 | 停前端 → 停后端(进程树) → 停 Redis → 清端口 → 静置 0.5s → 重新走启动流程 | `dev_running`（全新 PID） |
| **一键重启** | 生产 | 先等 STOPPED 再启动（避免被 NSSM 判定崩溃） | 生产服务运行中 | `nssm stop` → 等 STOPPED → `nssm start` → 等 RUNNING | `prod_running` |
| **一键关闭** | 开发 | 优雅终止开发环境全部进程并释放端口 | 开发运行中（或任意残留） | 停前端 → 停后端 → 停 Redis → 清端口 → 残留扫描 | `none`，Toast「已停止」 |
| **一键关闭** | 生产 | 停止两个 NSSM 服务（保留服务注册） | 生产运行中 | `nssm stop` ×2 → 等 STOPPED → 清端口 | 服务已停止（仍注册开机自启） |
| **紧急停止**（兜底） | 全部 | 强杀一切相关进程（含残留） | 任意状态 | 开发进程树 + Redis + psutil 残留扫描 + 3 端口释放（现有 `stop_all`，保留） | `none` |

**设计决策**：一键按钮只表达"意图"，具体执行全部在后台线程完成；按钮即时进入 loading 并**锁定整块操作区**，防止连点/双启（防 TOCTOU）。

## 2. 全局动作状态机

### 2.1 状态定义（`self._mode` 扩展）

现 `_mode` 仅覆盖开发：`none / starting / restarting / stopping / dual_dev`。扩展为**全局动作状态**，生产也纳入：

```
none ──────────► dev_starting ──成功──► dev_running ──► dev_stopping ──► none
  ▲                    │失败                  ▲              │
  │                    ▼                      │              ▼
  │               dev_restarting ◄────────────┤         prod_running ──► prod_stopping ──► none
  │                        │                  │              ▲
  └────────────────────────┴──────────────────┴──► prod_starting ──┘
                    （dev/prod 互斥：进入任一新模式前先停另一模式）
```

- `dev_running` = `_mode=='dual_dev'` 且前后端进程存活（现有判定，保留）
- `prod_running` = 服务状态 RUNNING（由 hosting 5s 轮询推导，保留）
- **新增**：`prod_starting / prod_stopping / prod_restarting` 三个过渡态，语义与开发侧对称

### 2.2 互斥与并发规则（防冲突核心）

| 规则 | 实现 |
| --- | --- |
| 过渡态期间拒绝一切新动作 | `_mode` 属于 `(dev_starting, dev_stopping, dev_restarting, prod_starting, prod_stopping, prod_restarting)` 时，3 组按钮全部 disabled，Toast「操作进行中，请稍候」 |
| 开发↔生产互斥 | 启动任一模式前自动停另一模式（已有 `_ensure_production_stopped` / `_ensure_development_stopped`，保留） |
| 动作原子性 | 每个动作 = 一个后台 worker 线程 + `_msg_queue` 回主线程更新（沿用现有模式，杜绝 UI 卡死） |

## 3. 执行逻辑

### 3.1 一键启动（开发）— 现有链路已完整，补充 1 个修复点

执行序列（`_start_dual_worker` → `_start_dual_thread`，现成）：
1. 互斥切换：停生产（`_ensure_production_stopped`，已等待 STOPPED）
2. 清端口：`_kill_port_sync(api/web)`
3. Redis：`_start_redis()`（探测→拉起→15×0.5s 轮询）
4. 后端：`python -u -m uvicorn fastapi_app.main:app --host 0.0.0.0 --port 5002 --reload --reload-dir fastapi_app`（`executable=_PYTHON_EXE`、`PYTHONPATH=项目根`）→ 30s 轮询 `/api/health`
5. 前端：`npm run dev -- --port 3000`（cwd=frontend-vite、`BACKEND_INTERNAL_URL`）→ 60s 轮询 WEB 页面
6. 任一步失败：终止已启动进程树 → `dual_failed` → 状态复位 + 红色 Toast + 写入告警中心

**修复点（v6.0.0 缺陷）**：第 5 步前端失败时，Redis 未停止，残留占用 6379。补一行 `_stop_redis()`（见第 6 节代码）。

### 3.2 一键启动（生产）— 补 loading / 等待 RUNNING / 失败确认

执行序列（改写 `_start_services`）：
1. 前置守卫：`_mode` 过渡态 → 拒绝（现已有）
2. `btn_prod_start.set_loading(True, '启动中…')`（新增）
3. 后台线程：停开发（`_ensure_development_stopped`）→ 清端口 → `nssm start erp-prod` → `nssm start erp-arq`
4. **新增** `_wait_service_running(name)`：轮询 `sc query` 至 RUNNING（60s 超时），并探测 `/api/health` 确认业务就绪
5. 结果：成功 → loading 复位 + Toast；失败 → 标红 + 具体原因 + 告警中心（`alerts.raise_alert('prod_start_failed', ...)`）

**与开发的差异化**（表格）：

| 维度 | 开发模式 | 生产模式 |
| --- | --- | --- |
| 进程宿主 | 管理器子进程（跟随管理器退出而终止） | NSSM Windows 服务（开机自启 + 崩溃自动重启） |
| 启动命令 | uvicorn `--reload` / `npm run dev` | `python -m fastapi_app.core.prod_runner --no-arq` + `arq WorkerSettings` |
| Worker 数 | 单进程 | 多 worker（默认 4，安装时指定） |
| 就绪确认 | 前后端端口探测 | 服务 RUNNING + `/api/health` |
| 停止方式 | 进程树 taskkill | `nssm stop`（必须等 STOPPED，禁强杀被管进程） |

### 3.3 一键重启（优雅停止 → 重新启动）

**开发（改写 `_restart_dual_thread`，补 loading）**：
```
置 dev_restarting（模式徽章显示"重启中"）
→ 停前端进程树 → 停后端进程树（taskkill 含子进程，现用 _collect_process_tree）
→ 停 Redis → 清 api/web 端口 → sleep 0.5s（等端口 TIME_WAIT 收敛）
→ 复用 _start_dual_thread 全流程（Redis→后端→前端→就绪）
```
- `dev_restart_btn` 同步 loading（现未接入）

**生产（改写 `_restart_services`，替换裸 `nssm restart`）**：
```
置 prod_restarting → btn loading
→ nssm stop erp-prod → _wait_service_stopped(45s)   ← 关键：必须确认 STOPPED，
→ nssm stop erp-arq → _wait_service_stopped(45s)      否则 AppExit Default Restart 会立刻拉起，
→ 清端口 → nssm start ×2 → _wait_service_running       与目标抢占端口
→ 健康检查 → loading 复位 + Toast / 失败告警
```

### 3.4 一键关闭

**开发（改写 `_stop_dual_mode_async`，补 stopping 过渡态与 loading）**：
```
置 dev_stopping（按钮 loading「停止中…」，模式徽章同步）
→ 停前端 → 停后端（进程树）→ 停 Redis → 清 api/web 端口
→ 残留扫描（_kill_residual_async 的 psutil 分支）
→ 复位 none + 绿色 Toast「已停止 · 端口已释放」
```

**生产（改写 `_stop_services`）**：
```
置 prod_stopping → btn loading
→ nssm stop erp-prod → 等 STOPPED → nssm stop erp-arq → 等 STOPPED
→ 清端口 → 复位 + Toast（服务保留注册，可再次一键启动）
```

**紧急停止**：保留现有 `confirm_stop_all`（Modal 二次确认 + `stop_all` 全链路），作为兜底不纳入常规一键。

## 5. 错误处理矩阵

| 动作 | 失败点 | 检测方式 | 用户反馈 | 自动恢复/出路 |
| --- | --- | --- | --- | --- |
| 启动开发 | Python 缺失 | `_PYTHON_EXE` 为空 | Modal 提示安装 | — |
| 启动开发 | 前端目录缺失 | `_FRONTEND_DIR` 校验 | Modal | — |
| 启动开发 | 后端 30s 未就绪 | `/api/health` 轮询超时 | 红 Toast + 告警 | 自动杀后端进程树 |
| 启动开发 | 前端 60s 未就绪 | WEB 探测超时 | 红 Toast + 告警 | 自动杀前后端进程树 + **补停 Redis（修复点）** |
| 启动开发 | 端口被占 | `_kill_port_sync` 清理后仍占用 | 日志 WARN | 自动重试 3 轮 |
| 启动生产 | NSSM 缺失 | `_find_nssm()` 为空 | Modal 指引下载 | — |
| 启动生产 | 服务 start 后未 RUNNING | `_wait_service_running` 超时 | 红 Toast + 告警 | 提供「查看日志」入口 |
| 启动生产 | 健康检查失败 | `/api/health` 超时 | 红 Toast | 提示检查 prod_runner 日志 |
| 重启开发 | 停止阶段失败 | 进程 kill 异常 | 日志 WARN | 继续走启动（端口已清，幂等） |
| 重启生产 | `nssm stop` 超时 | `_wait_service_stopped` False | 红 Toast + 告警 | **中止后续启动**，避免双服务抢端口；提供紧急停止 |
| 关闭开发 | 进程无法终止 | kill 异常 | 日志 WARN | 交由残留扫描兜底 |
| 关闭生产 | stop 超时 | 等待 STOPPED 超时 | 红 Toast | 提示手动 `nssm stop` 或紧急停止 |
| 任意 | 后台线程异常 | worker try/except（现有） | 红 Toast + 日志 | 状态强制复位 `none` |

**通用原则**：失败必须①给出**具体原因**（端口号/PID/服务名）②提供**出路**（重试/查看日志/紧急停止）③写入**告警中心**。状态永不"卡死"——所有 worker 均带 try/except 并在失败时强制复位。

## 6. 代码改造方案（v6.0.0 精确落点）

### 6.1 新增：等待服务 RUNNING 原语（放在 `_wait_service_stopped` 旁，~L4127）

```python
def _wait_service_running(self, name, timeout=60):
    """nssm start 后轮询服务至 RUNNING，并额外探测 /api/health 确认业务就绪。"""
    deadline = time.monotonic() + timeout
    while time.monotonic() < deadline:
        state = self._svc_state(name)
        if 'RUNNING' in state:
            try:
                urllib.request.urlopen(f'http://127.0.0.1:{_PORTS.api}/api/health', timeout=2)
                return True
            except Exception:
                time.sleep(1)
                continue
        time.sleep(1)
    return False
```

```python
def _btn_loading(self, key, loading, text=''):
    """统一按钮 loading：key ∈ dev_start/dev_restart/prod_start/prod_stop/prod_restart"""
    btn_map = {
        'dev_start':     getattr(self, 'dual_dev_start_btn', None),
        'dev_restart':   getattr(self, 'dual_dev_restart_btn', None),
        'prod_start':    getattr(self.services_page, 'btn_prod_start', None),
        'prod_stop':     getattr(self.services_page, 'btn_prod_stop', None),
        'prod_restart':  getattr(self.services_page, 'btn_prod_restart', None),
    }
    btn = btn_map.get(key)
    if btn is None:
        return
    with contextlib.suppress(Exception):
        if loading:
            btn.set_loading(True, text)
        else:
            btn.set_loading(False, '')  # set_loading 内部按变体恢复原文案
```

### 6.3 改写：一键启动生产 `_start_services`（~L4389）

```python
def _start_services(self):
    if self._mode in ('starting', 'restarting', 'stopping',
                      'prod_starting', 'prod_stopping', 'prod_restarting'):
        self.log_message('已有操作进行中，请稍候', 'WARNING')
        self.toast.show('warn', '操作被拒绝', '已有操作进行中')
        return
    if self._prod_running:
        self.toast.show('warn', '生产服务已在运行', '无需重复启动')
        return
    self._mode, self._current_mode_key = 'prod_starting', 'prod'
    self._btn_loading('prod_start', True, '启动中…')
    self._update_all_ui()

    def _worker():
        try:
            if self._ensure_development_stopped():
                self._msg_queue.put(('toast', {'kind': 'info', 'title': '已自动停止开发模式', 'desc': '开发/生产互斥托管'}))
            self._release_ports()
            for name in (_SVC_API, _SVC_ARQ):
                self._msg_queue.put(('log', {'text': f'正在启动 {name}...'}))
                nssm = self._find_nssm()
                if nssm:
                    subprocess.run(['nssm', 'start', name], executable=nssm, **_cap(30))
                else:
                    subprocess.run(['sc', 'start', name], **_cap(30))
            if self._wait_service_running(_SVC_API) and self._svc_state(_SVC_ARQ) and 'RUNNING' in self._svc_state(_SVC_ARQ):
                self._msg_queue.put(('toast', {'kind': 'success', 'title': '生产服务已启动', 'desc': f'erp-prod + erp-arq · :{_PORTS.api}'}))
            else:
                self._msg_queue.put(('toast', {'kind': 'error', 'title': '生产服务启动异常', 'desc': '服务未达到 RUNNING，请查看日志'}))
                self.alerts.raise_alert('prod_start_failed', 'error', '生产服务启动失败', 'nssm start 后未确认 RUNNING')
        except Exception as e:
            self._msg_queue.put(('log', {'text': f'启动生产服务异常: {e}', 'level': 'ERROR'}))
        finally:
            self._mode = 'none'
            self._current_mode_key = ''
            self._msg_queue.put(('ui_update', {}))
            self._msg_queue.put(('hosting_refresh', {}))
            self._btn_loading('prod_start', False)
    threading.Thread(target=_worker, daemon=True).start()
```

### 6.4 改写：一键停止生产 `_stop_services`（~L4405）

```python
def _stop_services(self):
    if self._mode in ('prod_stopping', 'prod_starting', 'prod_restarting'):
        return
    self._mode, self._current_mode_key = 'prod_stopping', 'prod'
    self._btn_loading('prod_stop', True, '停止中…')
    self._update_all_ui()

    def _worker():
        ok = True
        for name in (_SVC_API, _SVC_ARQ):
            if 'STOPPED' in self._svc_state(name):
                continue
            if not self._wait_service_stopped(name, timeout=45):
                ok = False
                self._msg_queue.put(('log', {'text': f'{name} 停止超时', 'level': 'ERROR'}))
        if ok:
            self._msg_queue.put(('toast', {'kind': 'success', 'title': '生产服务已停止', 'desc': '服务保留注册，可随时一键启动'}))
        else:
            self._msg_queue.put(('toast', {'kind': 'error', 'title': '停止超时', 'desc': '可尝试紧急停止'}))
        self._mode = 'none'
        self._current_mode_key = ''
        self._msg_queue.put(('ui_update', {}))
        self._msg_queue.put(('hosting_refresh', {}))
        self._btn_loading('prod_stop', False)
    threading.Thread(target=_worker, daemon=True).start()
```

```python
def _restart_services(self):
    if not self._prod_running:
        self.toast.show('warn', '生产服务未运行', '请先启动生产服务')
        return
    self._mode, self._current_mode_key = 'prod_restarting', 'prod'
    self._btn_loading('prod_restart', True, '重启中…')
    self._update_all_ui()

    def _worker():

            for name in (_SVC_API, _SVC_ARQ):            # 优雅停：必须等 STOPPED
                nssm = self._find_nssm()
                if nssm:
                    subprocess.run(['nssm', 'stop', name], executable=nssm, **_cap(15))
                else:
                    subprocess.run(['sc', 'stop', name], **_cap(15))
                if not self._wait_service_stopped(name, timeout=45):
                    self._msg_queue.put(('toast', {'kind': 'error', 'title': '重启中止', 'desc': f'{name} 停止超时，未执行启动'}))

                nssm = self._find_nssm()
                if nssm:
                    subprocess.run(['nssm', 'start', name], executable=nssm, **_cap(30))
                else:
                    subprocess.run(['sc', 'start', name], **_cap(30))
            if self._wait_service_running(_SVC_API):
                self._msg_queue.put(('toast', {'kind': 'success', 'title': '生产服务已重启', 'desc': '健康检查通过'}))
            else:
                self._msg_queue.put(('toast', {'kind': 'error', 'title': '重启后未就绪', 'desc': '请查看 prod_runner 日志'}))
        finally:
            self._mode = 'none'
            self._current_mode_key = ''
            self._msg_queue.put(('ui_update', {}))
            self._msg_queue.put(('hosting_refresh', {}))
            self._btn_loading('prod_restart', False)
    threading.Thread(target=_worker, daemon=True).start()
```
