Core Capabilities

六项核心能力升级

每一项都对应 v6 的一个具体病灶，也都有明确的大厂实践出处。不做为了炫技而加的功能。

四层单向依赖架构

表现层 → 应用层 → 领域层 ← 适配层。领域层零 I/O、100% 可单测；适配层实现领域定义的 Protocol， 依赖倒置。用 import-linter 在 CI 拦截越层引用，防止重新腐化。

DomainApplicationAdapterPorts

症状化告警引擎

遵循 Google SRE：告「API 错误率 > 5%」而非「CPU > 80%」。仅保留 4 条症状规则， CPU/内存/磁盘降级为 P3 饱和度预警。支持分组、抑制、静默三件套，每条规则强制绑定 runbook。

SREgroup_byinhibitionsilence

三级权限 + 高危管控

堡垒机 4A 裁剪：只读 / 运维 / 管理员三角色，高危操作分 L0–L3 四级。L3 需键入操作名并填写变更原因， L2 二次确认并列出影响面。本地 PIN 提权，30 分钟滑动过期。

RBACJITL0–L3PIN

不可篡改审计流水

借鉴字节 Romaster：append-only JSONL，每条记录携带前一条的 SHA-256， 形成哈希链。任何中间篡改都能被 verify_chain 检出。保留 180 天，支持按角色/操作/结果筛选导出。

append-onlysha256trace_id

Pipeline 流程编排

腾讯蓝鲸 SOPS 模型：把开发模式启动的 5 个步骤显式建模为 Pipeline + Step， 每步有状态、耗时、可重试、可中断，UI 渲染为 Stepper。告别写在 120 行线程函数里的一坨逻辑。

PipelineStepStepper可中断

统一可观测时间轴

字节 Argos 思路：Metrics / Logs / Events 收敛到同一时间轴。告警可一键跳转到该时刻的日志与指标， 用 trace_id 串联「一次操作 → N 个子步骤 → M 条日志 → K 条告警」。

Architecture

四层单向依赖架构

依赖方向严格向下，领域层不依赖任何外部 I/O。这是让业务逻辑从 0% 可测变为 100% 可测的关键。

L4

表现层 Presentation HTML / CSS / JS

Web 页面 + pywebview Bridge。零业务逻辑，只调用 UseCase、只消费事件。

L3

应用层 Application 用例编排

usecases / pipeline / event_bus / auth。编排步骤、事务边界、权限校验、写审计。

L2

领域层 Domain 零 I/O · 100% 可测

models / state_machine / rules / ports。模式状态机、互斥规则、告警求值、权限矩阵、健康判定。

禁止 import：subprocess · psutil · tkinter · open()
L1

适配层 Adapter 实现 Ports

process_win · service_nssm · metrics_psutil · health_http · storage_json · audit_jsonl

v6 的踩坑资产（进程树清理 / NSSM 等待 / OEM 解码）全部落在此层

依赖契约由 CI 守护

用 import-linter 声明四层顺序，越层 import 直接让 CI 失败，而不是靠自觉。

规模门禁

函数 ≤ 80 行、文件 ≤ 800 行、类方法 ≤ 20 个。v6 的上帝类 96 个方法，正是没有门禁的产物。

禁止静默失败

v6 有 148 处静默吞错。v8 全面禁绝 except Exception: pass， 统一返回含 ok / reason / detail 的显式结果对象。

导入冒烟检查

CI 增加逐模块 import 冒烟。v6 的 server_manager_console.py 导入不存在符号、 整文件是死代码却无人发现，根源就是没有这道检查。
