# 6.0 大包 UI 与 ui_prototype_v2.html 差异审计报告

> 审计对象：`dist/ERP服务器管理器_v6.0.0.exe`（源码 `server_manager.py` v6.0.0，亮色主题）
> 对比基准：`docs/ui-redesign/ui_prototype_v2.html`（高保真设计稿，Ant/Arco/TDesign 风格）
> 方法：源码逐类解析（SideNav/TopBar/StatusBar/6 页面/组件）+ 原型 CSS/JS 逐项比对；截图 `_ui_light_check.png` 供人工核验
> 结论先行：**两版整体同构（三段式框架/亮色 Token/组件体系均已对齐），差异集中在 1 项功能缺失 + 若干视觉细节**。

## 2. 差异清单（按严重程度分级）

### 🔴 严重（功能缺失 / 布局错乱）

#### S1. 部署发布页 —— Stepper 与发布历史缺失
| 项 | 内容 |
| --- | --- |
| 页面 | 部署发布 |
| 原型效果 | 顶部 4 步 Stepper（校验环境→备份现状→部署更新→健康检查，完成/进行/未开始/失败四态）+ 步骤执行日志 + 发布历史表格（时间/版本/结果/耗时/操作） |
| 6.0 实际 | 仅"NSSM 服务安装"卡片（Worker 数下拉 + 安装/卸载按钮）+ 顶部 Info 横幅明确标注"四步发布流水线为 P6 独立立项，当前版本提供 NSSM 生命周期管理" |
| 差异 | **整块 Stepper + 历史表功能未实现**（占位） |
| 修正 | `server_manager.py` → `class DeployPage.build()`：按原型实现 Stepper（4 步状态组件，参考原型 `.stepper/.step` 语义）+ 步骤日志区（deploy-log）+ 发布历史表（复用 `.tbl`）。执行体可先接 `_install_services/_service_cmd`，渐进到完整流水线。工作量：中 |

### 🟠 中等（明显视觉/语义偏差）

#### M1. 运行监控统计卡 —— 信息语义不同
| 项 | 内容 |
| --- | --- |
| 页面 | 运行监控（首屏 4 卡） |
| 原型效果 | 4 卡 = **服务健康**：后端服务（运行中/PID）、Redis（端口/内存）、前端服务（运行中/PID）、全局模式（开发/生产/未运行） |
| 6.0 实际 | 4 卡 = **模式状态**：开发模式、生产服务、Redis、管理器运行时长 |
| 差异 | 卡片关注的业务对象不同（服务级 vs 模式级）；原型第 1、3 卡展示具体服务（后端/前端），6.0 只到"模式"粒度 |
| 修正 | `OverviewPage.build()` 的 `_stat_card` 调用处：第 1 卡改为后端（值=运行中/已停止+`{api}:{pid}`）、第 3 卡改前端（值=运行中/已停止+`{web}:{pid}`）、第 4 卡改全局模式徽章。Redis 卡保留。`sync_stats()` 同步补充后端/前端 PID 子行。工作量：小 |

#### M2. 服务管理双卡 —— 按钮排列与原型分行布局不同
| 项 | 内容 |
| --- | --- |
| 页面 | 服务管理（开发/生产操作卡） |
| 原型效果 | 每个模式卡内三个按钮**各占一行**：一键启动 / 一键重启 / 一键关闭（左标签+右按钮组），下方进度条+说明 |
| 6.0 实际 | 开发卡：一键启动（一行）+ 一键操作（重启/关闭 组件同排一行）+ 进度条；生产卡同构。**行数/对齐与原型不同** |
| 差异 | 按钮分组方式不同：原型 3 行每行一个动作；6.0 启动独立一行、重启/关闭合并一行 |
| 修正 | `ServicesPage._build_quick_actions` / `_build_prod_detail`：将"一键操作"行拆为"一键重启"与"一键关闭"两行（复用现有组件按钮，仅调整容器结构为每行一个动作）。工作量：小 |

#### M3. 危险色 —— 6.0 偏艳
| 项 | 内容 |
| --- | --- |
| 页面 | 全局（danger 语义） |
| 原型 | `--danger: #D54941`（克制红，tint #FDECEA） |
| 6.0 | `LIGHT['danger'] = '#F53F3F'`（Arco 亮红） |
| 差异 | 6.0 红更亮更艳，与 v2"克制"基调有偏差；danger_tint 原型 #FDECEA vs 6.0 alpha 0.12（视觉近似） |
| 修正 | `DesignTokens.LIGHT['danger']='#D54941'`；tint 若需精确可改为实体色 `#FDECEA`。工作量：一行 |

#### M4. 服务列表行操作 —— 按钮常驻 vs 原型 hover 显示
| 项 | 内容 |
| --- | --- |
| 页面 | 服务管理·服务列表（ServiceRow） |
| 原型 | 操作列按钮 **hover 行才淡入**（`opacity 0→1`，150ms），减少视觉噪音 |
| 6.0 | `ServiceRow.add_button` 按钮**常驻显示** |
| 差异 | 可发现性相同但视觉密度不同：6.0 每行 1-3 个按钮常驻 |
| 修正 | `ServiceRow.add_button` 包装：行 `<Enter>/<Leave>` 绑定操作容器显隐（opacity 切换），保留 `:focus-within` 兼容。工作量：小（注意键盘可达） |

## 4. 结论
两版 UI **整体架构与设计语言已一致**（亮色 Token、三段式、组件体系、一键操作组件均对齐），无需推翻重做。需要落地的是：
1. **1 项功能缺失**：部署发布页 Stepper/历史表（P6 立项补齐）；
2. **4 项中等偏差**：监控卡语义、双卡按钮分行、danger 色、行操作 hover；
3. **若干 Token 微调**（品牌/警告色、侧栏/顶栏尺寸、圆角、标题字号）。

按 P1 批次修正后，6.0 与原型可实现"视觉一致 + 交互同构"。

## 6. 复核中发现并已修复的问题

🔴 **Bug（已修复）—— 服务列表操作列无法点击**
`ServiceRow.actions.bind('<Leave>', grid_remove)`：Tk 中指针移入操作区的**子按钮**同样触发父级 `<Leave>`，导致操作列在鼠标移到按钮上的瞬间隐藏，按钮点不到。
修复：改为 `_schedule_hide_actions()`（120ms 延迟）+ `_maybe_hide_actions()` 用 `winfo_containing(pointer)` 判定指针是否仍在该行/操作区子树内——在则保留，离开行才隐藏。已通过启动冒烟。

💭 **Nit（已清理）**：DeployPage 残留无用 `self._history_rows = []`，已删除。

⚠️ **运维提示（非代码问题）**：多次"启动即退出且无日志"实为**单实例互斥**——残留的 `ERP服务器管理器_v6.0.0.exe` 进程持有互斥体，新实例被 `_ensure_single_instance` 拒绝。验证时需先清理旧实例（`Stop-Process` 对应进程）。
