# 通用「一键重启 / 一键关闭」按钮组件 — 设计说明

> 实现文件：`one_click_action_component.py`（可直接并入 `server_manager.py` v6.0.0）
> 需求：开发/生产模式共用同一套重启、关闭操作入口，零重复代码，且具备确认 / loading / 结果反馈 / 并发防护 / 幂等。

---

## 1. 核心思路：差异收敛到配置，逻辑沉淀在控制器

两模式的『重启/关闭』交互 90% 相同，只有 4 处不同：

| 差异点 | 开发模式 | 生产模式 | 收敛位置 |
| --- | --- | --- | --- |
| 运行态判定 | `app._mode == 'dual_dev'` | `app._prod_running` | `ModeActionSpec.running` |
| 重启执行体 | 杀进程树 → 清端口 → 重跑 uvicorn/npm | `nssm stop`(等STOPPED) → `nssm start`(等RUNNING) | `ModeActionSpec.do_restart` |
| 关闭执行体 | 进程树 + Redis + 端口 | `nssm stop` ×2（保留注册） | `ModeActionSpec.do_stop` |
| 确认策略 | 关闭低风险可跳过确认 | 生产关闭必二次确认 | `ModeActionSpec.confirm_*` |

**结论：这 4 处全部收进一个 `ModeActionSpec`，组件本身零修改。** 新增"测试模式"只需再写一个 spec。

## 2. 架构分层（依赖方向）

```
OneClickButtonGroup        Tkinter UI：确认弹窗 → 触发 → loading → 复位
        │ 调用
        ▼
OneClickActionController   状态校验 → 原子占用锁 → 后台线程执行 → 结果收口
        │ 调用
        ├── ActionLock      全局在途锁（线程安全，防重复/跨模式冲突）
        └── ModeActionSpec  模式差异配置（running + do_restart + do_stop + confirm_*）
                 │
                 ▼
          执行体（调用方注入，后台线程内同步执行）
```

## 3. 幂等与并发规则（已通过 5 项单测）

| 规则 | 机制 | 测试 |
| --- | --- | --- |
| 非运行态调用重启/关闭 → 拒绝，且不产生副作用 | `controller.can_*` 前置校验 | T1 ✓ |
| 在途期间重复触发 → 拒绝 | `ActionLock.acquire` 原子占用 | T2 ✓ |
| 开发/生产跨模式互斥（共享同一把锁） | 全局唯一 `ActionLock` 实例 | T3 ✓ |
| 执行体异常 → 失败回调 + 锁释放 + 状态复位（永不卡死） | `_run_task` try/except 兜底 + `finally` 收口 | T4 ✓ |
| 成功 → 成功回调 + 锁释放 + 按钮复位 | `_finish` 统一收口 | T5 ✓ |

## 4. 接入三步（详见文件内「接入示例」）

1. **定义两个 spec**：把上表 4 个差异点写进 `ModeActionSpec(dev_spec / prod_spec)`；
2. **共享一把锁**：`self._action_lock = ActionLock()`（开发/生产互斥的根源）；
3. **实例化组件**：`OneClickButtonGroup(panel, OneClickActionController(app, spec, lock, on_success=..., on_failure=...))`
   —— 同一组件类实例化两次，仅 spec 不同。
   另在宿主 `_update_all_ui()` 中追加 `group.sync()` 保持按钮可用性最新。

## 5. 反馈闭环

- **确认**：`confirm_restart/confirm_stop` 按模式配置（生产关闭默认必确认，并展示影响范围描述）；
- **loading**：`busy_kind` 驱动按钮 `set_loading(True, '开发模式·重启中…')` 并禁用双钮；
- **结果**：成功 → 绿色 Toast；失败 → 红色 Toast + 告警中心 `raise_alert` + 日志；锁与按钮必然复位。

## 6. 扩展指南

| 需求 | 做法 |
| --- | --- |
| 新增"测试模式" | 新增 `ModeActionSpec(key='test', ..., running=..., do_restart=..., do_stop=...)` + 一个 `OneClickButtonGroup` 实例，不动组件代码 |
| 执行体改为异步进度上报 | `do_restart` 内部向 `app._msg_queue` 发进度消息，UI 侧已通过 `_on_busy_change` 钩子刷新 |
| UI 换成 Web 前端 | 逻辑层（Lock/Controller/Spec）原样复用，仅替换 ButtonGroup |

## 7. 与既有代码的关系

- `ActionLock` 替代了散落在各 `_start/_stop/_restart` 中的零散 `if self._mode in (...)` 守卫，收敛为统一入口；
- 现有 `restart_dual_dev / _restart_services / _stop_services` 的执行体作为 `do_restart / do_stop` 被注入（去掉各自的线程包装，线程由 controller 统一管理）；
- 与《一键操作按钮功能实现方案.md》互补：方案文档定义"三个按钮 × 两模式"的行为，本文档提供"重启/关闭"的**可复用组件实现**。
