# ERP 服务器管理器 v7.0 — UI 设计方案（pywebview 混合架构）

> 版本：v7.0 设计方案（对应原型 `ui_prototype_v3.html`）
> 架构决策：UI 层由 Tkinter 迁移为 **HTML/CSS/JS（pywebview + Edge WebView2 装壳）**，业务层（进程管理/NSSM/日志队列/托盘/单实例/配置持久化）**全部保留**，经 JS↔Python 桥薄封装调用。
> 设计基准：v6.0 已过审的 Token 体系 + Ant Design / Arco / TDesign 桌面端规范；默认亮色，暗色一键切换。
> 硬性约束：业务逻辑与流程不变；端口从配置读取（API 5002 / WEB 3000 / Redis 6379），UI 不硬编码（原型中集中为演示常量）。

## 1. 统一视觉规范

### 1.1 配色方案（Design Token）

| 紫弱底 | `--purple-tint` | `#F5EEFB` | 紫 Tag 底 |

**暗色（一键切换，同一套语义）**：`--bg #0F1115`、`--bg-card #16191E`、`--bg-hover #1D2229`、`--border-1 #262B33`、`--border-2 #3A404B`、`--text-1 #E8EAED`、`--text-2 #A9AEB8`、`--text-3 #6B7080`、`--brand #4080FF`、`--brand-tint #16233B`、`--success #23C343`、`--warning #FF9A2E`、`--danger #E0564D`、`--info #2BD1CB`、`--purple #9A6BE0`；弱底色统一用对应深色实体 hex（不做 rgba 叠加，避免与 Tk 历史同款渲染问题）。

**色彩使用纪律**（沿用大厂规范）：
1. 颜色永不单独传达信息——一律配合图标/文字/状态点（Apple HIG）。
2. 每屏主色面积 ≤ 10%；成功/警告/危险只用于语义状态，不做装饰。
3. 涨跌/健康语义：绿=正常、红=异常/停止，不引入其他隐喻色。

### 1.2 字体层级

| 层级 | 字号/字重 | 字体 | 用途 |
| --- | --- | --- | --- |
| 页面标题 | 18px / 600 | 界面字体 | 每页唯一 H1 |
| 卡片标题 | 14px / 600 | 界面字体 | 卡片头部 |
| 正文/控件 | 13~14px / 400 | 界面字体 | 表格、表单、按钮 |
| 辅助说明 | 12px / 400 | 界面字体 | 副标题、时间戳、占位 |
| 数据大值 | 22px / 500 | 等宽字体 | 统计卡数值（tabular-nums，避免跳动） |
| 日志/代码/端口 | 12px | 等宽字体 | 日志行、路径、PID、端口 |

- 界面字体链：`"Microsoft YaHei UI", "Microsoft YaHei", "PingFang SC", sans-serif`（目标机 Windows Server 2019 可靠项）。
- 等宽字体链：`"Cascadia Mono", Consolas, "Microsoft YaHei Mono", monospace`（WebView2 中逐字形回落由浏览器处理，中文不会变方块——这是相对 Tk 的直接收益）。
- 行高：正文 1.5，标题 1.4，日志行 1.6。数字一律 `font-variant-numeric: tabular-nums`。

### 1.3 间距体系（8pt 栅格，4 为半步）

| Token | 值 | 用途 |
| --- | --- | --- |
| `sp-1` | 4px | 图标与文字贴身间距 |
| `sp-2` | 8px | 控件组内间距、Tag 内边距 |
| `sp-3` | 12px | 卡片内分组间距、表格单元上下边距 |
| `sp-4` | 16px | 卡片内边距、页面区块间距 |
| `sp-5` | 20px | 卡片标准内边距（宽卡 24px） |
| `sp-6` | 24px | 页面左右留白、卡片间主力间距 |
| `sp-8` | 32px | 页面区块间大间距 |

### 1.4 圆角与阴影规则

| 对象 | 圆角 | 阴影 |
| --- | --- | --- |
| 小控件（Tag/状态点/开关） | 4px | 无 |
| 按钮/输入框/下拉 | 6px | 无（靠边框+底色） |
| 卡片/面板 | 8px | 无（亮色靠 `--border-1`；暗色同） |
| 弹窗/下拉菜单/Toast | 12px | `0 8px 24px rgba(15,17,21,.12)`（亮）/`rgba(0,0,0,.4)`（暗） |

规则：**层级靠底色深浅 + 1px 边框表达，阴影只给浮层**。延续 v6.0"极轻阴影"的克制基调，无渐变、无高光、无玻璃拟态。

## 2. 布局优化

### 2.1 整体布局结构（三段式，v6.0 已验证，保持）

```
┌────────────────────────────────────────────────────────────────┐
│ TopBar 52px：[☰] ERP服务器管理器 │ 模式徽章 API/WEB/Redis 端口胶囊 │ 主题 ⚙ │
├──────────┬─────────────────────────────────────────────────────┤
│ SideNav  │  主内容区（一屏一模块，页内纵向分层）                   │
│ 208px    │  PageHead（H1+说明+页级操作）→ 区块1 → 区块2 → …       │
│ 可折叠52px│                                                     │
│          ├─────────────────────────────────────────────────────┤
│ 6 项导航  │ StatusBar 30px：模式·状态消息 │ 告警数 · [紧急停止]    │
└──────────┴─────────────────────────────────────────────────────┘
```

导航顺序（按使用频率）：**运行监控 → 服务管理 → 日志中心 → 配置管理 → 部署发布 → 告警中心**（告警项带计数徽章）。

### 2.2 信息层级原则

1. **全局状态收敛在 TopBar/StatusBar**：运行模式、端口、Redis 指示灯全局唯一表达；页内只表达局部状态（消除 v5.33 时代的重复徽章问题）。
2. **一屏一焦点**：每页只有 1 个主操作区（服务管理页=一键操作组；部署页=流水线），其余为支撑信息。
3. **数据优先**：统计卡只放"服务健康"四卡（后端/Redis/前端/全局模式，v6.0 M1 修正后的语义）；性能图表独立分区，不与操作混排。

## 3. 组件美化（原型完整呈现）

| 组件 | 规范要点 | 原型呈现位置 |
| --- | --- | --- |
| 按钮 | 6 变体：primary / default / subtle / danger / danger-subtle / ghost；32px 高（sm 28px）；hover 150ms、按压 -0.5px 视觉、loading 内嵌 spinner 并禁点 | 各页头部/卡片 |
| 一键操作组（OneClickButtonGroup） | 开发/生产双卡同构；每卡三行（启动/重启/关闭各占一行，左标签右按钮）；共享 ActionLock：任一卡在途则全组禁用并显示在途徽章；进度条 + 阶段文案；失败转错误态可重试 | 服务管理页 |
| 表格 | 13px 行高 44px；表头 12px 辅助色；行 hover `--bg-hover`；操作列 hover 淡入（120ms 延迟防抖，指针离开行才隐藏）；数字列等宽字体右对齐 | 服务列表/进程快照/发布历史 |
| 表单 | 输入框 32px 高、6px 圆角；聚焦 `--brand` 边框 + 2px `--brand-tint` 外圈；错误态 `--danger` 边框 + 下方 12px 错误文案；标签 12px 在上 | 配置管理页 |
| 弹窗 | 420px 宽、12px 圆角、遮罩 `rgba(15,17,21,.45)`；危险操作红色标题 + 影响清单；ESC/遮罩可关 | 通用确认/紧急停止 |
| 状态栏 | 30px；左侧模式徽章（色点+文案）+ 最近消息；右侧告警计数 + 紧急停止 | 全局 |
| 提示信息 | Toast 右上堆叠（宽 332px）：图标+标题+描述+关闭，3.2s 自动消失；四语义色；最多 4 条 | 全局 |
| 状态徽章 | 6px 色点 + 12px 文字；运行中绿点带脉冲（可关）；停止灰；重启橙脉冲；错误红 | TopBar/表格/状态栏 |
| Stepper | 4 步横向：完成（绿勾）/进行中（品牌色脉冲）/未开始（灰）/失败（红叹号）；连接线随状态着色 | 部署发布页 |
| 空状态 | 40px 线性图标 + 主文案 + 辅助文案 +（可选）操作按钮 | 告警为空等 |
| 指标条 | 标签+百分数+进度条（4px 圆角）；≥80% 转警告色、≥95% 转危险色 | 运行监控页 |
| 趋势图 | SVG 折线 + 渐弱填充（仅图内，面积 ≤ 卡片 30%，属数据编码非装饰）；Segmented 切换指标 | 运行监控页 |

图标体系：统一 1.5px 描边线性 SVG（16/20 两档），手绘内联，无第三方依赖——pywebview 离线环境零外链。

## 4. 交互反馈（状态矩阵）

| 状态 | 表现 | 应用 |
| --- | --- | --- |
| 悬停 | 底色 `--bg-hover` / 主按钮 `--brand-hover`，150ms ease-out | 全部可点元素 |
| 按压 | 主按钮 `--brand-active`；默认按钮底色再深一档 | 全部按钮 |
| 聚焦 | 键盘焦点 2px `--brand-tint` 外圈（可访问性） | 输入框/按钮/菜单项 |
| 加载 | 按钮 loading 态：图标转 120°/s + 文案不变 + 禁点；全局在途时状态栏显示阶段消息 | 一键操作/发布流水线 |
| 禁用 | 45% 透明 + `not-allowed` 光标 + hover 显示原因 Tooltip（"运行中不可重复启动"） | 幂等拒绝场景 |
| 错误 | 表单：红框+错误文案；操作：Toast(error) + 日志中心写入 + 状态栏转错误消息；一键操作失败卡内转错误态并提供重试 | 全部 |
| 成功 | Toast(success) + 状态栏消息 + 相关卡片状态联动 | 全部 |
| 危险确认 | 二次确认弹窗，按钮红色，明确列出影响范围与"不可撤销" | 关闭/紧急停止/卸载服务 |
| 模式互斥 | 开发运行中点"启动生产"→ 警告 Toast + 互斥提示（不静默切换） | 双卡组件 |

**响应式验证**（见 §6）：原型内置视口模拟器（1440/1280/1080/900 四档）直接切换验证。

## 5. 响应式策略

| 视口宽 | 行为 |
| --- | --- |
| ≥1440 | 舒适态：四卡一行、监控 2:1 分栏、表格全列 |
| 1200~1439 | 四卡一行收窄、分栏保持 |
| 1080~1199 | 监控分栏改上下堆叠；表格隐藏次要列（环境列） |
| <1080 | 侧导航**自动折叠**为图标态（52px），用户可再展开；四卡改 2×2 |

原型中通过"视口模拟器"容器宽度切换演示；实际运行时由窗口 resize 驱动（pywebview 最小窗口 960×640，低于 1080 自动折叠导航，与上表一致）。

## 6. 组件 ↔ 业务逻辑映射（P3 接线清单，逻辑零改动）

| UI 元素 | 业务层（保留） |
| --- | --- |
| 一键启动/重启/关闭（双卡） | `OneClickActionController` + `ActionLock`（one_click_action.py，幂等/互斥/并发语义不变） |
| 服务列表行 | 端口探测 + PID 查询（现有 `_probe_*` 逻辑） |
| 监控图表/进程表 | psutil 采样（现有后台线程 + 队列） |
| 日志中心 | 队列化日志（主线程零阻塞，现有机制） |
| 配置管理 | `server_manager_config.json` 读写 + 校验（现有逻辑，脏标记为纯 UI） |
| 部署发布 | NSSM 安装/卸载/启停（`_install_services/_service_cmd`）；四步流水线按 P6 立项渐进 |
| 告警中心 | 操作失败/端口占用上报（现有 alert 流） |
| 紧急停止 | 现有进程树清理 + 端口释放逻辑 |
| 托盘/单实例/DPI | pywebview 下用 pystray + 现有互斥体逻辑保留 |
