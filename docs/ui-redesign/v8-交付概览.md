## 关键结论

1. **重构对象是架构与 UI，不是业务能力**。v6 的进程树管理、NSSM 托管、服务依赖探测、subprocess 安全约定是踩坑得来的资产，必须逐行迁移。
2. **核心病灶**：`ServerManagerApp` 上帝类 1669 行 / 96 方法，`tk.` 引用 478 次，业务逻辑 0% 可单测。
3. **技术路线**：延续 v7 已定的 pywebview 混合架构，业务层重写为 Domain / Application / Adapter / Presentation 四层单向依赖。
4. **能力扩展三项**：症状化告警引擎（SRE）、RBAC 三级权限 + 高危四级管控（堡垒机 4A 裁剪）、append-only 哈希链审计（字节 Romaster 裁剪）。
5. **迁移关键设计**：P4 阶段结束即可用 CLI 驱动全部业务能力，UI 风险与业务风险解耦。
