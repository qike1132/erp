### 1.1 现有实现概况

v5.33 已具备一定设计意识（"高端暗色 UI"宣称实为浅色 iOS 风格），基础盘点如下：

| 现有资产 | 说明 | 保留价值 |
| --- | --- | --- |

| `RoundedButton`（Canvas 圆角按钮） | solid / outlined / subtle 三变体 × 4 色调 | 组件思路好，重构样式 |
| `StatusBadge` | 状态徽章，支持运行/停止/重启等状态与脉冲动画 | 升级为规范 `Tag`/`StatusDot` 体系 |
| 卡片边框脉冲动画、窗口淡入、托盘、单实例 | 工程能力完整 | 全部保留 |
| 队列化日志（主线程零阻塞）、后台状态收集 | 架构良好 | 保留 |

### 1.2 视觉痛点根因

| # | 问题 | 根因 | 大厂对照 |
| --- | --- | --- | --- |
| 1 | **无导航层级，单页卡片堆叠** | 所有功能平铺在 1080×760 一屏，DEV/PROD/日志 三张卡片挤在一起 | 桌面后台普遍采用「左侧导航 + 主内容区」，一屏一主题 |
| 2 | **信息密度失衡** | 卡片式布局偏"移动端气质"，大卡片占满屏幕但承载信息少 | 管理工具应以「信息表格 + 紧凑面板」为主 |
| 3 | **状态展示重复分散** | 卡片内徽章 + 底部模式徽章重复表达同一状态 | 顶部全局状态栏统一收敛，模块内只表达局部状态 |
| 4 | **缺少性能可视化** | 无 CPU/内存/网络图表，运维价值未体现 | 监控面板是服务器管理器的"门面" |
| 5 | **交互状态不全** | 缺 loading 骨架、空状态、Toast 反馈、错误重试等 | 大厂组件库均提供完整状态矩阵 |
| 6 | **原生控件割裂** | `ttk.Scrollbar`、系统滚动条、未定制的 `tk.Text` 与自绘组件风格不统一 | 滚动条/输入框等细节需 Token 化定制 |
| 7 | **颜色硬编码** | 各处散落 hex 值，无 Token 体系，改主题成本高 | CSS Variables / Token 集中管理 |
| 8 | **高对比信息缺失** | 日志、端口、服务健康等关键信息视觉权重不足 | 明确的信息层级：标题 > 状态 > 数据 > 辅助 |

## 2. 设计目标与原则

### 2.1 目标

1. **专业感**：一眼可辨的"运维工具"气质——克制、高效、数据驱动。
2. **信息层级**：任何时刻屏幕上只有一个焦点任务（启动、监控、查日志、改配置）。
3. **零学习成本**：符合大厂用户心智（左侧菜单、顶栏状态、卡片+表格、步骤条发布）。
4. **可落地**：仅新增 psutil 一个轻量依赖（监控页采集用），基于 Tkinter 在 2~3 个迭代完成 P0~P5；部署发布页因后端能力不存在，独立立项（见 8.2）。

### 2.2 设计原则（对齐大厂规范）

- **扁平克制**：去渐变、去高光、去多余边框；用「层级背景色 + 1px 细边框 + 阴影」表达容器层级。
- **8pt 栅格**：所有间距、尺寸为 8 的倍数（4 为辅助半步），保证对齐。
- **色彩语义化**：颜色永远搭配图标/文字，不单独传达信息（Apple HIG 要求）。
- **状态可见**：任何异步操作必须有明确反馈（按钮 loading、骨架屏、Toast）。
- **深色优先、亮色可选**：运维工具暗色为主（长时间盯屏），提供亮色 Token 一键切换。

### 4.1 整体框架

```
┌──────────────────────────────────────────────────────────────────────────┐
│ 顶栏 TopBar（48px）                                                       │
│ [☰ 折叠] [ERP 服务器管理器]   [开发模式●] [API 5002] [WEB 3000] [主题] [⚙] │
├──────────┬───────────────────────────────────────────────────────────────┤
│ 左侧导航  │  主内容区 MainContent                                          │
│ SideNav   │  ┌─────────────────────────────────────────────────────────┐  │
│ (220px，  │  │ PageHeader：页面标题 / 副标题 / 右侧操作区                 │  │
│  可折叠    │  ├─────────────────────────────────────────────────────────┤  │
│  至 56px) │  │                                                         │  │
│          │  │   当前模块面板（页面级内容，按需滚动）                       │  │
│ ┌ 运行监控 │  │   · 统计卡片行 / 服务表格 / 性能图表 / 日志 / 表单 / 步骤条  │  │
│ ├ 服务管理 │  │                                                         │  │
│ ├ 日志中心 │  └─────────────────────────────────────────────────────────┘  │
│ ├ 配置管理 │                                                             │
│ ├ 部署发布 │  ┌─────────────────────────────────────────────────────────┐  │
│ ├ 告警中心 │  │ 底部状态栏 StatusBar（32px）                            │  │
│ └────────── │  │ [●运行中] 就绪 · 上次刷新 10:32:05      [紧急停止]      │  │
│  [收合 ◀]  │  └─────────────────────────────────────────────────────────┘  │
└──────────┴───────────────────────────────────────────────────────────────┘
```

**三段式要点：**

1. **左侧导航（SideNav）**：主导航唯一入口。分组：`运行监控 / 服务管理 / 日志中心 / 配置管理 / 部署发布 / 告警中心`，顶部品牌区 + 底部折叠开关。收起态仅保留图标（56px 宽），悬浮显示 Tooltip。
2. **顶部状态栏（TopBar）**：全局而非页面级。固定承载：页面标题（面包屑）、运行模式徽章（未运行/开发/生产 + 过渡态）、关键端口（API/WEB/Redis 可点击复制）、Redis 指示灯、主题切换、设置。**端口值必须从配置常量读取（`_API_PORT=5002 / _WEB_PORT=3000 / _REDIS_PORT=6379`），禁止在 UI 层硬编码**——早期版本按 8000/5173 硬编码展示是错的，实际启动命令用的就是这三个常量。
3. **主内容区**：一屏一模块，模块内再纵向分层。所有操作结果写入底部 StatusBar + 全局 Toast，不打断当前视图。

### 4.2 功能 → 模块映射（旧 → 新）

#### Tk 颜色落地注（rgba 扁平化）

Tk 颜色**不支持 alpha 通道**，上表中的 rgba Token（`--brand-tint` / `--bg-hover` / `--bg-active` 等）不能直接传给 Tk，必须按所在底色预混为不透明 hex：`mixed = fg×α + bg×(1−α)`。常用组合预算如下（暗色主题；亮色 Token 本身为不透明，无需处理）：

| rgba Token | 铺在 `--bg-page` #0F1115 | 铺在 `--bg-panel` #161A1F | 铺在 `--bg-elevated` #1E242C |
| --- | --- | --- | --- |
| `--brand-tint` rgba(47,123,255,.14) | `#132036` | `#1A283E` | `#20304A` |
| `--bg-hover` rgba(255,255,255,.06) | `#1D1F23` | `#24282C` | `#2C3139` |
| `--bg-active` rgba(255,255,255,.10) | `#27292C` | `#2D3135` | `#343A41` |

实施建议：`DesignTokens` 内提供 `tint(token, surface)` 帮助函数统一计算并缓存，组件层禁止手写 hex。

> **字体可用性（重要，实施验证修订）**：目标机器为 Windows Server 2019（build 17763）——`Segoe UI Variable` 是 Win11 专属字体、`Cascadia Mono` 随 Windows Terminal 分发，系统默认均**不存在**；且 **Segoe UI / Consolas 无中文字形**，排在回退链前面会导致全部中文显示为方块，并因逐字符字体回落拖慢文本渲染（v6.0 首版实测缺陷）。实施采用 **CJK 安全优先**链：界面 `Microsoft YaHei UI`（v5.33 同款，唯一可靠项）；等宽 `Microsoft YaHei Mono → Microsoft YaHei UI`（**永不自动选 Consolas**，等宽观感让位于中文正确性）；探测用 `_font_exists()`。

> **Tk 实施注**：Tk 无法绘制 box-shadow 与 glow。阴影 Token 仅用于 HTML 原型/亮色参考；Tkinter 实施中弹层（Toast/Drawer/Tooltip）以 `--border-strong` 1px 边框 + 不透明底替代阴影，状态点光晕以双层同心圆近似或直接省略。输入框聚焦的"外发光"同理，改为 2px 品牌色描边模拟（见 6.8）。

### 5.5 间距与栅格

- **基础单位 `--sp` = 4px**，间距取 8 的倍数：`4 / 8 / 12 / 16 / 24 / 32 / 48`。
- 面板内边距：16px；页面左右留白：24px；模块间垂直间距：16~24px。
- 栅格：内容区 12 列栅格；统计卡片行为 4 列（每列 25%），图表区按 8:4 分栏。
- 点击目标最小 32×32（桌面端），主操作按钮 ≥ 32px 高。

### 5.6 动效规范

| 场景 | 时长 | 曲线 | 说明 |
| --- | --- | --- | --- |
| hover 变色 | 150ms | ease-out | 按钮/行/Tab |
| 面板切换 | 200ms | ease-out | 透明度 0.4→1 + 8px 上移 |
| 侧边栏折叠 | 240ms | cubic-bezier(.4,0,.2,1) | 宽度过渡 |
| 状态点脉冲 | 1.6s 循环 | linear | 仅"运行中/启动中" |
| 数字滚动 | 600ms | ease-out | 监控数值变化 |
| 图表曲线 | 800ms | ease-in-out | 新数据点过渡 |

> 遵循 Apple HIG「Reduced Motion」：系统减弱动态时关闭全部动效。

### 6.2 服务器列表与连接状态

**服务列表表格（ServerTable）**——重做 DEV/PROD 卡片为统一表格：

| 列 | 内容 | 展示 |
| --- | --- | --- |
| 服务 | 图标 + 名称（FastAPI 后端 / Vite 前端 / Redis / ARQ Worker） | 名称 + Mono 副行（PID / 端口） |
| 状态 | StatusDot + 文案 | ● 运行中（绿，光晕）/ ◌ 已停止（灰）/ ⚠ 启动中（黄，脉冲）/ ✕ 故障（红） |
| 模式 | Tag | `开发` / `生产` / `独立进程` |
| 端口 | Mono 文本 | 5002 / 3000 / 6379（读自配置常量），点击复制 |
| 最近心跳 | Mono 文本 | `10:32:05`，超 15s 变红 |
| 操作 | 行内按钮组 | 启动 / 停止 / 重启 / 更多（⋯ 下拉） |

**交互**：行 hover 高亮 `--bg-hover`；状态变更时状态点先脉冲再定格；服务掉线自动插入告警并 Toast；表格支持按状态筛选（Tab 切换：全部 / 运行中 / 已停止 / 故障）。
**开发/生产互斥表达（必须）**：现有逻辑中开发与生产模式互斥（切换模式自动停止对方），统一表格会让用户误以为两侧行可并行启动。规则：一侧运行时，另一侧行内"启动/重启"按钮禁用（40% 透明）+ Tooltip「需先停止当前模式」，只读操作（查看日志/刷新）保持可用。
**原生菜单注意**：行内「更多（⋯）」下拉若用 `tk.Menu`，Windows 下是系统白色原生渲染，暗色界面中严重割裂——需自绘弹出层（Toplevel + Canvas）或接受该瑕疵并明确取舍。

### 6.3 实时性能监控面板（CPU/内存/网络）

**布局（8:4 分栏）**：
- 左栏（8 格）：「性能总览」卡片——三行指标条 + 主趋势图。
  - 每行 = 图标 + 名称 + 当前值（Display 数字）+ 迷你趋势线（120s 窗口）+ 色条进度（CPU/内存/磁盘使用率）。
  - 主趋势图 = CPU 与内存双曲线（Canvas polyline，渐变面积），X 轴时间刻度、Y 轴百分比；数据点 2s 采样一次，保留 60 点（2s × 60 = **120s 窗口**，X 轴标注 0~120s）。
- 右栏（4 格）：「网络流量」卡片——上行/下行双曲线 + 实时速率数字；「进程快照」卡片——Top 5 进程 CPU/内存排行（数据可由 `psutil` 提供）。

**视觉**：图表区底色 `--bg-input`，网格线 `--border` 半透明，曲线 2px，hover 显示十字参考线 + Tooltip（时间 + 数值）。数值更新用数字滚动动画。

### 6.4 日志查看器

**布局**：工具栏（筛选 + 搜索 + 操作）→ 日志正文 → 底部 mini 状态。
- 工具栏：级别筛选 Segmented（全部 / INFO / WARNING / ERROR，带计数）、关键字搜索框（实时过滤）、自动滚动 Switch、导出、清空。
- 正文：Mono 字体 12px，行 = `[HH:MM:SS] [级别] 消息`，ERROR 行红色 + 行 hover 高亮 + 单击行复制；空结果显示 Empty 状态（"没有匹配的日志"）。
- 性能：保留现有"队列 + 批量 flush"机制，将现有 `MAX_LOG_LINES=500 / LOG_KEEP_LINES=300` **提升至 2000 行上限** + 首行裁剪（沿用现有机制、仅调大常量）；级别筛选/关键字搜索采用「主缓冲 + 过滤视图」分离渲染，搜索输入 200ms 防抖——避免对 2000 行 `tk.Text` 全量 delete/重插造成输入卡顿。
- 级别颜色：INFO `--text-secondary`、WARNING `--warning`、ERROR `--danger`、SUCCESS `--success`。

### 6.5 配置管理页

> **前置条件（非纯视觉层）**：管理器当前**没有自己的配置持久化**——端口、Redis 路径、NSSM 候选路径等均为模块级常量（`_API_PORT` / `_REDIS_EXE_PATHS` / `_NSSM_CANDIDATES`…）。本模块实施前必须先引入配置文件（建议 JSON，随 `erp_project_path.txt` 同目录）并把上述常量重构为可配置项，属于对现有代码的侵入式改造，需单独排期（已计入 P3）。

**布局**：左侧配置分组导航（服务配置 / Redis / 端口与路径 / 日志策略 / 环境变量）→ 右侧分组表单。
- 表单控件统一：Label（Body）+ 控件（32px 高，`--bg-input` 底 + 1px `--border`）+ 说明文字（Caption `--text-muted`）。
- 密码/敏感项（如 NSSM 服务账号）：密码输入框 + 眼睛切换。
- 变更即"脏标记"：表单底部固定操作栏（重置 / 保存），保存成功 → 绿色成功态 + Toast「已保存，NSSM 服务将在下次重启后生效」。
- 端口/路径项用 Mono 字体；所有路径项带「浏览…」按钮（`filedialog`）。

### 6.6 部署/发布流程界面

> **范围告示（重要）**：部署流水线的后端能力——代码同步、构建、数据库迁移、备份/回滚、发布历史持久化——在 `server_manager.py` 中**完全不存在**（现有仅为 NSSM 安装/卸载与启停）。本节是终态交互设计，实施需按 8.2 的 P6 **独立立项**，不应挤占 UI 重构工期。

**布局**：顶部步骤条（Stepper：① 校验环境 → ② 备份现状 → ③ 部署更新 → ④ 健康检查）→ 中部当前步骤内容区 → 底部操作按钮。
- 步骤条：完成步骤 = 品牌色圆点 + 勾选；当前步骤 = 品牌色圆环 + 脉冲；未开始 = 灰点。步骤间有连接线，完成线品牌色。
- 执行中：当前步骤卡片内显示该步日志（Mono，实时追加）+ 步骤级进度（百分比）。
- 失败：当前步骤标红，按钮变为「重试当前步骤 / 回滚上一步」，回滚执行"备份还原"。
- 成功：全绿 + 成功 Banner「部署完成，健康检查通过 ✓」，提供「打开系统地址」。
- 下方发布历史表：时间 / 版本 / 结果 / 耗时 / 操作（查看日志）。

### 6.7 告警提示

| 类型 | 形态 | 使用场景 |
| --- | --- | --- |
| **Toast（右上角堆叠）** | 图标 + 标题 + 描述，3s 自动消失，可手动关闭 | 操作成功/失败反馈（启动完成、保存成功、端口占用） |

### 7.2 关键交互逻辑说明

1. **启动服务（主流程）**：点击「启动」→ 按钮进入 loading（文案"启动中…"）→ 状态栏模式 Tag 进入"启动中"（黄色脉冲）→ 对应服务行出现 Skeleton → 自动跳转日志中心并开启自动滚动 → 成功：按钮恢复、Tag 转绿、Toast「后端已启动 (PID 1234)」；失败：Tag 转红、Alert 提示失败原因、提供"查看日志"按钮。
2. **紧急停止**：状态栏常驻红色 subtle 按钮 → 点击弹确认 Modal（列出将被终止的进程树数量）→ 确认后执行现有 `_kill_residual_async` 全链路 → 完成 Toast + 日志追加。
3. **折叠侧边栏**：点击折叠钮 240ms 过渡至 56px，仅显示图标；悬停图标显示 Tooltip；折叠状态写入配置持久化。
4. **监控图表**：2s 采样（`root.after` 驱动，后台线程收集、队列回主线程，沿用现有架构；采集依赖 psutil——现有 netstat/tasklist 子进程轮询无法支撑 2s 频率，见 8.1）；采样失败不阻塞 UI，显示"数据延迟"提示；hover 图表显示数值。
5. **配置保存**：改动字段高亮"未保存"标记 → 保存时校验 → 成功绿色反馈；涉及服务重启的配置保存后提示"建议重启服务使配置生效"。
6. **日志导出**：沿用现有导出逻辑，导出成功后 Toast；大日志采用后台线程写文件避免阻塞。
7. **减动态效**：检测 Windows「在窗口中显示动画」设置（`SystemParametersInfo(SPI_GETCLIENTAREAANIMATION)`，注意参数名不是 SPI_GETCLIENTANIMATION），关闭时禁用全部动效与状态点脉冲。

### 7.3 无障碍（Apple HIG 对齐）

- 所有交互控件最小 32×32，键盘 Tab 可达。
- 状态/告警不依赖颜色：一律「色点 + 文字/图标」双通道。
- 文字对比度 ≥ 4.5:1（`--text-secondary` #9AA3AF 在 #0F1115 上 ≈ 7:1 ✓）。已知例外：`--text-muted` #6B7480 在 #161A1F 面板上约 3.9:1，**仅限 Caption/辅助标签使用，不得用于正文**；若需提升可微调至 #79828E 以上。
- 支持高对比度系统主题时自动切换亮色 Token。

## 8. 落地建议

### 8.1 技术路线选择

| 路线 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| **A. Tkinter 深度定制（推荐）** | 唯一新增依赖 psutil（监控页 2s 采样必需，netstat/tasklist 子进程轮询撑不起该频率）；现有线程/队列/托盘架构全部复用；PyInstaller 仅需在 spec 中追加 psutil（体量与已打包的 Pillow/pystray 同级） | 无现成组件库，需手写（已有 RoundedButton 经验） | ✅ 主推 |
| B. ttk + 第三方主题（sv_ttk） | 快速获得统一观感 | 仍无表格筛选/图表/步骤条；风格固定难调 | 辅助 |
| C. pywebview + 前端 Vue | 视觉上限最高、可复用 frontend-vite 设计语言 | 新增进程/依赖，打包体积增大，与现有托盘/互斥集成成本高 | 备选（长期演进） |
| D. PySide6/Qt | 组件最全 | 新增 ~200MB 依赖、打包与既有单实例/托盘改造工作量大 | 不推荐短期 |

**推荐 A**：在现有 `server_manager.py` 基础上做"视觉层替换"，现有业务逻辑（启动/停止/状态收集/日志队列/托盘）零改动，风险最小、见效最快。**注意**：零改动仅覆盖 P0~P2 的视觉/框架层；新增的监控（psutil）、配置（持久化基建）、告警（检测规则）模块需要新后端能力，部署发布另立项——均已在 8.2 计入。

### 8.2 落地步骤（分期）

> 排期基线：P0~P5 合计约 **11~12.5 天**（较初版 9~10 天上调：P0 增加 DPI/标题栏、P3 拆出部署后并入配置基建、P4 计入告警后端）；P6 部署发布另计 5~10 天。全量（P0~P6）约 16~22 天。

| 阶段 | 内容 | 预估改动量 |

### 8.3 组件组织与代码结构建议

保持单文件可维护性优先，建议按"类级"拆分（不强制拆多文件，避免 PyInstaller 路径调整）：

```
server_manager.py  (现有约 2260 行)
├── 常量区
│   ├── DesignTokens()          # 新：全部颜色/字体/圆角/间距常量（第 5 节 Token）
│   └── _PALETTE                # 改为 DesignTokens 的别名/映射，兼容现有引用
├── 基础组件区（现有 + 新增）
│   ├── RoundedButton           # 升级：支持 loading/disabled 视觉
│   ├── StatusBadge / StatusDot # 升级：统一为 Tag + 状态点体系
│   ├── NavButton               # 新：侧边栏菜单项（图标+文字+选中态）
│   ├── Segmented               # 新：分段筛选器
│   ├── ToastManager            # 新：右上角 Toast 队列
│   ├── EmptyState / Skeleton   # 新：空状态与骨架屏
│   ├── TrendChart              # 新：SVG 折线图（CPU/内存/网络）
│   └── Stepper                 # 新：发布步骤条
├── 框架区（新）
│   ├── SideNav / TopBar / PageHeader / StatusBar
│   └── PageRouter              # 基于 tkraise 的页面切换器
├── 业务逻辑区（现有，基本不动）
│   ├── 启动/停止/重启/状态收集/日志队列/托盘/单实例
└── ServerManagerApp            # 装配：框架 + 路由 + 6 个页面 Frame
```

**页面实现模式**：每个模块 = 一个 `tk.Frame` 子类（`OverviewPage` / `ServicesPage` / `LogsPage` / `ConfigPage` / `DeployPage` / `AlertsPage`），统一接口 `build()` / `refresh()` / `on_show()`。状态数据继续走现有 `_msg_queue` 回主线程，页面只消费状态、不碰 IO。

### 8.4 与 ERP 前端设计语言统一

ERP 前端（frontend-vite）若已采用 Ant Design，可将本方案的 Token（`--brand`、圆角、间距）与前端 `config/theme` 对齐，实现"桌面管理器与 Web 控制台同源同感"。

- 回归范围：单实例、托盘、窗口居中/最小尺寸、启动四步进度、生产 NSSM 安装/卸载、日志导出/清理、紧急停止、高分屏 DPI 缩放显示、暗色标题栏。
