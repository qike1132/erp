## 3. 目标架构（v8 方案核心摘要）

```
L4 Presentation  web/ (HTML/CSS/JS)  bridge.py (pywebview JS API)
              ↓  只调 UseCase / 只收 Event
L3 Application  usecases/  pipeline/  event_bus.py  auth/
              ↓  依赖 Domain 模型 + Adapter 的 Protocol
L2 Domain      models/  state_machine/  rules/  ports/    零 I/O，100% 可单测
              ↑
L1 Adapter     process_win / service_nssm / metrics_psutil / health_http / storage_json / audit_jsonl
```

**关键设计**：

1. **Domain Ports 显式结果**：所有 Port 方法返回 `OpResult / KillResult` 含 `ok / reason / detail / duration_ms`，**全面消灭 bool + 静默失败**
2. **类型化事件总线**：`@dataclass(frozen=True)` 事件替代 v6 的 12 种裸 `tuple`
3. **Pipeline 模型**：开发模式 5 步启动 = 一个 `Pipeline`，每步有 `state / duration_ms / retry / interrupt`，UI 渲染为 Stepper
4. **运行模式状态机**：`IDLE ↔ DEV ↔ PROD`，`SWITCHING` 持锁拒绝并发——把 v6 散落在 3 处的互斥逻辑内聚到一个文件
5. **症状化告警引擎**：v6 的阈值告警升级为症状规则（`health.api.consecutive_fail >= 3` for 30s）+ 分组 + 抑制 + 静默 + runbook + 推荐修复
6. **审计 append-only + 哈希链**：每条记录含 `prev_hash` 字段，校验时重算整链，可发现任何中间篡改

### A.2 告警时间窗（阿里云 + Alertmanager + 蓝鲸 三源共识）

- **触发持续周期**（`for_s`）：1 / 3 / 5 / 10 / 15 / 30 / 60 周期可选，1 周期 = 1 min
- **通道沉默周期**：5 min / 15 min / 30 min / 1 h / 3 h / 6 h / 12 h / 24 h
- **Alertmanager 收敛默认**：`group_wait=30s`（新组首次通知前等 30s，期间恢复则不发，天然去抖）、`group_interval=5m`、`repeat_interval=4h`
- **蓝鲸通知时间窗**：立即发送延迟 1s 后汇总 120s 内的同类；汇总阈值触发后延迟 60s 发汇总通知；语音告警 2 min 同组只接 1 次

### A.3 黄金四指标阈值参考（ARMS 默认）

| 维度 | 绿 | 黄 | 红 |
|---|---|---|---|
| 错误率 | < 1% | 1% ~ 5% | ≥ 5% |
| 平均耗时 | < 100 ms | 100 ~ 500 ms | ≥ 500 ms |
| 健康度（未恢复告警） | 0 | 1 | ≥ 2 |
| 饱和度（CPU/内存/磁盘取最大） | < 60% | 60% ~ 85% | ≥ 85% |

### A.5 状态机（运行模式）

```
IDLE ──start_dev──▶ DEV
IDLE ──start_prod─▶ PROD
DEV  ──switch_mode─▶ SWITCHING ──▶ PROD（先停 DEV）
PROD ──switch_mode─▶ SWITCHING ──▶ DEV（先停 PROD）
SWITCHING 持锁，拒绝并发转移
不变式：DEV ⊕ PROD = true（互斥）
```
