# ERP 服务器管理器 UI 重构 v2 — 设计决策说明

> 配套原型：`ui_prototype_v2.html`（亮色默认，右上角可切换暗色）
> 基准规范：腾讯 TDesign · 阿里 CloudDesign · Arco Design · 字节 Semi Design
> 本文档回答"为什么这么做"——每个视觉、结构、交互、动效决策背后的理由。

---

## 1. v1 → v2 复盘：AI 生成痕迹的根因

v1 被指"AI 痕迹重"，根因不是技术问题，而是**设计克制度失控**。逐条对照：

| # | v1 的问题 | 大厂后台的真实做法 | v2 的处理 | 决策理由 |
| --- | --- | --- | --- | --- |
| 1 | 一屏 6 种高饱和彩色（蓝绿黄红青紫）同时出现 | 语义色只出现在"状态表达处"（状态点/Tag/告警），装饰性元素全部中性色 | 页面主色仅品牌蓝 1 个；绿/黄/红仅在状态、Tag、告警、图表曲线出现，且全部配浅 tint 底色收敛饱和度 | 颜色是信息通道，不是装饰。颜色越多，信息层级越弱（参考 Ant Design「色彩即语义」原则） |
| 2 | 彩色图标块（30×30 各色圆角方块） | 图标统一 16px 线性、中性色（--text-2），只有选中/激活才用品牌色 | 全部删除彩色图标块，图标仅用于侧边菜单，stroke 1.5 统一 | 彩色图标块让视觉"花"，且与信息无关，是典型装饰噪音 |
| 3 | Logo 渐变、卡片 hover 上浮、状态点发光光晕 | 无渐变；hover 只做背景色 150ms 变化；状态用 6px 色点+文字 | Logo 为纯色 24px 圆角块；卡片无位移；状态点无光晕 | 大厂后台的层级靠「背景深浅 + 1px 边框」表达，不靠阴影/位移/发光 |
| 4 | 状态点脉冲动画、"启动中"用黄色闪烁 | 过渡态用 spinner + 文字（如"启动中"），不用闪烁表达 | starting/stopping 态改用 11px spinner + 文字 | 闪烁承担信息传达且制造焦虑；spinner 是用户已建立的"进行中"心智 |
| 5 | 圆角 6/8/12/16 混用、阴影 `0 12px 32px` | 组件圆角统一小体系（4/6/8/12），阴影 ≤2 级 | 圆角收敛为 4/6/8/12 四级；阴影仅 `sh-1/sh-2` 两档且极轻 | 圆角大 + 阴影重 = 消费级/移动端气质；后台工具需要"工程感" |
| 6 | 每页堆满图标按钮、彩色统计卡 | 关键操作收敛为 1 个主按钮 + 少量次按钮 | 每页只有 1 个主按钮（页面唯一主操作）；统计卡无图标无彩色 | 操作优先级：主按钮唯一，避免用户犹豫；"信息密度 > 装饰密度" |
| 7 | 动效无目的（入场动画、卡片脉冲） | 动效只服务反馈/引导/状态转换 | 保留的动效仅 4 类，见第 6 节 | 动效是"交互的语言"，没有目的的动效就是噪音 |
| 8 | 暗色 + 高饱和 = AI 审美的"默认输出" | 大厂控制台默认亮色为主 | v2 默认亮色（#F5F7FA 底 + 白面板），暗色降为可选项 | 亮色更贴近腾讯云/阿里云控制台的心智模型，也天然收敛了颜色表现 |

## 2. 设计原则（决策的顶层依据）

1. **信息层级优先**：标题(500) > 状态(色点+文字) > 数据(mono) > 辅助说明(灰)。任何元素问一句"它承载什么信息"，答不上来就删。
2. **颜色只做语义**：主色 1 个（品牌蓝），语义色 3 个（成功/警告/错误）只在状态处出现，中性色承担 80% 界面。
3. **一屏一焦点**：每页 1 个主操作按钮；操作按风险分级（默认按钮→危险按钮，紧急停止需要二次确认）。
4. **可预期**：hover 必反馈、异步必 loading、失败必给原因和出路（重试/查看日志）。
5. **8pt 栅格**：间距 8/12/16/24，组件高 32/36，卡片内边距 16，页面边距 24。

## 3. 视觉规范（Design Tokens）与决策理由

### 3.1 色彩

| Token | 值（亮） | 用途 | 决策理由 |
| --- | --- | --- | --- |
| `--brand` | `#1668DC` | 主按钮、选中态、链接、图表主曲线 | 腾讯云一代蓝，明度适中，在浅色背景对比度 4.6:1（达标）；比 Ant `#1677FF` 略沉，更"工程" |
| `--success` | `#00A870` | 运行中/成功 | TDesign 标准绿，带一点青，在亮色底更耐看 |
| `--warning` | `#FF8800` | 警告/启动中 | 与 success/danger 色相区隔明显，避免色盲混淆（配合文字） |
| `--danger` | `#D54941` | 错误/停止/告警严重 | Arco 红，饱和度比 v1 的 `#F53F3F` 低，更克制 |
| `--bg-app` | `#F5F7FA` | 页面底 | 浅灰，衬托白色面板形成层级；纯白做底会导致所有卡片无边界感 |
| `--bg-panel` | `#FFFFFF` | 面板/卡片/侧边栏/顶栏 | 核心表面 |
| `--border-1` | `#E4E7ED` | 常规描边 | 层级主要靠 1px 边框，不用重阴影 |
| `--text-1/2/3/4` | `#1F2329/#4E5969/#86909C/#C9CDD4` | 主/次/辅助/禁用 | TDesign 中性色阶，对比度：主 15.9:1、次 7:1、辅 4:1 |

**颜色纪律**：语义色必须成对使用「浅 tint 底 + 语义色文字/色点」；禁止纯色块大面积铺陈（Tag 用 tint 底不用实色底）；图表曲线颜色 ≤3 种。

### 3.2 字体

| 层级 | 字号/字重 | 用途 | 理由 |
| --- | --- | --- | --- |
| H1 | 18px / 500 | 页面标题 | 大厂后台标题不超过 18-20px，避免与内容抢层级 |
| H2 | 14px / 500 | 面板标题 | 卡片标题统一 14，全局一致 |
| Body | 13px / 400 | 表格、正文、按钮 | 桌面后台标准字号 |
| Secondary | 12px | 说明、表头、状态 | — |
| Mono | 12px | 端口、PID、日志、数值 | 等宽字体保证数字对齐，运维工具必备 |

**理由**：字体只设 2 个字重（400/500），不用 700+——粗体是强调手段，用多了就失去强调作用。

### 3.3 圆角 / 阴影 / 间距

- 圆角：控件 4px（按钮内小元素/Tag）、6px（按钮、输入框、表格操作）、8px（卡片、日志框）、12px（Modal）。
  **理由**：圆角与"工程感"负相关，4-8px 是大厂后台主流区间；v1 的 16px 卡片+999px 胶囊是移动端/消费级语言。
- 阴影：`sh-1 0 1px 2px`（卡片）、`sh-2 0 6px 20px`（浮层/Modal）。**理由**：桌面后台以边框分层为主，阴影只给"悬浮于页面之上"的元素。
- 间距：8pt 栅格（8/12/16/24）。行高表格 12px 内边距，卡片 16px，页面 24px。**理由**：栅格对齐是"整齐感"的来源。

## 4. 页面结构与布局理由

三段式保留（v1 的正确决定），每页布局按"信息承载方式"重新设计：

| 页面 | 结构 | 布局决策理由 |
| --- | --- | --- |
| **运行监控** | 页头(主操作"启动全部"+"刷新") → 4 数据卡 → 2:1 分栏（左：指标条+趋势图；右：网络+进程 TOP5） | 数据卡去图标化：大数字+单位+底部一行状态说明，信息直达；趋势图每 Tab 单曲线+次曲线，不堆叠 6 色 |
| **服务管理** | 页头 → 状态筛选 Tabs → 服务表格 → 底部生产明细 Tag 区 | 表格成为信息主轴（大厂后台通用模式）；操作列 hover 显示（次级操作不抢占视觉）；异常行红色 PID 心跳立即暴露问题 |
| **日志中心** | 工具条(级别 Tabs/搜索/自动滚动/导出/清空) + 日志正文 | 级别用 Tabs 带计数能力，比下拉更快；自动滚动用原生 checkbox（低层级选项用原生控件更轻） |
| **配置管理** | 左 176px 分组导航 + 右侧分组表单 + 底部操作栏 | 左侧导航符合"设置页"心智（微信/钉钉/控制台均如此）；保存/重置固定在表单底部，符合阅读动线 |
| **部署发布** | Stepper + 步骤日志 + 操作按钮 → 发布历史表 | Stepper 用填充/描边/实心区分完成/进行/未开始，无动画（状态可读性 > 动效） |
| **告警中心** | 列表（级别色点 + 标题 + 描述 + 时间 + 确认操作） | 确认操作明确、可批量；已确认置灰降噪，但保留可见（审计需要） |

**导航**：侧边 208px 可折叠至 52px（图标态）。菜单 3 分组（总览/管理/运维）——按"看 → 管 → 发布"的运维心智分组。

## 5. 组件规范

| 组件 | 规范 | 理由 |
| --- | --- | --- |
| 按钮 | 高 32（主操作 36）；变体 4 种：primary（品牌实底）/default（白底描边）/danger（红实底，仅毁灭性操作）/text（行内文字）；禁用 45% 透明；loading 内嵌 spinner 并禁用点击 | 变体越少决策成本越低；危险操作必须实色红，不可与普通操作同级 |
| 表格 | 表头 12px 灰、行高 48px、上下边框、hover 浅灰底、操作列 hover 淡入 | 大厂表格标准；hover 操作列避免 6 个按钮常驻 |
| 状态标识 | 6px 色点 + 12px 文字；过渡态用 11px spinner + 文字；**永远不单独用颜色** | 色盲友好 + 屏幕阅读器友好（Apple HIG 同款要求） |
| Tag | 高 22px、圆角 4px、tint 底 + 语义色文字；环境 Tag（开发/生产）用 tint 区分 | Tag 是"短状态"载体，必须可扫描 |
| 输入框 | 高 32、聚焦品牌色 2px 光晕、错误红边框+下方错误文案 | 错误要"说明原因"而非只变红（见可用性） |
| 空状态 | 40px 图标 + 12px 文案（+可选操作），禁止大留白占位 | 空状态是结果不是错误，不给用户压力 |
| Modal | 标题+描述+操作栏，遮罩 45% 黑；用于紧急停止等不可逆操作 | 二次确认是"最后一道保险" |

## 6. 关键交互定义（状态流转 / 边界 / 异常）

### 6.1 服务启停状态机（原型可交互体验）

```
        ┌──────── 启动 ────────┐        ┌──────── 停止 ────────┐
  已停止 ──► 启动中(可取消) ──► 运行中 ──► 停止中 ──► 已停止
     ▲            │(超时30s/端口冲突)       │
     └────────────┴──► 异常(原因可见) ◄─────┘
```

- **进入条件**：启动按钮仅在 `stopped/error` 态可用；停止仅在 `running` 态可用。
- **互斥边界**：开发/生产环境互斥——切换环境前必须停止当前环境；启动时若另一环境在运行，弹确认 Modal 先停后启（原型在"生产明细"区提示该规则）。
- **异常处理**：启动失败必须给出**具体原因**（原型演示：端口 8000 被 PID 7841 占用），并提供"重新启动"出路，同时自动写入告警中心。
- **防重复**：starting/stopping 期间操作列显示"操作锁定中"，按钮全部禁用——避免连点造成进程双起。

### 6.2 行内操作的可发现性

- 操作按钮 hover 行才出现（`opacity 0→1`）。**理由**：6 行服务 × 3 按钮 = 18 个按钮常驻会淹没表格；hover 展开符合"需要时才有"的认知，且键盘/Touch 场景下保持 `:focus-within` 可见。

### 6.3 日志中心

- 级别筛选 + 关键字搜索双条件过滤（原型已实现实时过滤）。
- 自动滚动默认开启；进程退出时插入 `── 上次进程启动 · PID 8932 ──` 分隔线并停止滚动。
- 清空为**不可逆**，用普通按钮 + 成功 Toast 反馈（清空日志风险低，不需要 Modal 二次确认；与紧急停止的确认策略分级）。

### 6.4 配置保存（脏标记机制）

- 表单任一字段修改 → 标题栏出现"未保存"警示（黄色原点+文字），保存/重置按钮激活。
- 保存前校验（原型：Redis 端口 1-65535），失败：输入框红框 + 下方错误文案 + Toast，**不滚动页面不打断其他输入**。
- 保存成功：Toast"已保存"并**明确提示影响范围**（"涉及 NSSM 的修改将在下次服务重启时生效"）——告诉用户"接下来会发生什么"。
- 无变更点保存 → 中性提示"没有变更"，不假装成功。

### 6.5 部署发布

- 步骤条：完成（实心勾）/进行（描边数字）/未开始（灰描边）/失败（实心红），当前步仅靠填充差异表达，**无脉冲动画**。
- 每步执行中日志实时追加；**失败分支**：当前步标红，操作区切换为"重试本步 / 回滚上一步"（原型提供"回滚"按钮与对应 Toast 说明回滚目标备份）。
- 完成：全步骤实心 + 绿色 Banner + 成功 Toast。

### 6.6 告警确认

- 确认后置灰但**保留在列表**（审计需要），可一键批量确认。
- 级别：严重(红)/警告(黄)/提示(蓝)，与状态色同一语义体系。

### 6.7 紧急停止（最高风险操作）

- 入口常驻状态栏（红实底小按钮），但**必须经过 Modal 二次确认**，Modal 内列出将被终止的完整进程树清单。
- 确认按钮进入 1.4s loading 防连点，完成后 Toast + 状态栏同步为"已停止"。
- **决策理由**：风险与确认成本成正比。清空日志（低风险）用单次确认；紧急停止（不可逆）用 Modal。

## 7. 动效规范（动效即反馈，不承担信息传达）

| 动效 | 时长/曲线 | 目的 | 出现场景 |
| --- | --- | --- | --- |
| hover 背景/文字变色 | 150ms ease | 反馈"可交互、有响应" | 按钮、菜单、表格行、Tabs、操作按钮 |
| 页面切换淡入 | 200ms ease | 位置感知连续性，避免跳变 | 侧边菜单切换页面 |
| 按钮 loading spinner | 0.7s 循环 | 反馈"异步进行中"，同时禁用防连点 | 启动/停止/保存/紧急停止 |
| 指标条宽度 | 500ms ease | 数值平滑变化，避免跳动 | CPU/内存/磁盘使用率条 |
| 操作列淡入 | 150ms ease | 可发现性，非炫技 | 表格行 hover |

**明确不做**：脉冲/光晕/位移动画/入场序列动画/骨架呼吸。理由：状态转换由「颜色+文字+spinner」表达，动效不承载信息——这是 v1 被诟病"为动而动"的直接修正。

## 8. 可用性自检清单（对照 WCAG 2.1 AA / Apple HIG）

- [x] 对比度：正文 #1F2329 on #FFFFFF = 15.9:1；辅助文字 #86909C = 4.0:1（仅用于非关键信息）；品牌蓝按钮白字 4.6:1
- [x] 状态不只靠颜色：色点 + 文字双通道；色盲（红绿）可通过文字识别
- [x] 触控目标 ≥ 32px（桌面端），主操作 ≥ 36px
- [x] 键盘可达：所有操作是原生 button/input，支持 Tab/Enter
- [x] 错误有原因 + 出路（错误文案 + 重试按钮），不甩给用户
- [x] 一屏一主操作，次要操作 hover 展开，认知负担最低
- [x] 减少动效偏好：全部动效 ≤500ms，无循环装饰动画
