# ERP 系统全量迁移方案（192.168.0.95 → 192.168.0.142 · C 盘）

> 迁移方式：**整机物理冷拷贝**（停服后整目录复制，新机注册服务即运行）。
> 数据范围：**全量业务数据 + 结构 + 数据库插件 + 所有配套运行环境**，与旧机 100% 一致。
> 本文档随迁移包一起拷贝到新服务器，供新服务器上的 Trae 一键恢复使用。

---

### Windows 服务清单（3 个基础服务 + 2 个 NSSM 服务）

| 服务名 | ImagePath（旧机原文） | 运行账户 |
|------|------|------|
| postgresql-x64-18 | `"D:\PostgreSQL\bin\pg_ctl.exe" runservice -N "postgresql-x64-18" -D "D:\PostgreSQL\data" -w` | NT AUTHORITY\NetworkService |
| postgresql-replica | `"D:\PostgreSQL\bin\pg_ctl.exe" runservice -N "postgresql-replica" -D "D:\PostgreSQL\replica_data" -w` | NT AUTHORITY\NetworkService |
| rediserp | `"C:\Redis\redis-server.exe" --service-run D:\erp_system\config\redis.production.conf --service-name RedisERP` | NT AUTHORITY\NetworkService |
| erp-prod (NSSM) | `C:\...\Python313\python.EXE -m fastapi_app.core.prod_runner --no-arq`，AppDirectory `D:\erp_system` | LocalSystem |
| erp-arq (NSSM) | `python.EXE -m arq fastapi_app.core.arq_app.WorkerSettings`，AppDirectory `D:\erp_system` | LocalSystem |

NSSM AppEnvironmentExtra（两个服务相同）：
`APP_ENV=production FASTAPI_DEBUG=false PYTHONPATH=<项目根> PYTHONUTF8=1 PYTHONUNBUFFERED=1 UVICORN_WORKERS=4`

> `NT AUTHORITY\NetworkService` 是全机统一的内置账户（SID S-1-5-20），新机无需创建任何 OS 账户；ACL 已随 /COPYALL 复制。

## 3. 新服务器恢复步骤（Trae 逐条执行）

> 前提：迁移包已在 `C:\erp_migration_142\`。管理员权限 PowerShell。逐阶段执行并汇报。

### 阶段 1：目录就位（C 盘内移动，秒级完成）

```powershell
robocopy C:\erp_migration_142\erp_system  C:\erp_system          /E /COPYALL /R:2 /W:2 /MT:16
robocopy C:\erp_migration_142\PostgreSQL  C:\PostgreSQL          /E /COPYALL /R:2 /W:2 /MT:16
robocopy C:\erp_migration_142\Redis       C:\Redis               /E /COPYALL /R:2 /W:2
robocopy C:\erp_migration_142\nssm        C:\nssm                /E /COPYALL /R:2 /W:2
robocopy C:\erp_migration_142\Python313   C:\Python313           /E /COPYALL /R:2 /W:2 /MT:16
```

> robocopy 退出码 0-7 均为成功（8+ 才是失败）。全部就位后 `C:\erp_migration_142` 可保留 3-7 天作为二次恢复源，验证通过后可删。

### 阶段 2：必改配置（D: → C: 及 IP 相关，共 3 个文件）

1. **`C:\erp_system\.env`**
   - `JWT_PRIVATE_KEY_PATH=d:/erp_system/config/jwt/private.pem` → `c:/erp_system/...`
   - `JWT_PUBLIC_KEY_PATH=d:/erp_system/config/jwt/public.pem` → `c:/erp_system/...`
   - `ALLOWED_HOSTS=["192.168.0.95","localhost","127.0.0.1"]` → `["192.168.0.142","192.168.0.95","localhost","127.0.0.1"]`（保留 95 便于过渡期访问）
   - `CORS_ORIGINS` 追加 `,http://192.168.0.142:3000`
   - 数据库/Redis 连接全部是 localhost，**不用动**（密码已在数据目录/配置里，原样有效）
2. **`C:\erp_system\fastapi_app\log_config.json`**：两处 `"filename": "D:/erp_system/logs/fastapi.log"` → `C:/erp_system/logs/fastapi.log`
3. **确认无需改动**：`config/redis.production.conf`（相对路径）、`config/nginx-windows.conf`（未启用，路径相对项目根）、`migrations/alembic.ini`

### 阶段 3：注册基础服务（PG 主 → PG 副 → Redis）

```powershell
# VC++ 运行库自检（PG/Python 需要；缺则先装 vc_redist.x64.exe 再继续）
Test-Path C:\Windows\System32\msvcp140.dll

# PostgreSQL 主库（-S a = 开机自启）
C:\PostgreSQL\bin\pg_ctl.exe register -N "postgresql-x64-18" -D "C:\PostgreSQL\data" -S a
sc.exe config postgresql-x64-18 obj= "NT AUTHORITY\NetworkService"

# PostgreSQL 只读副本（5433）
C:\PostgreSQL\bin\pg_ctl.exe register -N "postgresql-replica" -D "C:\PostgreSQL\replica_data" -S a
sc.exe config postgresql-replica obj= "NT AUTHORITY\NetworkService"

# Redis（服务名 rediserp，与旧机一致）
sc.exe create rediserp binPath= "\"C:\Redis\redis-server.exe\" --service-run C:\erp_system\config\redis.production.conf --service-name RedisERP" start= auto obj= "NT AUTHORITY\NetworkService"

# 若 PG 首次启动报 postmaster.pid 锁文件（跨机冷拷贝偶发），删除后重试：
# Remove-Item C:\PostgreSQL\data\postmaster.pid, C:\PostgreSQL\replica_data\postmaster.pid -ErrorAction SilentlyContinue

# 按序启动：主库 → 副本 → Redis
Start-Service postgresql-x64-18; Start-Sleep 5
Start-Service postgresql-replica;  Start-Sleep 5
Start-Service rediserp
```

### 阶段 4：注册 NSSM 服务（erp-prod / erp-arq，两步安装法）

```powershell
$nssm = "C:\nssm\nssm.exe"
$py   = "C:\Python313\python.exe"

# 后端主服务（监督器：uvicorn 4 workers，不内嵌 ARQ）
& $nssm install erp-prod $py
& $nssm set erp-prod AppParameters "-m fastapi_app.core.prod_runner --no-arq"
& $nssm set erp-prod AppDirectory "C:\erp_system"
& $nssm set erp-prod AppEnvironmentExtra "APP_ENV=production FASTAPI_DEBUG=false PYTHONPATH=C:\erp_system PYTHONUTF8=1 PYTHONUNBUFFERED=1 UVICORN_WORKERS=4"

# ARQ 异步任务服务
& $nssm install erp-arq $py
& $nssm set erp-arq AppParameters "-m arq fastapi_app.core.arq_app.WorkerSettings"
& $nssm set erp-arq AppDirectory "C:\erp_system"
& $nssm set erp-arq AppEnvironmentExtra "APP_ENV=production FASTAPI_DEBUG=false PYTHONPATH=C:\erp_system PYTHONUTF8=1 PYTHONUNBUFFERED=1 UVICORN_WORKERS=4 PYTHONIOENCODING=utf-8"

& $nssm start erp-prod
& $nssm start erp-arq
```

### 阶段 5：前端托管（按现状回退 vite preview；Nginx 可选增强）

现状是 vite preview（prod_runner 自动管理，无需额外服务），只需：

```powershell
# 安装 Node.js ≥ 20.19（旧机为 v24.14.0；装 LTS 22.x 或 24.x 均可）
# 验证：
node --version

# prod_runner 启动时会自动执行 vite preview --host 0.0.0.0 --port 3000 并反代 /api、/ws
```

可选（推荐，生产更稳）：下载 Nginx for Windows 解压到 `C:\nginx`（含 `nginx.exe`），prod_runner 会**自动优先**使用 `config/nginx-windows.conf` 托管 dist（此后无需 Node 常驻）。

### 阶段 6：防火墙放行（局域网访问 3000）

```powershell
netsh advfirewall firewall add rule name="ERP-Frontend-3000" dir=in action=allow protocol=TCP localport=3000
```

## 4. 验证清单（逐项打勾）

- [ ] `pg_isready -h 127.0.0.1 -p 5432` 与 `-p 5433` 均 accepting
- [ ] 副本在恢复模式：`& C:\PostgreSQL\bin\psql.exe -U erp_app -h 127.0.0.1 -p 5433 -d erp_system -c "SELECT pg_is_in_recovery();"` → `t`（密码 110110）
- [ ] **（旧机实情）** 5433 副本实际是 **WAL 归档冷备**（自行回放本地 WAL，非实时流复制挂接主库；旧机日志见"无法从WAL流中取得记录/恢复中关闭"）。新机恢复后行为与此一致即正确；若要与主库建立实时流复制，需按第 5 节兜底表重建 basebackup。业务写入只走 5432 主库，不受影响
- [ ] **插件一致**：`SELECT extname||' '||extversion FROM pg_extension;` → 恰好 `plpgsql 1.0`、`pg_trgm 1.6` 两行
- [ ] Redis：`C:\Redis\redis-cli.exe -a ERP_Redis_2026_Secure_Password ping` → PONG
- [ ] 后端：`curl http://127.0.0.1:5002/api/health` → 200
- [ ] 前端：浏览器开 `http://192.168.0.142:3000` 出登录页
- [ ] 业务数据完整：登录后任开"订单/库存/报表"页，记录数与旧机一致（抽查 1-2 个页面即可）
- [ ] 异步任务：触发一次导出/报表，ARQ 正常出结果
- [ ] NSSM：`Get-Service erp-prod,erp-arq,postgresql-x64-18,postgresql-replica,rediserp` 全部 Running；重启服务器一次，全部自动拉起

## 5. 回滚与兜底

| 场景 | 处置 |
|------|------|
| 新机验证失败 | 旧机 95 未做任何破坏性变更，原服务随时可 `Start-Service` 拉起（迁移期间已恢复验证过一次） |
| PG 服务起不来 + 报 DLL 缺失 | 安装 Microsoft VC++ 2015-2022 x64 运行库（vc_redist.x64.exe）后重试 |
| PG 报 postmaster.pid 占用 | 删除 `data\postmaster.pid`（及 replica_data 下的）再启动 |
| 副本连不上主库（WAL 缺口） | 重新 basebackup：停 postgresql-replica → 清空 `C:\PostgreSQL\replica_data` → `pg_basebackup -h 127.0.0.1 -p 5432 -U replicator -D C:\PostgreSQL\replica_data -Fp -Xs -P -R`（密码 ERP_Replication_2026_Secure）→ 起服务 |
| vite preview 异常 | 装 Nginx 到 `C:\nginx` 走静态托管（阶段 5 可选项） |
| 前端要重新构建 | 注意：本项目环境 `vite build` 偶发卡死，构建卡住时用 `npx vite preview` 兜底，勿反复重试 |
