## ADR-001: 备份加密决策单点化（状态：已接受，实施于 5f18610）

**上下文**：加密决策分散在服务层（create_full_backup 内部回退）与端点层
（_resolve_encryption）两处。遗留端点 /save 在无环境密码时会用**随机密钥**在
服务层加密，端点层又降级明文把密文存成 .zip——文件永久不可还原；有环境密码
时两层各加密一次（双重加密）。随机密钥只输出前 8 位预览，等价于销毁备份。

**决策**：加密意图只在调用方解析一次（参数 > 请求头 > 环境变量，均无则明文
+告警），服务层只执行。`encrypt=True` 无密码直接报错（宁可失败不可造出打不开
的备份）；`BACKUP_ENCRYPTION_FALLBACK_TO_GENERATED` 默认改 false 并弃用。
新增 `decrypt_backup_auto` 兼容裸信封/meta 前缀两种历史格式。

**后果**：放弃"忘了配密码也能有加密备份"的伪安全感；换来备份 100% 可还原
（明文）或显式失败。加密文件统一 `.zip.enc` 扩展名 + `.meta` sidecar。

## ADR-002: 异地备份（3-2-1）（状态：暂缓——用户 2026-08-23 决定不做）

**上下文**：开发机即生产服务器，备份与数据同盘，单盘故障 = 数据与备份同失。
对标项目（OCA SFTP / Frappe offsite S3 / DBackup 13+ 适配器）均有异地能力。

**决策**：用户明确本批不实施。`BackupStorage` 端口与 LocalBackupStorage 适配器
保留为扩展位；若未来启动，推荐先做"备份完成后推送命令模板"（零依赖、可逆），
再做原生 SFTP 适配器。

**后果**：单盘风险仍在，已知且由用户接受；架构上留有低成本接入点。

## ADR-003: 还原内核唯一化——接线 DatabaseRestoreOrchestrator（状态：已接受，实施于 6c6087a）

**上下文**：六边形 ports/adapters + Orchestrator 设计完整但未接线，与过程式
restore_from_zip 双轨并存（解密/校验/验证各写两遍），漂移风险高。备选是删除
半成品。

**决策**：接线而非删除。restore_from_zip 成为薄包装：构建 Orchestrator +
现有适配器，端点层已持有的 Redis 锁与 pre-restore 安全备份以 NoOp 适配器注入
（职责归属：锁与安全备份归端点，归档解密/策略/组件/连接池/缓存/验证归内核）。
组件-only 包保留轻量路径。**行为变化**（有意）：db 文件 checksum 不匹配由
"告警继续"改 fail-fast。

**后果**：还原逻辑单一真相源，阶段化/journal 可观测；restore.py 净删 ~200 行
重复实现。修复成本换长期可维护性。

## ADR-004: PITR 方向（状态：提议，仅记录不实施）

**上下文**：应用级备份 RPO = 两次备份间隔（当前每日全量 + 高频增量，最坏数
小时）。WAL 归档（pgBackRest/WAL-G）可达秒级 RPO，但属数据库层运维体系。

**决策**：暂不实施。应用级备份保业务粒度（表级/组件/加密/验证），PITR 由
DBA 体系承担——两者解耦共存。待业务对 RPO 有硬要求（如财务审计级）再启动。

**后果**：避免为假想的 RPO 需求引入双运维体系。

## 附：本批明确拒绝的替代方案

| 提案 | 拒绝理由 |
|---|---|
| restic/Borg 式内容寻址去重 | 单机数据量级收益低；复杂化恢复路径（DBackup 明示同样权衡） |
| WebSocket/SSE 替换轮询 | 单管理员场景 800ms 轮询足够；设计文档两次排除 |
| 备份域微服务化 | 单机部署、无独立扩展诉求 |
