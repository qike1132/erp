## 一、这次是被一句话推翻重做的

> 「这个页面，只是登记到货时间以及到货数量。」

这句话把上一版的根本错误点出来了：我在**没有约定交期**的数据上，用 30 天阈值造了一个「逾期」概念，
又把它和「已到齐/进行中/未开始」混在同一列状态里。结果：

- 用户看到「逾期 38 天」，会以为「本该 38 天前到」——但系统里根本没有那个「本该」；
- 「逾期」既不能排序也不能筛选（混语义），红字铺满整屏，红色失去指向性；
- 三层卡片（订单 → 供应商 → 物料）把可比较性换成了装饰，一屏只放得下 3 单。

## 二、这一版的信息模型

页面上只有两个业务事实：**哪天到的**、**到了多少**。其余都是推导：

| 列 | 数据来源 | 说明 |
|---|---|---|
| 到货日期 + 已等 N 天 | `material_registration.registration_date` | 如实显示登记日与距今自然日；不叫「逾期」 |
| 订单 / 客户 · 产品 | `purchase_order_no` / `customer_name` / `sku_items` | 一行物料的归属 |
| 物料 / 规格 | 明细 `material_name` / `specification` | |
| 已到 / 采购 + 单位 | `received_quantity` / `ordered_quantity` / `unit` | 已到加粗，采购作分母弱化 |
| 进度 | 已到 ÷ 采购 | 0% 写「未到」、100% 写「到齐」，不写数字 |
| 明细 | — | 打开供应商详情（内含逐子件「登记收货」） |

**行 = 一条登记里的一行物料。** 同一供应商的多批登记不合并：到货日期不同，合并会抹掉「哪一批还没收齐」。
供应商 / 订单降级为**视图模式**（分组行），默认「按供应商」——这是 owner 最初的要求，
但它现在是一层分组标题，不是一层卡片。

## 三、三条明确的取舍

1. **时间风险与数量进度分通道。** 数量只说三种事实（未到 / 部分 / 到齐）；时间只在日期列表达
   （≤7 天灰、7–29 天琥珀、≥30 天且未收齐红）。两者不混在同一列，所以都能各自筛选。
2. **跨单位不给百分比。** 组头数量合计与数量进度只在「组内单位一致」时出现（码/只/kg 混在一起求和无意义）；
   否则组头只给「已到齐 x/y 项」，这是单位无关的事实。行级百分比永远成立（同一行同单位）。
3. **阈值只有一个来源。** `SLOW_DAYS = 30` 与后端 `stats/distribution` 的 SQL 同口径；
   界面文案从「逾期」改为「≥30 天」，说明的是「登记满 30 天仍未收齐」这个可核验的事实。
