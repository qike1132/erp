# M3 双损耗语义拆分设计方案 — 备品率 vs 材料损耗率

> 版本：v1.0（待产品确认）｜ 日期：2026-08-29 ｜ 作者：产品经理
> 范围：`/purchase` 汇总下单弹窗（工厂内部订单 + 供应商采购订单）
> 性质：**纯设计文档，不修改任何代码**
> 前置：M1+M2 已由架构师审核确认（合计行备品列位缺陷、测试盲区），本文聚焦 M3 语义拆分，M1/M2 的修复建议一并纳入 P0 范围。

## 0. 问题背景与代码事实（调研依据）

### 0.1 当前实现：一个输入框、两个语义

`SummaryModal.vue` 顶部「损耗率（千分之几）」单输入框（`SummaryModal.vue:42-59`），输入经 300ms 防抖后（`:277`）发出 `applyLossRate`，同时驱动两处：

| 驱动点 | 公式 | 粒度/取整 | 代码位置 |
| --- | --- | --- | --- |
| ① 备品数量列（新增） | `备品 = ceil(订单数量 × 损耗率‰)` | 产品级成品件数，向上取整 | `useSummaryModal.ts:25-28`（calcSpareQty）、`SummaryModal.vue:104` |
| ② 布料「数量」列叠加（既有） | `布料 = 原值 + 原值 × 损耗率‰`，round 2 位 | 材料级连续值，不取整 | `useSummaryModal.ts:288-313`（applyLossRate，同步修改工厂布料 + 供应商物料） |

### 0.2 问题复现（实测口径）

订单 100 件、损耗率 5‰：
- 备品列：`ceil(100×5‰)=ceil(0.5)=1` 件 —— 占订单 **1%**
- 布料列：原值 × 1.005 —— 仅叠加 **0.5%**

若备品件需要对应布料供应，布料叠加量**不足以覆盖**取整后的备品件（缺口 0.5 件对应的布料）；若损耗率本意只是材料损耗，则备品列存在"重复计损"。且两列单位不同（件 vs 米/连续量），紧邻展示易让用户误读「损耗率到底加在哪」。

## 1. 产品口径定义（方案对比与推荐）

### 1.1 两套参数的语义（推荐口径，先定义再谈方案）

| 参数 | 语义（产品语言） | 单位 | 取值域 | 默认值 | 驱动对象 |
| --- | --- | --- | --- | --- | --- |
| **备品率** spare_rate | 按订单成品件数比例预留的备品（成品备件），用于交付/质检替补 | 千分之几 ‰ | 0-1000 | 0 | 仅「备品数量」列（+ P1 可选联动布料） |
| **材料损耗率** material_loss_rate | 生产环节（裁剪/缝制）布料损耗，按布料用量叠加 | 千分之几 ‰ | 0-1000 | 0 | 仅布料「数量」列 + 供应商物料「数量」（两 Tab 平行叠加） |

行业习惯依据：
- **备品**在服装/纺织采购中通常是**按订单件数比例预留成品**（如每 100 件备 1 件，即 10‰），是离散件数概念，天然向上取整；
- **布料损耗**是**生产环节连续损耗**（裁剪损耗、段差损耗等），按布料米数/用量加比例，是连续值概念。

两者业务阶段不同（采购口径 vs 生产口径）、粒度不同（件 vs 连续量）、取整规则不同（ceil vs round），**不应共用一个输入**——这是本次拆分的核心论点。

### 1.2 方案对比

| 维度 | 方案 A：两个独立参数 | 方案 B：单一备品率 + 布料自动联动 | 方案 C（推荐）：两个独立参数 + 备品布料联动开关 |
| --- | --- | --- | --- |
| 参数个数 | 2（备品率、材料损耗率） | 1（备品率） | 2 + 1 开关（备品率、材料损耗率、「备品计入布料」默认开） |
| 备品列公式 | `ceil(订单×备品率‰)` | `ceil(订单×备品率‰)` | 同 A |
| 布料数量公式 | `原值 × (1 + 材料损耗率‰)` | `原值 × (订单+备品)/订单`（备品自动折算进布料） | 开：`原值 × (订单+备品)/订单 × (1+材料损耗率‰)`；关：`原值 × (1+材料损耗率‰)` |
| 语义清晰度 | ★★★★★ 两参数职责独立 | ★★★★ 单参数简单，但丢失"材料损耗"独立表达 | ★★★★★ |
| 备品是否有布料供应 | ✗（默认不联动，备品与布料脱钩） | ✓（自动折算，严格自洽） | ✓（默认开）；可关 |
| 能否独立表达生产损耗 | ✓ | ✗（无法表达"备品之外还有裁剪损耗"这类真实需求） | ✓ |
| 用户操作成本 | 每次填 2 个值（可配默认值后≈0） | 1 个值 | 同 A（开关默认开，多数场景无需动） |
| 实现成本（前端） | M（拆分 state/UI/公式） | M（拆 state + 改联动公式） | M（与 A 相当，多一个开关与一条公式分支） |
| 实现成本（后端） | P0 零；P1 全局配置接口 S-M | P0 零；P1 同左 | P0 零；P1 同左 |
| 对现状的兼容 | 两输入都填原值时与现状完全一致（纯拆分，无回退） | 需迁移语义（布料叠加由 rate 改为联动因子），数值会与旧行为不同 | 两输入都填原值 + 关闭联动时与现状一致；默认开启时布料数值变化（这正是修复目标） |

### 1.3 推荐：方案 C（A 的务实版）

**推荐理由**：
1. **语义正交**：备品率管"成品件数预留"，材料损耗率管"生产布料损耗"，两参数职责单一、口径自洽，彻底消除"同一数值两种含义"；
2. **默认联动解决真实缺口**：默认开启「备品计入布料」后，布料数量按 `(订单+备品)/订单` 折算，备品件有对应布料供应——直接修复 0.5 节描述的"叠加不足"缺陷；
3. **保留纯材料损耗场景**：不需要备品布料联动时（如备品仅作交付备用、布料按生产实际独立下单），一键关闭联动即可退化为"只按材料损耗率叠加"，不损失表达能力；
4. **渐进可落地**：P0 只做"纯拆分"（方案 A 行为，零回退），P1 再加联动开关与持久化，风险可控；
5. **贴合行业**：备品按件数比例、布料损耗按生产环节，两个概念在本行业采购流程中本来就分开管理。

**回退说明**：若产品最终确认"备品不需要布料供应、布料只按生产损耗叠加"，则采用方案 A（P0 拆两参数、不做联动开关），本文档中 P1 联动部分自动降级为"可选增强项"。

## 2. 交互设计

### 2.1 输入控件形态

- **位置**：沿用现有损耗率输入区（`SummaryModal.vue:42-59`，汇总表头右上角），改为**两个紧凑输入框**并排：
  - 「备品率 ‰」（w-16，样式同现有 input）
  - 「材料损耗率 ‰」（w-16）
  - P1 起在两者之间追加「备品计入布料」复选框（默认勾选，选中时显示浅色提示文字"备品布料已按件数折算"）
- **文案**：输入框前标签分别写「备品率（千分之几）」「材料损耗率（千分之几）」，鼠标悬停/`title` 给一句解释：
  - 备品率 → "按订单件数预留成品备件，向上取整"
  - 材料损耗率 → "按布料用量叠加生产损耗，用于裁剪/缝制"
- **防抖/校验**：沿用 `useDebounceFn(..., 300)`（`SummaryModal.vue:277`）；两个输入各自 debounce；校验逻辑复用现有 `onLossRateInput`（`:279-286`）：`NaN/<0 → 0`，`>1000 → clamp 1000`；`min=0 max=1000 step=any`。
- **实时反馈**：输入即重算（备品列 / 布料列 / 合计列同步刷新），与现状一致。

### 2.2 编辑模式表现（关键交互决策）

现状：编辑模式下输入框隐藏（`SummaryModal.vue:42`），且进入编辑态**不重置**参数、参数叠加值可被「保存修改」固化（F3）。

设计建议（P0 一并处理）：
1. **编辑模式下两参数输入框保持隐藏**（避免"参数"与"手工改数量"两种编辑方式在同一视图混淆）；
2. **进入编辑态自动重置参数**：`toggleEditMode(true)` 时若任一路率 ≠ 0，弹确认「进入自定义编辑将清除备品/损耗叠加，恢复原始数量」，确认后 `factoryData ← factoryOriginalData` 且两路率归 0（与 `toggleEditMode(false)` 行为对称，`useSummaryModal.ts:254-261`）；
3. **「保存修改」只持久化手工编辑 diff**：`saveFactoryEdits` 基于"无参数叠加的原始值"比对（参数叠加只作用于展示副本），避免参数误固化；同时保留现有个数级布料数量编辑能力（`updateFactoryQty:263-286` 同步供应商物料）；
4. **openSummary/close 重置两路率为 0**（修复 L7，`useSummaryModal.ts:231-252,364-369`）。

### 2.3 汇总行/合计

- P0 修复 M1：合计行改为 5 单元格 —— `colspan=3「合计」` + 第4列备品合计 + `colspan=3` 空 + 第8列数量合计 + 第9列空（`SummaryModal.vue:128-136`）；
- 备品合计仍按"各 group ceil 后累加"（F7），材料损耗不产生独立合计列（已并入布料数量）。

## 3. 数据模型影响

### 3.1 结论：P0 无需持久化、后端零改动

- 现状 `lossRate` 为纯前端会话态（F1），后端 schema/接口无损耗/备品字段（F6）；
- P0 拆分后两参数仍为前端 `ref` 会话态，**不进 saveFactoryEdits 契约**。save 契约维持 `{item_ids, quantity}` 不变——参数是"计算参数"，布料最终数量才是持久化数据，参数本身不落库；
- **既有保存/导出/打印影响**：
  - 保存：save 逻辑不变（数量 diff），仅交互上避免参数叠加值误固化（§2.2）；
  - 导出/打印：`buildFactoryHtml` 参数由 `lossRate: number` 改为 `rates: { spareRate, materialLossRate }`，输出 9 列表头与列顺序不变 → **历史格式兼容**。

### 3.2 P1 持久化建议（全局配置，粒度分级）

| 粒度 | 方案 | 适用 | 工作量 |
| --- | --- | --- | --- |
| 全局配置（推荐 P1 首期） | 后端单行表 `purchase_settings`（参照 `BackupSettings` 单行模式，`shared_models/backup_settings.py:16-29`），字段 `spare_rate / material_loss_rate / spare_fabric_linkage / updated_by / updated_at`，新增 `GET/PUT /purchase-center/settings`；前端 openSummary 时拉取作为默认值 | 多用户共享默认参数、可审计 | M |
| 用户级/工厂级 | 表加 `scope/scope_id` 维度或独立用户设置表 | 多工厂/多用户差异 | L |
| 订单级快照 | 保存汇总时将两参数写入采购订单扩展字段/备注 JSON | 单据追溯、重打单一致 | L |

- 前端兜底：P1 若暂缓后端，可先用 `localStorage` 存默认值（单机单用户场景），但**不推荐作为最终方案**（无法多用户共享、无审计）。

### 3.3 saveFactoryEdits 契约评估

- **不新增字段**（P0/P1）：edits 维持 `item_ids + quantity`；
- 若 P2 需要"保存时同时记录本次汇总的参数快照"，建议扩展 `FactorySummarySaveRequest` 增加可选 `params: { spare_rate?, material_loss_rate? }`（`schemas/purchase_center.py:196-197`），后端落订单快照字段——**默认不做，作为 P2 可选项**。

## 5. 边界与兼容

| 场景 | 行为 | 说明 |
| --- | --- | --- |
| 旧数据（已有订单无两套参数） | 打开弹窗两参数默认 0 → 备品 0、布料原值 | 与旧行为"rate=0"一致，无破坏 |
| 旧用户习惯（单一 rate=5） | 拆分后填「备品率=5 + 材料损耗率=5」→ 备品 1 件 + 布料 +0.5% | 与旧行为数值完全一致（纯拆分无回退） |
| 损耗率=0 / 材料损耗率=0 | 备品 0、布料不叠加 | `calcSpareQty` 已守卫 `<=0 → 0`（:26）；材料损耗 0 分支等价原值 |
| 备品率>0 但 qty×rate<1 | 备品 = 1（ceil 下界） | 与现状一致（100×5‰→1）；P1 联动时布料按 `(订单+1)/订单` 折算 |
| 历史打印/导出 | 表头 9 列、列顺序不变；每次实时生成 HTML 快照，不追溯历史 | 无历史兼容问题（前提：P1 不加"含备品/含损耗"标注，如需加属格式变更需单独评审） |
| 小数订单数量（0.01 件） | 沿用现状（备品按原始值 ceil=1） | L2 观察项，P2 再议 |
| 空 fabrics group | 备品合计与可见行不同源（L6） | 建议随 P0 顺带修复（spareGrandTotal 只累加有 fabrics 的 group） |

## 6. 分阶段实施建议

## 7. 待产品确认问题清单

1. **是否真的需要两套参数？** 备品率（按件数预留成品备件）与材料损耗率（按布料用量叠加生产损耗）是否都作为独立输入？还是只要"备品率 + 布料自动联动"（方案 B，省一个输入但丢失材料损耗独立表达）？
2. **备品是否必须联动布料供应？** 备品件数是否要求布料按 `(订单+备品)/订单` 折算补足？默认开启还是默认关闭？（决定 P1 联动公式与开关默认值）
3. **参数是否需要持久化？粒度？** 全局配置（单行表）／用户级／订单级快照／仅会话态？（决定 P1 后端改动量与接口设计）
4. **编辑模式下参数如何处理？** 进入编辑态是否自动清除参数叠加、保存是否只持久化手工 diff？（避免参数误固化入库）
5. **默认值是多少？** 备品率/材料损耗率默认 0，还是按行业惯例预置（如备品 5-10‰、材料损耗 20-50‰）？预置会影响所有新单据展示。
6. **旧单一输入框迁移引导？** 拆分后旧用户需填两个值，是否在输入区加一次性引导文案/提示气泡，避免"只填一个"造成数值与预期不符？
7. **打印/导出是否标注参数？** 表头保持 9 列不加标注（兼容优先），还是 P2 增加"含备品 X、含损耗 Y‰"注记（更严谨但属格式变更）？
