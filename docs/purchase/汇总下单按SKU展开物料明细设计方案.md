# 汇总下单「按 SKU 展开物料明细」设计方案

> 版本：v1.0（待评审）｜ 日期：2026-09-30
> 范围：`/purchase` 汇总下单弹窗「工厂内部订单」页签（屏幕 + 打印预览 + Excel 导出）+ 后端汇总接口
> 性质：**纯设计文档，不修改任何代码**
> 前置裁决（用户 2026-09-30）：① 口径 A（每 SKU 物料量 = `BOM 单件用量 × 该 SKU 数量`，**算出来的**）；② 每 SKU 一块、块内物料独立；③ 率与数量在「同一物料」上**跨 SKU 联动**；④ 存在手工改动差异时**追加「实际下单」对照块**；⑤ 供应商列块内合并、客户列跨整组合并；⑥ 打印/导出同步；⑦ 供应商页签**不动**。

---

## 0. 问题与目标

**现象**：多 SKU 的采购单里，物料明细是**跨 SKU 合并**展示的——看不出「哪个 SKU 要多少料」。用户截图那单（MINISO国际 / 测试 10000 + 鲨鱼 10000）里，两种超柔各只出现一行（订单级合计），SKU 名则堆在左侧一格。

**目标**：每个 SKU 拥有一整块自己的物料明细（供应商 / 布料名称 / 规格型号 / 损耗率 / 数量 / 单位），块内独立、彼此不合并。

**明确不做（非目标）**：

| 不做 | 原因 |
| --- | --- |
| 改落库结构（采购明细按 SKU 拆行） | 会连带改动供应商汇总、完成来料登记、导出与全部历史数据；本方案用「算出值 + 差异对照」替代 |
| 新增按 (SKU × 物料) 的率/数量存储 | 与①「同物料联动」的裁决冲突——率与数量仍按物料的**一行**存 |
| 供应商页签（供应商采购订单）改造 | 那是按供应商汇总的采购口径，与「按 SKU 看料」是两件事 |
| 备品口径调整 | 已定案：`ceil(订单数量 × 订单级率‰)`（提交 `01ec0092`），本方案不动 |

## 2. 口径定义

### 2.1 每 SKU 每物料的基准量（口径 A）

```
基准量(SKU, 物料) = 该物料在 SKU 的 BOM 单件用量 × 该 SKU 的 order_qty
```

- **同一 SKU 内的多作用域（角色）重复行照旧累加**——与生成路径一致（同一 BOM 行可能出现在多个角色作用域）；
- **不同 SKU 之间不合并、不去重**：这是展示口径，每个 SKU 各得一份；
- **不含损耗加放**：基准量只到「用量 × 数量」这一步。

### 2.2 屏幕「数量」列的显示值

沿用现状公式：`ceil(基准量 × (1 + 该物料的行损耗率‰))`。

即：基准量由后端给出，**加放由前端按该物料当前的行损耗率实时计算**（与今天订单级行的做法完全同源）——这样用户改率时该列立即变化，无需回后端。

### 2.3 差异判定（对照块是否出现）

按 `(供应商, 物料名, 规格, 单位)` 逐键比较：

```
Σ_SKU 基准量(SKU, 键)   vs   落库 quantity(键)
```

- 容差：`|差| > 0.005` 视为差异（数量落库为 2 位小数，避免浮点尾差误报）；
- **整组任一键存在差异 → 该组渲染对照块**；全部一致 → 该块**完全不出现**（保持表格精简）；
- 对照块展示**该组全部落库物料行**（浅色底），不一致的行**描红**。

### 2.4 与备品的关系

备品仍为口径 A（`ceil(订单数量 × 订单级率‰)`），**不受本方案影响**；它在每个 SKU 块内显示该 SKU 自己的备品（已实现）。

## 3. 后端设计

### 3.1 接口变更（**只增字段，既有字段语义与形状不变**）

`POST /purchase-center/orders/factory-summary` 响应中，`groups[].skus[]` 增加 `materials[]`：

```jsonc
"skus": [
  {
    "product_name": "测试",
    "product_barcode": "6978946330000",
    "order_qty": 10000,
    "materials": [                       // 新增；该 SKU 的物料（**基准量**）
      { "supplier_name": "仓库", "material_name": "漂白边伦", "specification": "仓库", "unit": "码", "quantity": 50 },
      { "supplier_name": "旭日", "material_name": "3mm漂白吉绒", "specification": "C001", "unit": "码", "quantity": 90 }
    ]
  }
]
```

- `quantity` = **基准量**（§2.1），**不含损耗加放**；
- 供应商分组由前端按 `supplier_name` 做（与现状一致）；
- `groups[].suppliers[].fabrics[]`（落库真值 + `item_ids`）**原样保留**——对照块与编辑态都依赖它。

### 3.2 计算实现

在分组构建时（`_build_factory_group_map` 已按 SKU 遍历 BOM、已拿到 `sku_lines` 与该 SKU 的 `pid`），**额外收集**一份按 SKU 的物料列表：

- 复用**同一套物料命名与作用域口径**（`_MATERIAL_SPECS` / `_material_row` 的命名规则，与 F3/F4 同源），确保键与落库明细、与既有 `fabrics` 完全对齐（否则对照块会全行误报）；
- 过滤 `_is_filling_category`（F10）；
- 数量 = `bom['quantity'] × sku_order_qty`；
- 同一 SKU 内多作用域重复行**累加**；
- 按 SKU 归属（而不是像现在那样先合再取并集）。

**性能**：纯内存，遍历规模 = `Σ_SKU (该 SKU 的 BOM 行数)`；**不新增任何数据库查询**（F2 已加载全部所需数据）。汇总接口的读耗时增量与 `groups × skus × BOM行` 同阶，且该接口结果本就有缓存。

### 3.3 降级与兼容

| 场景 | 行为 |
| --- | --- |
| **该组全部 SKU 都无 BOM**（`bom_data` 为空） | 无从展开 ⇒ 整组**回退为现状的订单级单块**（即今天的形态），不显示对照块；单 SKU 单因此天然零回归 |
| **多 SKU 中仅个别 SKU 无 BOM** | **保留块结构**：有 BOM 的 SKU 正常按 SKU 展开；缺 BOM 的那个 SKU 块渲染一条占位行「无 BOM 明细」（不隐藏该 SKU，否则用户会以为漏了它） |
| `po_sku_map` 缺失（旧数据 / 未回填） | `skus` 退回订单级单行（既有行为）⇒ 不触发按 SKU 展开，形态与今天一致 |
| 旧后端不返回 `materials` | 前端按「无该字段」回退现状（零回归） |
| 明细为空（无采购明细） | 照旧（汇总已有兜底） |

## 4. 前端设计

### 4.1 行模型

由「组 × 供应商 × 布料」三级改为 **「组 × SKU × 供应商 × 物料」** 四级：

- 以 `skus[]` 的顺序为块序（与「产品名称」列逐 SKU 的顺序一致）；
- 每块内的供应商顺序沿用既有排序规则（供应商名升序、物料名升序），保证稳定不跳动。

### 4.2 单元格合并（列 → rowspan 范围）

| 列 | 合并范围 |
| --- | --- |
| 客户 | 整组（一组一个客户） |
| 产品名称 / 订单数量 / 备品数量 | **该 SKU 块**（块内第一个物料行起，跨该块全部物料行） |
| 供应商 | 块内**该供应商**的物料行数 |
| 布料名称 / 规格型号 / 损耗率 / 数量 / 单位 | 不合并（一行一条物料） |

### 4.3 率与数量的「同物料联动」（裁决③）

同一物料可能在多个 SKU 块出现，而库里**只有一行**（F6/F7）。**「同一物料」的判定键 = `(供应商, 物料名, 规格, 单位)`** —— 直接复用既有 `summaryMaterialKey`（`useSummaryModal.ts`，工厂页与供应商页同源的那个键），不另造一套：

- **损耗率**：各块显示**同一个值**；任一输入框改动 → 该物料（按 `item_ids` 定位）落库**一次**，且该物料在所有块里的显示值同步更新；
- **数量（编辑态）**：同样联动——改动块 A 中某物料的数量，等价于改订单级那一行，块 B 中同一物料随之变化；
- **必须在编辑态给出可见提示**（裁决⑥ 的连带后果）：编辑态下在该物料的输入框加 `title`/内联提示，文案明示「该物料各 SKU 共用一行，改动会影响所有 SKU」；
- 实现上复用现有 `applyFabricLossRateAndSave` / `updateFactoryQty` 的定位键（`item_ids` 与物料键），**不新增落库契约**。

### 4.4 差异对照块

- 触发：§2.3 判定存在差异时，在**整组末尾**追加；
- 内容：一条浅色横幅（说明「实际下单含手工调整，与上方按 BOM 推算不一致」+ 列出不一致的物料）+ 该组**全部**落库物料行的浅色渲染（不一致者描红）；
- 无差异：不渲染（不占高度）。

### 4.5 打印 / 导出

与屏幕同结构（10 列、每 SKU 一块）——继续共用 `buildFactoryHtml`（列定义已收敛到 `FACTORY_TABLE_HEAD`）。**差异对照块一并输出**（打印件必须与屏幕同源，否则等于隐瞒差异）。

A4 版面：2 SKU × 6 物料 = 12 行，纵向可承载；多 SKU × 多物料的极端单需实测（见 §6 测试）。

### 4.6 组件规模

`SummaryFactoryTab.vue` 现 342 行，本次会显著增长（行模型 + 联动 + 对照块）。**硬门禁 ≤400 行**——预计需要把对照块拆成独立子组件（`SummarySpareDiffBlock.vue` 或类似），本方案允许这一处必要拆分。

## 5. 边界与异常

| 场景 | 行为 |
| --- | --- |
| **单 SKU 单**（`skus` ≤ 1 或缺失） | **走现状路径**：单块、无对照块 —— 与今天逐字一致（零回归锚） |
| 多 SKU 但某 SKU 无物料（BOM 空） | 该块显示「无 BOM 明细」占位行 |
| 同一物料在同 SKU 内多角色重复 | 累加（与生成路径一致） |
| 同一物料跨 SKU | **各块各显示一份**（不合并、不去重） |
| 填充类物料 | 过滤（F10），不出现 |
| 数量为 0 / SKU 数量为 0 | 该行数量 0，照常显示（不隐藏） |
| 率未设 | 率显示 0，数量列 = 基准量 |
| 编辑态 + 差异块并存 | 差异块在编辑态只读（编辑不修改落库真值以外的显示） |
| 落库真值含手改 + 用户在按 SKU 视图里改数量 | 落库行被改 → 差异随之变化（对照块实时反映） |
| 旧后端 / 字段缺失 | 回退现状形态 |

## 8. 风险

| 风险 | 影响 | 处置 |
| --- | --- | --- |
| **BOM 在采购单生成后被改名/删行** | 推算值与落库真值不一致 ⇒ 对照块会常驻显示 | 这正是对照块的价值（把「推算 vs 真值」的差异**显式化**）；若差异长期存在，提示用户核对 BOM |
| 键命名口径漂移（新字段与 `fabrics`/落库明细不一致） | 对照块**全行误报** | 复用同一命名函数；用「键逐字一致」的测试钉死（§6.1） |
| 表格行数膨胀（多 SKU × 多物料） | 屏幕滚动变长、A4 打印变高 | P0 实测单 SKU 与 4 SKU 两种规模；P1 评估横向打印 |
| 联动编辑被误用（以为只改一个 SKU） | 意外改动其它 SKU 的数量 | 编辑态显式提示（§4.3）；后续可考虑「只读快照 + 集中编辑」的更强交互 |
| `SummaryFactoryTab.vue` 越过 400 行门禁 | 门禁红 | 预先拆对照块为子组件（§4.6） |
