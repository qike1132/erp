# ERP系统优化需求规格说明书

## Overview
- **Summary**: 对现有ERP系统进行订单与备货逻辑优化、UI与排版优化、功能增强的综合升级项目
- **Purpose**: 解决当前订单与备货管理中存在的逻辑问题，提升用户体验，增强系统功能
- **Target Users**: ERP系统操作人员、管理员

## Goals
- 优化订单与备货的业务逻辑，确保状态同步与数据一致性
- 改进ERP系统UI界面设计，提升直观性与美观度
- 实现订单与备货的单独新增功能，增强抵扣备货功能

## Non-Goals (Out of Scope)
- 不涉及用户权限系统的修改
- 不增加新的报表功能
- 不改变现有数据库结构（仅在现有表范围内扩展功能）

## Background & Context
- 当前系统：基于Flask的ERP系统，包含产品、订单、备货、出货、库存管理模块
- 现有问题：
  1. 订单与备货状态未同步（如订单状态字段未正确更新）
  2. 备货抵扣功能仅在订单列表页存在入口，无独立新增功能
  3. UI界面较为朴素，布局和排版有待优化
  4. 订单新增时无法直接选择备货进行抵扣

## Functional Requirements
- **FR-1**: 订单创建时可选择关联备货进行抵扣，实时显示抵扣后剩余备货数量
- **FR-2**: 实现独立的备货新增功能（不依赖订单独立创建备货记录）
- **FR-3**: 优化订单状态与备货状态的同步逻辑
- **FR-4**: 改进UI布局，使用卡片式设计优化信息展示
- **FR-5**: 优化表格样式，提升可读性
- **FR-6**: 添加快捷操作按钮，优化工作流

## Non-Functional Requirements
- **NFR-1**: 界面加载速度不受影响
- **NFR-2**: 所有交互操作需在2秒内响应
- **NFR-3**: 兼容主流浏览器（Chrome、Edge）
- **NFR-4**: 保持响应式布局，适配不同屏幕尺寸

## Constraints
- **技术**: Flask + SQLite + Bootstrap 5
- **开发环境**: Windows
- **依赖**: 现有静态资源（bootstrap、css）

## Assumptions
- 用户熟悉现有系统操作流程
- 备货抵扣功能需要在订单创建时或创建后都可使用
- UI优化需保持现有功能逻辑不变

## Acceptance Criteria

### AC-1: 订单状态同步
- **Given**: 创建备货记录并关联订单
- **When**: 备货数量达到或超过订单数量
- **Then**: 订单状态自动从"待备货"更新为"已备货"
- **Verification**: `programmatic`
- **Notes**: 需要修复app.py中订单状态更新逻辑（total_stocked变量未正确定义）

### AC-2: 备货单独新增功能
- **Given**: 用户进入备货管理页面
- **When**: 点击"新增备货"按钮，填写备货信息（不关联订单）
- **Then**: 成功创建独立的备货记录，产品库存增加
- **Verification**: `programmatic`

### AC-3: 订单新增时抵扣备货
- **Given**: 在订单新增界面
- **When**: 用户点击"备货抵扣"选项，选择备货SKU并输入抵扣数量
- **Then**: 实时显示抵扣后剩余的备货数量，确认后订单创建成功
- **Verification**: `programmatic`

### AC-4: UI布局优化
- **Given**: 用户访问ERP系统各功能页面
- **When**: 页面加载完成
- **Then**: 布局采用卡片式设计，表格清晰易读，颜色搭配合理
- **Verification**: `human-judgment`

### AC-5: 快捷操作入口
- **Given**: 用户在订单管理页面
- **When**: 需要快速创建订单
- **Then**: 提供醒目的"新增订单"快捷入口
- **Verification**: `human-judgment`
