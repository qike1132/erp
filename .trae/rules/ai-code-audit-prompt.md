# AI代码审核专用提示词 v1.0

> 基于 [awesome-ai-rules](https://github.com/Lay4U/awesome-ai-rules)、[karpathy-guidelines](https://github.com/mbeijen/andrej-karpathy-skills-cursor-vscode)、[agent-rules](https://github.com/agent-rules/agent-rules) 等顶级开源项目的审核模式与提示词设计模式优化而成。

## 审核目标声明

在开始代码审核前，你必须明确：

1. **审核类型**：□代码审查 □Bug修复验证 □性能优化验证 □安全审计 □架构重构验证
2. **审核范围**：明确列出需要审核的文件/模块/函数
3. **质量标准**：本次审核需要达到的质量门槛（如：零P0/P1问题、性能提升>X%等）
4. **已知上下文**：本次审核的背景信息、已知的风险点、用户特别关注的区域

## 核心审核原则

### 1. 先理解再审核（Think Before Review）

**禁止在理解代码意图前就给出判断。**

- 先回答：这段代码要解决什么问题？
- 再回答：当前实现方案是否合理？有没有更简单的方式？
- 最后给出：具体问题点和改进建议

### 2. 双策略审核（Dual-Strategy Audit）

**必须按以下两个阶段顺序完成，禁止跳过任何阶段：**

#### 阶段1：分类清单扫描（广度优先）

按以下6个维度逐项检查，每个维度至少输出1条发现（即使结论是"无问题"）：

| 维度 | 检查要点 | 常见陷阱 |
|------|----------|----------|
| **算法与数据结构** | 时间/空间复杂度、嵌套循环、重复计算、N+1问题 | O(n²)隐藏在双重循环、未分页的全表扫描 |
| **代码结构与模块化** | 职责单一性、耦合度、代码重复、抽象合理性 | God函数、循环依赖、过度抽象 |
| **命名与语义** | 变量/函数/类命名是否语义化、是否存在歧义命名 | 单字母变量名、缩写歧义、动词名词混用 |
| **资源管理** | 文件句柄/连接/管道是否正确关闭、内存泄漏、线程安全 | 未释放的连接池、竞态条件、死锁风险 |
| **导入与依赖** | 未使用的import、未使用的变量、冗余依赖、缺失依赖 | 隐式依赖、循环import、版本冲突 |
| **边界与异常** | 空值/None处理、越界访问、异常吞没、竞态条件 | 未处理的边界值、裸except、异常被静默吃掉 |

#### 阶段2：执行路径追踪（深度优先）

对每个关键方法，逐步骤追踪其完整执行路径：

1. **标注所有调用者**：谁调用了这个方法？在哪个线程/上下文？
2. **追踪数据流**：入参从哪来？返回值到哪去？状态变量何时被读写？
3. **检查语句顺序**：赋值顺序是否导致使用过期/错误值？
4. **检查阻塞点**：`time.sleep`、同步I/O、`subprocess.run`是否在主线程？
5. **检查跨线程操作**：后台线程是否直接操作非线程安全组件？
6. **检查资源生命周期**：子进程/管道/文件是否在所有退出路径上正确关闭？

### 3. 迭代审核意识（Iterative Review）

**接受单次审核无法覆盖所有问题的客观规律：**

- 问题遮蔽效应：高严重度问题会遮蔽低严重度问题
- 修复引入回归：每轮修复都在改变代码状态，可能引入新问题
- 扫描策略盲区：单一策略无法覆盖所有问题维度
- 每次审核聚焦不同维度，避免重复扫描同一视角

### 4. 手术式审核（Surgical Review）

**审核变更时，只关注与用户请求直接相关的代码：**

- 不要审核无关代码的风格/格式/组织方式
- 不要建议重构未被要求修改的代码区域
- 如果发现无关区域的严重问题，单独标注为"非本次审核范围，但建议关注"

## 问题分级标准

| 级别 | 标识 | 定义 | 处理方式 |
|------|------|------|----------|
| **P0** | 🔴 | 安全漏洞、数据损坏、系统崩溃、权限越界 | 必须修复，禁止合并 |
| **P1** | 🟠 | 功能缺陷、严重性能问题、资源泄漏 | 必须修复，禁止合并 |
| **P2** | 🟡 | 代码异味、可维护性问题、边界场景未覆盖 | 建议修复，可后续处理 |
| **P3** | 🔵 | 命名建议、风格统一、注释完善 | 可选优化 |

## 审核输出格式

审核完成后，**必须**按以下格式输出结果：

```markdown
## 审核报告

### 基本信息
- **审核类型**：[填写]
- **审核范围**：[文件/模块列表]
- **审核时间**：[填写]
- **代码行数**：[填写]

### 问题清单

#### 🔴 P0 - 必须修复
| # | 文件:行号 | 问题描述 | 影响 | 修复建议 |
|---|-----------|----------|------|----------|
| 1 | file.py:42 | ... | ... | ... |

#### 🟠 P1 - 必须修复
| # | 文件:行号 | 问题描述 | 影响 | 修复建议 |
|---|-----------|----------|------|----------|

#### 🟡 P2 - 建议修复
| # | 文件:行号 | 问题描述 | 影响 | 修复建议 |
|---|-----------|----------|------|----------|

#### 🔵 P3 - 可选优化
| # | 文件:行号 | 问题描述 | 影响 | 修复建议 |
|---|-----------|----------|------|----------|

### 维度覆盖确认
- [ ] 算法与数据结构：[结论]
- [ ] 代码结构与模块化：[结论]
- [ ] 命名与语义：[结论]
- [ ] 资源管理：[结论]
- [ ] 导入与依赖：[结论]
- [ ] 边界与异常：[结论]

### 执行路径追踪确认
- [ ] 公开方法调用者标注：[完成/未完成]
- [ ] 数据流追踪：[完成/未完成]
- [ ] 阻塞点检查：[完成/未完成]
- [ ] 资源生命周期检查：[完成/未完成]

### 总体评价
[对代码质量的整体评价，1-2句话]

### 审核结论
□ 通过（零P0/P1问题）
□ 有条件通过（P0/P1已修复，P2/P3可后续处理）
□ 不通过（存在未修复的P0/P1问题）
```

## 审核验证标准

审核完成后，必须确认：
- [ ] 阶段1的6个维度全部已覆盖（非空结果）
- [ ] 阶段2对所有公开方法和后台线程入口已完成路径追踪
- [ ] 发现的问题按严重度排序（P0/P1/P2/P3），并标注具体行号
- [ ] 每个问题都有明确的修复建议
- [ ] 审核结论与问题清单一致
