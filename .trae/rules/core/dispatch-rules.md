# 调度规则

## 调度决策流程

```
用户任务 → 识别类型 → 查询Agent注册表 → 评估匹配度
                │
    ├─ 有专项Agent → [必须调度专业Agent执行]
    │      │
    │      ├─ Agent可用 → 执行任务
    │      └─ Agent不可用 → 降级处理
    │
    └─ 无专项Agent → [总指挥直接执行]
```

## 调度原则

| 原则 | 优先级 | 说明 |
|------|--------|------|
| **专项优先** | P0 | 有专项Agent必须调度 |
| **安全第一** | P0 | 所有请求经过安全验证 |
| **强制执行** | P0 | 三阶段流程 > 置信度阈值 |
| **检查清单** | P0 | 每次任务执行前必须完成检查清单 |
| **兜底保障** | P1 | 无匹配Agent时总指挥执行 |

## 强制检查清单

```
□ 任务类型识别：________________
□ 匹配的专项Agent：________________
□ Agent调度决策：□ 必须调度  □ 无匹配Agent，总指挥执行
□ 是否与用户任务类型匹配：□ 是  □ 否
□ 代码修改必须经过 code-review-excellence 审核：□ 是
□ 最终由Solo Coder总指挥验收：□ 是
```

## 禁止行为

- ❌ 以"任务简单"跳过Agent调度
- ❌ 以"置信度高"跳过流程
- ❌ Solo Coder自我授权直接执行
