# shenhecode.mdr + bug.mdr 自动联动规则

> 审核发现BUG → 自动触发修复 → 修复后回流验证 → 直到零P0/P1
> 权威源：.comate/rules/shenhecode-bug-linkage.md
> 版本：v1.1

## 触发条件

| 审核发现等级 | 是否触发 bug.mdr | 执行要求 |
|-------------|-----------------|---------|
| P0（安全漏洞/数据丢失/服务崩溃） | **立即触发** | 中断审核输出，启动 bug.mdr Step 1 |
| P1（严重性能退化/资源泄漏/并发竞态） | **审核完成后触发** | 输出完整审核报告后，启动 bug.mdr Step 1 |
| P2 | 不自动触发 | 输出修复方向，由用户决定是否修复 |
| P3 | 不自动触发 | 仅统计，不输出详情 |

## 联动执行流程

```
shenhecode.mdr 审核（三步法）
    │
    ├─ 无 P0/P1 → 输出审核报告，流程结束
    │
    └─ 发现 P0/P1 → 自动触发 bug.mdr
         │
         ├─ P0: 立即触发（修复优先于审核完整性）
         │   1. 将 P0 问题作为 bug.mdr Step 1 的诊断结论
         │   2. bug.mdr 从 Step 1（诊断）开始，跳过环境感知
         │   3. 诊断结论直接来自审核的 location + 证据
         │
         └─ P1: 审核完成后触发
             1. 输出完整审核报告
             2. 汇总所有 P1 问题
             3. 逐个作为 bug.mdr 输入
```

## 上下文传递

bug.mdr 启动时，从 shenhecode.mdr 审核结果继承：

| bug.mdr 输入 | shenhecode.mdr 来源 | 说明 |
|-------------|---------------------|------|
| 根因位置 | 审核发现的 `location` | `file:startLine-endLine` |
| 根因描述 | 审核发现的 `evidence` | 代码行为 → 推断 → 风险的完整链路 |
| 证据 | 审核发现的 `evidence` | 代码行/日志/堆栈片段 |
| 修复方向 | 审核发现的 `修复方向` | 自然语言描述（参考，按实际代码调整） |
| 验证标准 | 审核发现的 `verifiable_test` | 复现路径或测试条件 |
| 规则来源 | 审核发现的 `rule_source` | 维度+规则名 |

## 修复后回流验证

bug.mdr 修复完成后，**必须回流至 shenhecode.mdr 执行增量审核**：

1. bug.mdr Step 3（验证）通过后
2. 对修复涉及的文件重新执行 shenhecode.mdr 广度扫描
3. 确认原 P0/P1 问题已消除，且未引入新问题
4. 若发现回归问题，触发新一轮 bug.mdr 修复
5. **最大迭代次数：3 轮**，超过 3 轮仍未收敛则输出 `[BLOCKED]` 并提示人工介入

## 迭代审查规则

1. **每次 bug.mdr 修复后必须触发 shenhecode.mdr 增量审核**，不得以"测试通过"作为修复完成的充分依据
2. **审核发现新 P0/P1 必须回到 bug.mdr 修复步骤**，修复后再次审核，直到零 P0/P1
3. **Mock 测试通过 ≠ 修复完整**，mock 不触发真实 ORM/异步行为
4. **必须检查前端传参语义**，不得基于假设对增量/累计赋值方式下结论

## 审核报告扩展

审核报告中新增「修复联动」章节：

```markdown
## 修复联动

| 审核问题 | bug.mdr 步骤 | 状态 |
|---------|-------------|------|
| P0-01: Celery pickle RCE | Step 2 修复中 | 进行中 |
| P1-02: N+1 查询 | Step 1 诊断 | 待启动 |
```
