## 2. 多框架集成架构方案

### 2.1 可行的集成模式

#### 2.1.1 模式一：API Gateway 模式（推荐）

```
架构特点:
├── 统一入口: Nginx/ Kong/ Traefik 作为 API Gateway
├── 服务隔离: 各框架独立进程，互不干扰
├── 路由分发: 根据URL路径分发到不同服务
└── 资源共享: 共享数据库、缓存、配置

优点:
✅ 各框架独立运行，互不影响
✅ 可独立部署、扩展、升级
✅ 故障隔离，单服务故障不影响整体
✅ 技术栈灵活，可按需选择

缺点:
⚠️ 运维复杂度增加
⚠️ 需要统一认证机制
⚠️ 服务间通信需要处理
```

#### 2.1.2 模式二：嵌入式集成模式

```python
架构特点:
├── 主框架: Flask 作为主应用
├── 嵌入服务: FastAPI 作为 WSGI 应用嵌入
├── 共享进程: 同一进程内运行
└── 共享上下文: 共享数据库连接、配置

实现示例:
from flask import Flask
from fastapi import FastAPI
from fastapi.middleware.wsgi import WSGIMiddleware

flask_app = Flask(__name__)
fastapi_app = FastAPI()

# FastAPI 嵌入到 Flask
flask_app.wsgi_app = WSGIMiddleware(fastapi_app)

优点:
✅ 部署简单，单一进程
✅ 共享资源方便
✅ 运维成本低

缺点:
⚠️ 性能相互影响
⚠️ 故障无法隔离
⚠️ 不利于独立扩展
```

#### 2.1.3 模式三：微服务模式

```
架构特点:
├── 服务拆分: 按业务域拆分为独立服务
├── 独立部署: 每个服务独立部署运行
├── 服务发现: 使用 Consul/ Nacos 等服务发现
└── 消息队列: 服务间通过消息队列通信

优点:
✅ 高度解耦
✅ 独立扩展
✅ 技术栈自由

缺点:
⚠️ 架构复杂度高
⚠️ 运维成本高
⚠️ 对20人规模过于复杂
```

### 2.2 推荐方案对比

| 方案 | 复杂度 | 适用规模 | 推荐度 |
|-----|-------|---------|-------|
| API Gateway | 中等 | 20-200人 | ⭐⭐⭐⭐⭐ |
| 嵌入式集成 | 低 | <50人 | ⭐⭐⭐ |
| 微服务 | 高 | >100人 | ⭐⭐ |

**针对20人规模，推荐采用 API Gateway 模式**。

#### 3.2.3 认证层共享

```python
共享方案:
┌─────────────────────────────────────────────────────────────┐
│                    统一认证架构                              │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  方案一: JWT Token (推荐)                                   │
│  ┌─────────────────────────────────────────────────────┐   │
│  │  用户登录 → Flask/FastAPI 生成 JWT Token             │   │
│  │  前端存储 Token → 请求携带 Token                      │   │

│                                                             │
│  方案二: Session + Redis (兼容方案)                         │
│  ┌─────────────────────────────────────────────────────┐   │
│  │  用户登录 → Flask 创建 Session                        │   │
│  │  Session 存储到 Redis                                │   │
│  │  各服务从 Redis 读取 Session                          │   │
│  └─────────────────────────────────────────────────────┘   │
│                                                             │
└─────────────────────────────────────────────────────────────┘

JWT 实现示例:
# shared_auth.py
from jose import jwt, JWTError
from datetime import datetime, timedelta

SECRET_KEY = "your-shared-secret-key"
ALGORITHM = "HS256"

def create_token(user_id, permissions):
    expire = datetime.utcnow() + timedelta(hours=24)
    return jwt.encode(
        {"sub": user_id, "perms": permissions, "exp": expire},
        SECRET_KEY,
        algorithm=ALGORITHM
    )

def verify_token(token):
    try:
        payload = jwt.decode(token, SECRET_KEY, algorithms=[ALGORITHM])
        return payload
    except JWTError:
        return None

# Flask 使用
from shared_auth import create_token, verify_token

# FastAPI 使用
from shared_auth import verify_token
from fastapi import Depends, HTTPException
from fastapi.security import OAuth2PasswordBearer

oauth2_scheme = OAuth2PasswordBearer(tokenUrl="token")

async def get_current_user(token: str = Depends(oauth2_scheme)):
    payload = verify_token(token)
    if not payload:
        raise HTTPException(status_code=401)
    return payload
```

## 4. 技术栈整合可能性

│  4. 页面请求 → Session 验证                                 │
│  5. API请求 → JWT 验证                                      │

实现代码:
# Flask 登录处理
@app.route('/login', methods=['POST'])
def login():
    user = authenticate(username, password)
    if user:
        # 创建 Session
        session['user_id'] = user.id
        session['permissions'] = user.permissions
        
        # 生成 JWT Token (供 API 使用)
        token = create_jwt_token(user.id, user.permissions)
        
        return jsonify({
            'success': True,
            'token': token  # 前端存储此 token
        })

# FastAPI API 验证
@router.get("/api/products")
async def get_products(user = Depends(verify_jwt_token)):
    # user 已通过 JWT 验证
    return await Product.all()
