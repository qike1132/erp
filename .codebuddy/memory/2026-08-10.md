## pattern-room 布局恢复：诊断与修复

**问题**：用户发现 `http://192.168.0.95:3000/pattern-room` 的 UI 布局变了，不再是之前设置的左右分栏布局。

**诊断过程**：
1. 检查 git 历史 — 仅一个提交 `5e6964f`（8月6日），内容是旧的 Tab 式布局（布局 A）
2. 检查暂存区 — 发现 21 个文件变更，正是用户想要的左右分栏布局（布局 B）
3. 验证布局 B 的 25 个导入项完整性 — 全部通过（9组件 + 4本地composable + 3全局composable + 2API + 7类型）

**根因**：布局 B 的代码一直在工作目录和暂存区中，但从未被提交。旧提交 `5e6964f` 包含的是布局 A。如果服务器按 Git 构建部署，就会显示布局 A。

**修复**：
- `git commit` 提交暂存区改动 → commit `9aed69b`
- 终止旧 Vite dev server (PID 18156) 并重启 → PID 22972，监听 `0.0.0.0:3000`

**发现第二个问题**：`CustomerGroupList.vue` 第 128 行 `(defineProps as any).groups` 在 watch 闭包内错误使用编译宏 `defineProps`，导致 `defineProps is not defined` 运行时错误，组件渲染失败。

**修复（94a5b7f）**：
- `defineProps` 返回值存入 `const props`
- `watch` 改用 `props.groups`
- `import { watch }` 移到文件顶部 import 区
