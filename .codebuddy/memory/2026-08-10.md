## pattern-room 部位布料新增不显示：get_parts_by_version 修复

**问题**：用户在 `http://192.168.0.95:3000/pattern-room` 点击"新增部位"提交后，右侧"部位布料"表格（跨版本二维表）不显示新提交的部位。截图显示 badge "2"、T2/T3 的"身体"数据可见，但用户刚添加的部位（如"头部"）不出现。

**根因**：`get_parts_by_version` 服务函数**只从 `customer_sampling_fabric_version.snapshot_data` JSONB 字段读取所有版本数据**。但 `snapshot_data` 仅在 `create_version` 调用时才会重新生成。新增部位只写入 `customer_sampling_part` 表（活跃数据），**不会**自动更新 `current_version` 的 `snapshot_data`。所以 `get_parts_by_version` 查不到新部位，前端表格自然不显示。

**修复**（修改 `fastapi_app/services/customer_sampling_service.py` 第 1064-1128 行，`get_parts_by_version` 单函数，+32/-5 行）：
- 加载项目 `current_version`
- 预加载当前版本活跃部位（带 supplier 关联）
- 对 `current_version`：**实时**从 `customer_sampling_part` 表读取（保证新增/编辑/删除立即可见）
- 对其他历史版本：保持从 `snapshot_data` 读取（保留历史快照不可变设计原则，spec 5.5.1.6）

**为什么这样修**：
- 最小改动：只改一个 service 函数，不改 API/前端/schema
- 同时修复了"编辑/删除当前版本部位后不刷新"的同类问题
- 保留了"历史版本快照不可变"的核心设计

**验证**：
- `read_lints` 无错误
- 39 个 service 单元测试（TestNextVersion/TestNormalizeValue/TestComputeDiff/TestServiceMockErrors）全部通过
- 8 个 ServiceIntegration 测试失败是数据库连接问题（asyncpg Event loop is closed），与本次修改无关

**未来参考**：
- 当一个功能依赖"快照 + 当前活跃数据"双源时，查询接口应对 current 实时读、对历史从快照读，而不是把 current 也强制从快照读
- `customer_sampling_part`（活跃数据） vs `customer_sampling_fabric_version.snapshot_data`（历史快照）的边界要分清
- 修改 snapshot_data 写入路径不一定合适 —— 改为读取路径合并两源更干净

**验证**：`npm run type-check` 和 `npm run lint` 均通过。
