## pattern-room 新增打样项目后不显示 BUG 修复（完整）
- **第一轮根因（误判，已修复）**：`CustomerGroupList.vue` 双栏布局，右侧只显示选中客户的项目。`selectedCustomerKey` 是内部状态，新建项目后 `selectedProjectId` 仅用于高亮，不切换客户分组。新项目归入"未分类"时右侧看不到。
- **第二轮根因（真实，截图证实）**：用户截图显示 4 个客户分组正常加载、MINISO国际 active，但右侧项目区域**完全空白**（无加载中、无空状态、无错误）。唯一解释是模板中 `<VirtualList v-else-if="projectAreaHeight > 0">` 条件未满足 + **没有 v-else 兜底**。
- **真实根因**：`projectAreaHeight` 测量失败（保持为 0）。原实现只在 `onMounted` 同步读 `clientHeight`，但父级 flex 链在数据从空数组→有数据时才完成布局（loading→hasData 切换、cgl-body v-else 显隐），此时 `.cgl-project-area` 自身尺寸可能没变，ResizeObserver 不会触发，父级尺寸变化也没被监听。
- **完整修复**：
  1. 模板：添加 `v-else` 兜底分支（"加载中..." spinner），任何边界失败都有反馈而非空白
  2. `measureProjectArea`：改用 `offsetHeight || getBoundingClientRect().height`（更准确）
  3. `tryMeasureWithRetry`：同步 + nextTick + rAF 三重测量，覆盖异步布局完成时点
  4. ResizeObserver 同时监听自身 + 父级（`cgl-body`），覆盖父级尺寸变化导致漏触发的盲区
  5. 监听 `window.resize`（窄屏切换、抽屉展开/收起）
  6. `watch(props.groups)` 主动测量（首次加载 / 新增后 groups 从空→非空触发 v-else 分支切换）
  7. `onUnmounted` 清理所有 observer 和 listener
- 文件：`frontend-vite/src/views/pattern-room/components/CustomerGroupList.vue`
- **教训**：模板 `v-if/v-else-if` 链必须有 `v-else` 兜底，否则任意分支失败都导致完全空白；高度测量依赖 ResizeObserver 不够，必须配合 nextTick/rAF 主动重试

## Git EPERM worktree 残留修复
- **现象**：Git 操作报 `EPERM: operation not permitted, open '.git\worktrees\37017f14-ba77-4c36-bb12-dfd83d186e39\HEAD'`
- **根因**：`ERP服务器管理器_v5.19.exe`（freebuff daemon，PID 15136/19384，自 8月10日起常驻）持有已删 worktree `37017f14` 的文件句柄，导致：
  - 目录处于 pending-delete 中间态（MFT 目录项残留，访问 ACCESS_DENIED）
  - `takeown`/`icacls`/`rd` 全部失败（底层 CreateFile 打不开句柄）
  - 只有 `git worktree prune` 遍历到该目录时才 fatal，主仓库 status/log/branch/add 正常
- **修复**：终止两个 `ERP服务器管理器_v5.19.exe` 进程释放句柄 → Remove-Item 删除残留目录 → 删除孤儿分支 `freebuff/task-37017f14-ba77-4c36-bb12-dfd83d186e39`
- **残留**：MFT 幽灵目录项可能仍存在（`Get-ChildItem` 父目录时可见但 `Test-Path` 返回 False + Access denied），需 `chkdsk d: /f` 彻底清理，但不影响 Git 日常使用
- **教训**：Windows 上 worktree 残留 EPERM，先查 `Get-CimInstance Win32_Process` 找长期常驻的 daemon 类进程（freebuff/ERP 管理器），而非直接 takeown

## 二次处理：MFT 幽灵目录项，已安排重启 chkdsk
- **现象**：终止 ERP 进程后，`37017f14` 目录仍残留为 MFT 幽灵目录项 —— 父目录 `Get-ChildItem` 能看到，但 `Test-Path`/`Remove-Item`/`cmd rd`/`.NET Directory.Delete`/`takeown`/`icacls` 全部 ACCESS_DENIED 或无法删除

## 登录跳转空白页修复（全局路由导航 loading）
- **现象**：点击登录后 1-2 秒空白页，才显示"加载中"，最后到 /dashboard
- **根因**：`/dashboard` 是 `/`（DefaultLayout）子路由，两者均懒加载。`router.push('/dashboard')` 后，DefaultLayout chunk 就绪时 App.vue 的 `<router-view>` 切换到 DefaultLayout，但其内部 `<router-view>`（第7行）等待 DashboardView chunk 下载期间渲染为空 → 空白。空白期 = chunk 网络下载时间
- **方案**：在 `App.vue` 添加全局路由导航 loading 遮罩，覆盖懒加载 chunk 下载期
  - `router.beforeEach` 启动 loading（150ms 延迟，已缓存路由瞬时切换不闪烁）
  - `router.afterEach` + `router.onError` 清除 loading
  - 全屏遮罩（z-index 9999）+ 居中 spinner + "正在进入系统…"，复用 `--color-surface` 等现有 CSS 变量
  - `<Transition>` 淡入淡出，体验平滑
- **改动文件**：仅 `frontend-vite/src/App.vue`（新增 script setup + template 遮罩 + style）
- **验证**：lint 0 错误
- **效果**：登录页"登录中…"按钮 → 全屏 loading 遮罩 → dashboard"数据加载中"，全程无空白

## 登录后 0.5s 加载动画延迟优化

## 登录跳转问题深度修复（加载后不跳转/无错误提示）
- **现象**：点击登录后 loading 显示 1-2 秒结束，不跳转，无错误提示
- **排查过程**：review 全部前后端代码，逻辑上所有路径都可达；`getErrorMessage` 始终返回非空字符串；问题无法直接定位
- **修复内容**（4 个文件）：
  1. **`App.vue`**：删除 `router.onError()` 注册——Vue Router 4 中 `onError` 返回 `void`，`removeError` 为 `undefined`，不能作为 cleanup 函数。`beforeEach`/`afterEach` 返回的 cleanup 函数正常保留
  2. **`authStore.setUserInfo`**：入参改为 `UserInfo | null | undefined`，增加类型校验（非 object返回 null，permissions 用 `Array.isArray` 兜底），防止异常数据静默失败

  4. **`useLogin.ts`**：分离关注点——登录成功后先 `authStore.setUserInfo(res.user)` 写入用户数据，再 `authStore.init(true)` 初始化；新增 4 条 `console.log/error` 诊断日志追踪完整流程

- **诊断**：修复后已验证通过。登录流程日志：`[Login] API 响应成功, has_user: true` → `已通过登录响应设置用户信息` → `authStore.init 完成, loaded: true` → `跳转到: /dashboard`。整体耗时 ~700ms（auth-api 661ms + init 38ms），跳转流畅无空白。
- **经验**：引入新参数（`preloadedUserInfo`）不如让 store 自检测 `user.value` 判断是否需 fetchUser——更简洁、回退路径天然可靠

## 登录流程继续优化（nav-sections 非阻塞 + Redis pipeline）
- **目标**：消除 `auth-store-init: 38ms` 的 nav-sections 等待，让登录到仪表盘跳转更快
- **后端优化**（`auth.py:193-197`）：两个 Redis `incr` 调用（burst + window）从串行改为 pipeline 批量发送，省一次网络 RTT
- **前端核心改动**（`auth.ts:65-76`）：`init()` 在 user 就绪后立即设 `loaded = true`，nav-sections 改为 `fetchNavSections().catch(...)` 非阻塞后台加载，不再 await
  - 登录场景：user 已通过 `setUserInfo` 预加载 → `loaded = true` 同步生效 → `init(true)` 立即返回 → 路由跳转不被 nav-sections 阻塞
  - 刷新场景：`fetchUser()` 完成 → `loaded = true` → 导航继续，nav-sections 后台加载
- **路由守卫适配**（`router/index.ts:174`）：权限检查增加 `authStore.navSections.length > 0` 前置条件——nav 未加载时放行（非阻塞门），nav 加载完成后侧边栏自然过滤不可见项

- **安全性**：nav 未加载时放行非超级用户的权限检查是安全的——侧边栏本身就依赖 nav-sections 渲染，用户看不到未授权的导航项
- **验证**：后端导入 OK，前端 3 文件 lint 0 错误
