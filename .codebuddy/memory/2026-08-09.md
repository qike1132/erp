## beile-order 输入时页面跳动修复（appendTo body → inline）

**问题**：输入关键字后整个页面上下跳动。

**根因**：`.page-card-main` 有 `overflow: hidden`，`UiAutocomplete` 硬编码了
`appendTo="body"`——下拉面板渲染到 `<body>` 末尾。每次输入触发 suggestions
更新，PrimeVue 在 body 上增删/更新 overlay DOM → 触发 body 级 layout
recalculation → 页面跳动。

**方案**：让 beile-order 的 autocomplete overlay 渲染在组件树内（不 appendTo body），
避免 body 级 DOM 变动。

**改动**：

*UiAutocomplete.vue*（+3 行）：
- 新增 `appendTo?: string` prop，默认 `'body'`（保持其他 4 处调用向后兼容）
- template 改为 `:appendTo="(appendTo as string | undefined)"`

*BeileOrderView.vue*（+2 行）：
- 两个 `UiAutocomplete` 各加 `:appendTo="undefined"`，overlay 在组件树内渲染

**注意**：`UiAutocomplete` 的其他调用者（StockOutTab、ProductListView、
CustomerOrderView、CaseStockTab）不受影响，appendTo 仍默认 `"body"`。

## beile-order 页面跳动终极修复（4 角度综合分析）

**遗留问题**：上轮 `:appendTo="undefined"` 改动未解决问题——overlay 在组件树内
被 `.page-card-main { overflow: hidden }` 裁剪，下拉根本不可见；跳动画因未解决。

**4 角度分析**：

1. **CSS position/overflow/transform**：`appendTo="body"` 将 overlay Teleport 到
   body 末尾。`.page-card { transition: transform 0.4s }`，body 级 DOM 变动
   引起微小的尺寸变化被动画放大显示。

2. **父容器高度变化**：`.page-card-header { align-items: center }`，
   overlay 在 body 的 DOM 变动可触发 header 内 flex 子项重新居中对齐。

3. **滚动条 CLS**：`body { overflow-y: auto }`，无 `scrollbar-gutter`。
   PrimeVue overlay append 到 body → document.body.scrollHeight 重算 →
   滚动条出现/消失 → 视口宽度变化（100vw ↔ 100vw-6px）→ 卡片横向+纵向偏移。

4. **contain 隔离缺失**：`.page-card` 无 `contain`，无法阻断 body 级重排传播。

**最终方案（2 文件，6 行改动）**：

*app.css*（+2）：
```css
body { scrollbar-gutter: stable; }
```
始终预留滚动条空间，彻底消除 viewport 宽度 CLS。对所有页面有益。

*BeileOrderView.vue*：
- 移除 `:appendTo="undefined"`（2 行删），恢复默认 `"body"` Teleport
- `.bo-container` 加 `contain: layout style`（隔离 body DOM 变动不内传）
- `.bo-container` 加 `overflow-anchor: none`（禁用滚动锚定干扰）
