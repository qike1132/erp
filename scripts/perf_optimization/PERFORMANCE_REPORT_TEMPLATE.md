## 2. 优化措施摘要

| # | 优化措施 | 影响范围 |
|---|---------|---------|
| 1 | 部分索引 `WHERE is_deleted IS NOT TRUE` + 覆盖排序 | 订单/库存列表查询 |
| 2 | keyset 分页 (深翻页 O(1)) | 翻页 > 100 页场景 |
| 3 | 虚拟滚动表格 (仅渲染可视区域) | 前端大数据量渲染 |
| 4 | 智能预取下一页 (TanStack Query prefetch) | 翻页体验优化 |
| 5 | 前端 L1+L2 多级缓存 | 字典/列表数据二次加载 |
| 6 | 事件委托替代 N 个监听器 | 列表操作性能 |
| 7 | pg_trgm GIN 索引 | 模糊搜索走索引 |
| 8 | 缓存 TTL 优化 (local_ttl 15s→30s) | 热点数据缓存命中 |

## 9. 后续性能监控与持续优化建议

### 9.1 监控部署架构

```
[Prometheus] ← 抓取 /metrics → [FastAPI App]
     ↓
[Grafana] → 可视化面板
     ↓
[AlertManager] → 告警通知
```

### 9.2 关键监控指标

| 指标 | 告警阈值 | 说明 |
|------|---------|------|
| `http_request_duration_seconds` P95 | > 500ms | API响应时间 |
| `slow_query_total` | > 10/min | 慢查询计数 |
| `db_connections_active` | > 40 | 连接池使用率 |
| `cache hit rate` | < 70% | 缓存命中率 |
| 前端 LCP | > 2.5s | 最大内容绘制 |
| 前端 FID | > 100ms | 首次输入延迟 |

### 9.3 持续优化路线图

1. **短期** (1周内): 部署数据库索引 + 缓存TTL调优 + 虚拟滚动
2. **中期** (1月内): keyset分页 + 读写分离验证 + Prometheus告警
3. **长期** (持续): 数据归档策略(>1年数据冷存储) + 查询自动优化(pg_stat_statements分析) + 前端性能预算(performance budget)

### 9.4 数据归档建议

当数据量超过 100,000 条时，建议：
- 超过1年的已完成订单归档到 `order_archive` 表
- 使用 PostgreSQL 表分区 (按月/季) 自动管理
- 冷数据使用压缩存储 (TOAST + LZ4)
