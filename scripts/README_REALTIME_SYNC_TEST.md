# 实时同步功能测试指南

本指南将帮助您验证 ERP 系统与 Dashboard 之间的实时同步功能是否正常工作。

## 📋 前置条件

1. **后端服务正在运行**：确保 FastAPI 后端已启动
2. **Dashboard 页面已打开**：在浏览器中打开 dashboard-preview
3. **浏览器控制台已打开**：按 F12 打开开发者工具，观察 Console 标签
4. **数据库中有测试数据**：确保有产品和库存数据

## 🚀 快速开始

### 1. 单次出库测试

打开一个新的终端窗口，执行：

```bash
cd d:\erp_system
python scripts\simulate_stockout.py
```

脚本会自动：
- 选择一个有库存的产品
- 执行出库操作
- 清理 dashboard 缓存
- 发送 WebSocket 实时通知

### 2. 指定产品测试

如果您想测试特定产品（如之前的鲨鱼产品 ID=20409）：

```bash
python scripts\simulate_stockout.py --product-id 20409 --quantity 50
```

### 3. 批量测试（连续出库）

测试连续多次出库的同步效果：

```bash
python scripts\simulate_stockout.py --batch 3
```

### 4. 查看帮助

```bash
python scripts\simulate_stockout.py --help
```

## ✅ 验证清单

执行出库脚本后，请按以下步骤验证：

### A. 脚本端验证

- [ ] 脚本显示 "开始模拟出库操作..."
- [ ] 脚本显示产品信息和出库预览
- [ ] 脚本显示 "✓ 出库操作完成！"
- [ ] 脚本显示 "✓ Dashboard 缓存已清理"
- [ ] 脚本显示 "✓ WebSocket 事件已发布"
- [ ] 没有红色错误信息

### B. 浏览器端验证

打开浏览器的开发者工具（F12），观察 Console 标签：

- [ ] 控制台显示 `[WebSocket] 连接已建立`（表示WebSocket已连接）
- [ ] 控制台显示 `[WebSocket] 收到消息: stock_changed`（表示收到事件）
- [ ] 控制台显示 `[WebSocket] 检测到数据变更，自动刷新`（表示触发刷新）
- [ ] 页面显示 Toast 提示 "数据已更新"（蓝色提示框）
- [ ] 页面数据自动刷新，无需手动点击

### C. Dashboard 数据验证

观察 dashboard 页面的数据变化：

- [ ] **出库总览**："今日出库数量" 和 "今日出库金额" 应该增加
- [ ] **订单总览**：如果是关联订单的出库，订单状态可能更新
- [ ] **最新更新时间**：页面底部的更新时间应该刷新
- [ ] **同步状态指示器**：状态显示为 "实时同步中"（绿色）

## 🚨 常见问题排查

### 问题 1: 页面不自动刷新

**可能原因**：
- WebSocket 连接断开
- 事件没有正确发布
- 浏览器缓存没有被绕过

**解决方法**：
1. 检查控制台是否有 WebSocket 错误
2. 确认脚本显示 "✓ WebSocket 事件已发布"
3. 检查网络标签页，确认 API 请求没有缓存（应该有 `_t` 参数）

### 问题 2: 数据没有更新

**可能原因**：
- 缓存没有失效
- 数据库查询没有返回新数据

**解决方法**：
1. 手动刷新页面试试
2. 检查后端日志，确认缓存失效是否执行
3. 直接访问 API 验证数据是否正确

### 问题 3: WebSocket 连接失败

**可能原因**：
- 后端服务没有启动
- 端口不对
- Origin 限制

**解决方法**：
1. 确认后端服务在 5000 或 5002 端口运行
2. 检查浏览器控制台的连接错误
3. 检查后端 WebSocket 相关日志
