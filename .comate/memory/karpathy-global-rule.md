## 强制规则：所有编码任务必须遵守 Karpathy Guidelines

**Why:** 用户明确要求将 Karpathy 设置为全局默认规则。此前多次违反这些原则导致引入了不必要的问题（如给不需要缓存的接口加缓存、过度工程化等）。

**How to apply:**

1. **Think Before Coding** — 动手前必须明确假设。不确定就停下来问，绝不沉默地做选择。如果多种解读存在，列出所有解读再选择。发现 YAGNI 冗余必须主动指出。

2. **Simplicity First** — 只写解决问题所需的最少代码。不为"未来扩展性"加抽象层。不添加没被要求的功能。如果 50 行能搞定，绝不写 200 行。自问："资深工程师会说这过度复杂了吗？"如果是，简化。

3. **Surgical Changes** — 只改必须改的。不"顺手"改旁边代码、注释、格式。匹配已有风格。自己造成的孤儿代码要清理，但不删除预先存在的死代码。每行改动必须能追溯到用户需求。

4. **Goal-Driven Execution** — 把任务转化为可验证的目标。多步任务先列简要计划，每步有验证标准。强标准让自己能独立循环验证，弱标准需要反复确认。

### 典型违规案例（必须避免）

- 用户要求"消除延迟"，结果加了缓存（没被要求），然后为解决缓存问题又加了跨进程失效机制（没被要求），最终缓存本身就是延迟来源
- 正确做法：先检查旧代码为什么不延迟 → 发现旧代码不缓存 → 直接查库即可，改动量接近零
