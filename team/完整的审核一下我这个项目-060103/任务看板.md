> 状态机：`pending → claimed → in_progress → completed｜failed｜cancelled`；`rework` 为 review 返工过渡态。**完整枚举（7 个）**：`pending`、`claimed`、`in_progress`、`completed`、`failed`、`cancelled`、`blocked-by-user-decision`；**终态** = `completed` / `failed` / `cancelled`。依赖只认上游 `completed`。review/requirements 只有 `verdict=pass` 才 `completed`；非 pass 自动开 `repair-N` + `review-N+1`。
>
> **`blocked-by-user-decision` 与 `conditional` 的关系**：`blocked-by-user-decision` 是**非终态**，**仅** `conditional: true` 的任务可用 —— 依赖已满足，但**必须等用户显式裁定**才可 claim；裁定「启动」⇒ 转 `pending`，裁定「不启动 / 撤销」⇒ 转 **`cancelled`（终态）**。该状态**不得**计入 `pending` 的可启动集合，也**不得**计入 `completed`。
>
> **`cancelled` 与 `conditional` 的关系**：`cancelled` 是**终态**，表示任务被显式撤销（如用户裁定条件任务不触发）；条目**保留**以维持 DAG 与审计轨迹，不参与调度、不计入完成。
