## 编写指南

### 设计原则
1. **聚焦HOW**: 描述如何实现，而非做什么
2. **架构优先**: 先整体架构，后局部细节
3. **接口清晰**: 明确模块间接口和契约
4. **可实施性**: 设计应可直接指导编码

### 图表使用
- 架构图: 使用Mermaid的graph或flowchart
- 时序图: 使用Mermaid的sequenceDiagram
- ER图: 使用Mermaid的erDiagram
- 状态图: 使用Mermaid的stateDiagram

### 文档质量检查
- [ ] 架构图清晰展示系统结构
- [ ] 所有接口都有明确定义
- [ ] 数据模型完整
- [ ] 异常处理覆盖全面
- [ ] 性能和安全考虑充分
