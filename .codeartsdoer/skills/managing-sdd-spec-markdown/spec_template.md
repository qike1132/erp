# 需求规格文档模板

## 文档结构

### 1. 概述部分
```markdown
## 概述
- **摘要**: [简要描述功能/问题]
- **目的**: [文档目的]
- **目标用户**: [目标用户群体]
```

### 2. 目标与非目标
```markdown
## 目标
- [目标1]
- [目标2]
- [目标3]

## 非目标（超出范围）
- [非目标1]
- [非目标2]
```

### 3. 背景与上下文
```markdown
## 背景与上下文
- [背景信息1]
- [背景信息2]
- [技术栈信息]
```

### 4. 功能需求
```markdown
## 功能需求
- **FR-1**: [需求描述，使用EARS格式]
- **FR-2**: [需求描述]
- ...
```

### 5. 非功能需求
```markdown
## 非功能需求
- **NFR-1**: [性能需求]
- **NFR-2**: [安全需求]
- **NFR-3**: [可用性需求]
- ...
```

### 6. 约束与假设
```markdown
## 约束
- **技术**: [技术约束]
- **业务**: [业务约束]
- **依赖**: [依赖约束]

## 假设
- [假设1]
- [假设2]
```

### 7. 验收标准
```markdown
## 验收标准

### AC-1: [验收标准标题]
- **给定**: [前置条件]
- **当**: [触发动作]
- **那么**: [预期结果]
- **验证**: [验证方式]

### AC-2: [验收标准标题]
...
```

### 8. 开放问题
```markdown
## 开放问题
- [ ] [待确认问题1]
- [ ] [待确认问题2]
```

## 编写指南

### 需求描述原则
1. **聚焦WHAT，而非HOW**: 描述需要什么功能，而非如何实现
2. **使用EARS格式**: 确保需求清晰、可测试
3. **原子性**: 每个需求只描述一个功能点
4. **可验证性**: 每个需求都应有对应的验收标准

### 验收标准编写原则
1. **完整性**: 覆盖所有功能需求
2. **明确性**: Given-When-Then格式清晰
3. **可测试性**: 明确验证方式
4. **独立性**: 每个验收标准独立验证

### 文档质量检查
- [ ] 所有功能需求都有对应验收标准
- [ ] 所有需求使用EARS格式
- [ ] 目标与非目标清晰界定
- [ ] 约束和假设明确列出
- [ ] 开放问题已记录
