# 订单抵扣备货BUG修复总结

## 问题描述
在订单管理系统中发现一个功能性BUG：当在订单管理模块新增加订单并应用抵扣备货操作后，备货管理模块中的剩余数量未能实时更新并显示抵扣后的正确数值。

## 问题根因
批量提交订单API (`/api/batch-submit-orders`) 缺少抵扣备货的处理逻辑，导致通过该API创建的订单无法自动抵扣备货，备货管理模块的剩余数量无法实时更新。

## 业务逻辑说明

### 订单抵扣备货的正确流程
1. **订单抵扣备货** → 直接扣减备货库存
2. **不创建出货记录** → 抵扣操作不经过出货管理
3. **备货管理显示** → 剩余数量 = 备货数量 - 已抵扣数量

### 技术实现方式
- 创建 `StockOut` 记录仅用于记录抵扣关系（内部使用）
- 通过特殊的 `note` 标识 `[订单抵扣]` 区分抵扣记录和真正的出货记录
- 出货管理页面过滤掉订单抵扣记录，只显示真正的出货

## 修复方案

### 1. 提取抵扣逻辑为独立函数
创建了 `process_order_deduction()` 函数，将订单抵扣备货的核心逻辑提取为独立的可复用函数。

**函数签名：**
```python
def process_order_deduction(order, product_id, order_quantity, deduct_stock=True, custom_deduct_quantity=None):
    """
    处理订单抵扣备货的核心逻辑
    
    参数:
        order: Order对象，订单实例
        product_id: int，产品ID
        order_quantity: int，订单数量
        deduct_stock: bool，是否执行抵扣，默认True
        custom_deduct_quantity: int，自定义抵扣数量，None表示抵扣全部
    
    返回:
        int: 实际抵扣的总数量
    """
```

**功能特性：**
- 按FIFO原则（先进先出）从备货记录中抵扣
- 正确计算已抵扣数量，避免重复抵扣
- 创建StockOut记录（仅用于内部记录，使用 `[订单抵扣]` 标识）
- 根据抵扣结果更新订单状态（已备货/部分备货/待备货）
- 创建InventoryLog记录
- 更新Product.current_stock

### 2. 修改批量提交订单API
在 `/api/batch-submit-orders` API中添加了抵扣备货的处理逻辑：
- 解析前端传递的 `deductStock` 参数
- 解析前端传递的 `deductibleQuantity` 参数（自定义抵扣数量）
- 在创建订单后调用 `process_order_deduction` 函数
- 正确处理抵扣失败的情况

### 3. 重构单个订单提交逻辑
修改了单个订单提交的抵扣逻辑，使用新创建的独立函数，保持功能不变，代码更简洁、可读性更好。

### 4. 修改出货管理页面
在 `/stockouts` 路由中添加过滤条件：
- 过滤掉 `note` 以 `[订单抵扣]` 开头的记录
- 只显示真正的出货记录
- 确保订单抵扣操作不会出现在出货管理中

### 5. 修复数据库字段长度问题
扩展了以下数据库字段长度：
- `inventory_log.related_id`: VARCHAR(20) → VARCHAR(50)
- `stock_out.stockout_no`: VARCHAR(20) → VARCHAR(50)
