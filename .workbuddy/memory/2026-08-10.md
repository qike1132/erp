## 修复服务器启动失败问题

**问题**：`fastapi_app.shared_models.customer_sampling` 模块缺少 Python 模型定义，导致导入失败。

**根因**：`shared_models/__init__.py` 从 `customer_sampling.py` 导入 `CUSTOMER_SAMPLING_ACTIONS`、`CUSTOMER_SAMPLING_CHANGE_TYPES`、`CustomerSamplingChangeLog`、`CustomerSamplingFabricVersion`，但这些名称在模块中未定义。数据库表已由 migration 019 创建，仅 Python 代码缺失。

**修复内容**（`fastapi_app/shared_models/customer_sampling.py`）：
1. 添加 `JSONB` 导入（from sqlalchemy.dialects.postgresql）
2. 添加常量 `CUSTOMER_SAMPLING_ACTIONS`（8 种操作类型映射）
3. 添加常量 `CUSTOMER_SAMPLING_CHANGE_TYPES`（add/modify/delete）
4. `CustomerSamplingProject` 添加 `current_version` 字段和 `fabric_versions`、`change_logs` 关系
5. `CustomerSamplingPart` 添加 `to_snapshot_dict()` 方法
6. 新增 `CustomerSamplingFabricVersion` 模型类
7. 新增 `CustomerSamplingChangeLog` 模型类

**附加**：创建 migration `pg_standalone_025_add_cs_indexes` 补齐缺失的数据库索引。

## 修复 PatternRoomView 缺失 composable 导入

**问题**：Vite 编译报错 `Failed to resolve import "./composables/useSamplingPart" from "src/views/pattern-room/PatternRoomView.vue"`。

**根因**：`useSamplingPart.ts` 文件不存在，`PatternRoomView.vue` 在第 183 行引用了该模块但文件未被创建。

**修复**：创建 `frontend-vite/src/views/pattern-room/composables/useSamplingPart.ts`，参照 `useSamplingVersion.ts` 的架构：
- 接收 `Ref<number | null>` 类型的 `projectId` 参数
- watch projectId 自动重新加载部位列表
- 封装 `fetchParts` / `create` / `update` / `remove` 方法
- 乐观锁冲突（409）时自动刷新列表
- 导出 `parts`、`loading`、`submitting`、`error` 响应式状态
